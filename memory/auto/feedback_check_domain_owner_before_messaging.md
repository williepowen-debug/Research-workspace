Before sending a cross-agent message that makes a claim, correction, or "no corroboration" assertion about something in **another agent's domain**, READ the owning domain agent's current files (STATUS / PREDICTIONS / workbook / board_log) first. Don't substitute your own sweep's silence for the domain owner's evidence.

**Why:** BRENT 6/12 wrote a correction outbox to CARL asserting "no corroboration for US strikes on Iran / IRGC Hormuz closure / Bab al-Mandab activation" — while the outbox itself said "HAWK owns the kinetic adjudication." HAWK's Jun 12 re-mark corroborated ALL THREE (CENTCOM strikes inside Iran Jun 9-11, formal Hormuz closure Jun 11, Bab al-Mandab activation Jun 8-9). BRENT's sweep missed them only because the WALTER BOARD signals (SIG-W-...-001/-002) never reached its inbox. Worse, the reasoning inverted a confirmed decoupling ("crude fell, so the kinetic can't be real") into evidence the events didn't happen — exactly backwards. Caught only because Will asked "did you check that agent's domain?" — the check must gate the message PRE-send, automatically.

**How to apply:** When drafting any cross-agent signal/correction: (1) identify which domain owns each claim in it; (2) open that owner's files and reconcile before writing — especially for negative/absence claims; (3) if you can't reach the owner's data, downgrade to a question ("HAWK — can you confirm X?") not an assertion. Inbox-delivery gaps mean your inbox silence ≠ event absence. Sibling of [[feedback_verify_existence_external_primaries]] (fleet silence ≠ proof) and [[feedback_route_to_domain_agent]]; complements [[feedback_verify_counts_before_propagating]].

**Refinement (Orc adversarial check, 6/13):** checking the domain OWNER is necessary but NOT sufficient for a confirm/absence claim — the owner may share your data-starvation (here both BRENT and the owner depended on the same undelivered BOARD signals). For a load-bearing confirm/absence claim, **verify against external PRIMARY sources, not just the sibling agent's internal summary** (BRENT's first "fix" swapped confirm-via-own-state for confirm-via-HAWK's-summary — still internal). News-check a kinetic/event claim the same way you'd check a BLS print. Also a delivery-state corollary (cuts both ways — Orc asserted a file was "undelivered in outbox" from stale memory; BRENT asserted "live in inbox" — verify, don't assert): **check current file location before claiming delivered/undelivered.** Do NOT mint a separate "price-stillness ≠ event-absence" finding — that's an instance of the existing [[finding_catalyst_path_decoupling]] / [[finding_catalyst_vs_consequence_conflation]] class (one finding per class, not per instance).
