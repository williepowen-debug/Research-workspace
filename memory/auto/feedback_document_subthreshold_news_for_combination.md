Will, 2026-11-05 15:22 ET, to LABOR after a news sweep, verbatim: *"Even if any singular piece of news doesnt move the needle by itself - we do want to account for and document things that might matter eventually, or in combination, etc."*

**Why:** a threshold answers whether one item acts now. It says nothing about what several small items add up to, and an item dropped today cannot be summed next month. LABOR's sweep had filtered by individual size and left smaller notices out.

**How to apply:** record sub-threshold items in your existing ledger, grouped by theme, each with its read state, its counterevidence and what would make the theme matter. Keep the separation that protects the reader: logging is not scoring, so a tag moves no vector, and items of different kinds (announced, voluntary, global, realized) are never summed. This is a recording habit, not a new checker; LABOR's form is the `combo:` tag in `workbook/KB.tsv`, read at each NFP grade.

**Update, same day, 15:43 ET, verbatim:** *"Lets make sure this is something that is updated as new data is encountered"*. A theme is a running record, not a one-time list: add to it in the session the item or print arrives, counterevidence included. It only moves when a session runs, so say that plainly rather than imply continuous coverage.
