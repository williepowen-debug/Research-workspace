**"Never received" ≠ "does not hold." A delivery_log of zero measures MY routing record, not the agent's knowledge.** Before telling an owner about its own domain, read **the owner's STATUS** — not my record of what I sent it.

**The incident (WALTER, 2026-07-17).** WALTER discovered that OSPREY had received **zero** routed signals ever (`delivery_log` = 0, no `inbox/WALTER/` items) and inferred it lacked theater context. It dispatched a signal explaining the Russia-Ukraine vessel campaign's shape. OSPREY's own STATUS, dated **five days earlier**, already held:
- the vessel-count claims **already reconciled** ("progressive snapshot windows, not contradictory counts") with daily tallies — so the inbound "116 in 9 days" was the same running total it was tracking;
- **the signal's headline finding, verbatim, as its own pre-registered prediction** — OSP-01: *"stays attritional + Crimea-fuel logistics,"* OPEN at 65%, nudged 60→65 that session **on the same two supporting facts WALTER "brought"**;
- a **better-sourced version of the key figure** (4.22M bpd, Bloomberg/Kpler, explicitly superseding 3.83M) than the one routed ("~4 mb/d").

**Why the inference is structurally wrong:** a handoff/delivery count is a **record of the router's own outbound actions**. It is silent on what the agent pulled itself, inherited at spinout, or built in-session. OSPREY had inherited a frozen record from HAWK and run two live sessions. The zero meant *"I have never sent this agent anything"* — which is a fact about the router.

**How to apply.** Before routing to any agent — *especially* a new one, and *especially* when the pitch is "it has no coverage here":
1. **Read the agent's STATUS and pre-registered predictions/triggers first.** If the finding matches a prediction it already registered, the signal is a **fold**, not a discovery.
2. **Never use your own delivery/handoff record as a proxy for the recipient's knowledge.** They measure different things.
3. **A newly-wired agent is not a blank agent.** Spinouts inherit; agents pull their own sources. "Wired into routing on date X" ≠ "knew nothing before X."
4. If it's already theirs, say so plainly and route only the **residual** (here: one post-dates-your-session datum), with the framing withdrawn.

**The sharp edge:** this is `[[finding_board_lags_agents_not_vice_versa]]` — *the ahead/behind question is per-LEG, not per-agent* — **failed by the agent that had written that lesson the previous day**, and failed *because* it was pleased about closing a routing gap. Congratulating yourself for finding a gap is the moment you stop checking whether the gap is real. **Corollary, same session, same shape:** the fleet's own file also beat the aggregator twice — BRENT held the identical SPR figure from the EIA primary *and* knew the real §6241 statutory floor (252.4M) that refuted the post's invented "300M floor"; LIQUID held a KB row (KB-LIQ-070) specifically warning that the *"Fed injects $XB / QT over"* press framing **is** just mechanical Reserve Management Purchases. **When an inbound item looks like a great find in someone else's domain, the base rate is that the owner already has it, better.**
