When a fast-moving anchor is re-stamped, the re-verify pass naturally tests **facts**. It does not test **sequence** — and sequence is what the frame rests on.

**Worked instance (WALTER, 2026-07-27).** A 7/25 stamp framed the Jazan refinery strike as landing into an **escalating** war and read Friday's −3.9% in Brent as *"talks-progress headlines."* **Every fact in it was true.** What was wrong was the **order**: the Pentagon had already suspended a 13-night bombing campaign **the night before** the refinery was hit. Nothing about the strike, the Reuters video, the FIRMS anomalies or the truce-break needed retracting — but the frame inverted, and with it the actionable call (*"the market is positioned the WRONG WAY… gap risk into the Sunday open"*), which was **exactly backwards**.

**Why:** a fact-by-fact re-verify returns all-green on a sequence error, so the normal instrument certifies the broken state. The error lives in the *relations between* the facts, which no single-fact check has a referent for. This is why it survives review by people who did the checking properly.

**How to apply:** when re-stamping a fast-moving anchor, **re-verify the ORDER OF EVENTS and not only the events** — write the timeline as dated lines and ask which one you assumed rather than observed. When the correction lands, say plainly **which half stands and which half is retracted**, at every surface. A retraction is cheap exactly when the original stated its actionable call explicitly enough to be falsified — so state calls falsifiably.
