**2026-07-31.** ORACLE PM sweep flagged **Fed +25bps @ Sept-mtg-specific 56.5%, Δ1d +4.0, Δ7d +3.0** ($2.1M vol, deep $347.7K liq) as a "post-FOMC deepening" and routed it to LIQUID/HENRY as an amendment to the AM Fed-retract packet. That framing was materially wrong when Will asked for the trajectory: the same market went **10.5% (5/17 low) → 39.5% (6/19) → 23.5% (7/1 low) → 56.5% intraday (7/31)** — the "sweep-fresh" +3/7d is the tail of a **+30–40pp climb since mid-June** through TWO earlier gap-ups. The FOMC hold merely paused it for two days (7/23–7/25). The base trend is up, not fresh.

**Why it happened structurally, not by lapse:** a market that was pinned this session has, by definition, **no entries in `workbook/ODDS_LOG.tsv` before today**. The fetcher shows the current level, plus the API's own Δ1d/Δ7d, plus tier/vol/liq — nothing else. All of those read as *current-print* facts. The trajectory has to be *actively pulled* via `polymarket.py history` (or `history --write` for the tsv), which touches the CLOB `prices-history` endpoint separately. **Nothing in the pin-and-pull loop forces the trajectory.** So the failure mode is: pin → pull → level read → publish, and the level reads as ambient because the tool surfaces don't distinguish "new market on a climb" from "new market at a base." A single instance is a mislabel; the class is a durable framing hazard on every future new pin.

**Why it matters for downstream consumers:** the amendment outbox to LIQUID/HENRY said "Sept-specific DEEPENING post-FOMC" and gave the read as the sweep's headline. LIQUID/HENRY consume ORACLE marks to weight the rates story; the difference between "fresh post-FOMC re-arm" and "6-week climb resuming after a 2-day pause" is materially different — the former reads as a new catalyst, the latter as an existing trend the operator should already have been tracking. My AM Fed-retract to the same recipients had also missed this: aggregate Fed-HIKE-2026 Δ7d −5 was measured off the local 7/24 spike (71.5%), not the base — the 7/22 close was 59.5%, the 7/31 close is 66.5%, i.e. **+7pp on the true base-to-base 7-day window** while my number read as a retreat. Same class of failure, twice, in one session.

**Sibling to but distinct from [[finding_divergence_requires_fresh_likeforlike_baseline]]** — that one's about the *thesis* baseline being stale in a divergence; this one's about the *market itself* having no visible baseline on first pin. And it's a specific application of [[finding_number_carries_threshold_unit_source]] to prediction markets: **a market level carries a trajectory in the same way it carries a source and a date**; a level without the trajectory context is a naked number.

**How to apply:**
1. **When pinning a NEW market to `watchlist.tsv`, run `python3 scripts/polymarket.py history` (or the market-scoped equivalent) on that market BEFORE writing any level-based read to STATUS / NEXUS_BRIEF / KB / outbox.** The sparkline + Δ30d + Δ90d + since-creation + [min-max] range is the minimum context. Cost: ~1 CLOB call per market; time: seconds. This is a hard rule, not a nice-to-have — the mislabel is not detectable from tool output alone.
2. **When quoting a Δ7d on ANY market with recent volatility, cross-check against the base-to-base close-window**, not just the API-computed Δ7d. The API Δ7d is a "print now vs print 7d ago" — a spike-and-retrace inside that window can invert the sign of the true trend. Fix: `awk` the last two same-time-of-day rows in HISTORY.tsv OR read the sparkline shape.
3. **Framings to interrogate before publishing a level-based read on a fresh pin**: "is this a new signal or the tail of an existing trend?", "what did this market do at each of the last 3 catalysts in this domain?", "did I check the sparkline shape or only the last row?". If the answer to any is "I don't know," pull the trajectory first.
4. **For the specific ORACLE toolchain**, add the trajectory pull to the boot/closeout ritual for any newly-pinned market this session — mirror of how [[finding_closeout_as_writeback_tail]] structures write-back symmetric to read-in. New pin at boot → `history` at closeout, no exceptions.
5. **Retract cleanly when caught.** The 7/31 PM amendment to LIQUID/HENRY was corrected in-session (per Will's ask). The correct move is to send a second amendment naming the trajectory + retracting the "fresh post-FOMC" framing, not to bury the correction in the next-session note.
