**Instance (2026-09-02):** DEWEY delivered REQ-001 with the CXMT bit-output leg as SEARCH-NOT-FOUND — explicitly NOT upgraded to VERIFIED — and named the STAR Market IPO prospectus as the one unchecked fallback. ZHAO, spawned in parallel, pulled that exact document (411,324 chars, text-searched: the wafer unit appears 3×, all as sensitivity deltas, never a level) and closed the leg the same night as a **VERIFIED ABSENCE** — deliberate non-disclosure, which says *why* the number does not exist. VULCAN's ask had stood 30 days across three packets. DEWEY then re-graded its own report from the primary (a "reportedly" claim CONFIRMED; two basis traps added; one input it had declared absent turned out to exist — registered as follow-on, NOT retro-fitted, because it is a demand series and the test is a supply question).

**Why it works:** a generic gap has no owner and no next step; a named fallback is an executable instruction that any desk with the reach can run without re-deriving the search. It also makes the confidence token honest: SEARCH-NOT-FOUND → VERIFIED-ABSENT only after the named path is checked (PROME/CLAUDE.md § Session Process Controls). Related: [[finding_declared_data_wall_needs_fleet_memory_check]] · [[finding_delivery_check_is_not_a_knowledge_check]].

**How to apply:** every SEARCH-NOT-FOUND in a report or packet names (a) the exact fallback not yet checked, (b) who has the reach, (c) what a hit would change. When you are the desk with the reach, close it and packet BOTH the asker and the original author so the author can re-grade its own claims (DEWEY's five edits). Never substitute a proxy for a missing primary in the closing packet.
