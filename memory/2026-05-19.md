## Post-closeout addendum (2026-05-19 PM): architectural design discussion

After main closeout, Will dropped a screenshot + transcript in newly-created `WILL/share/` folder showing a parallel conversation he had with an anonymous Agent-View-dispatched Claude. That Claude had explained the three-mechanism taxonomy (Agent View dispatch / Agent Teams / independent tmux) and proposed several coordination options. Will asked Prome to weigh in.

**Substantive points landed (full reasoning preserved in this session's conversation, not duplicated here):**

- **Teams/Agent View can't replace file-based coordination for persistent named agents** — instantiation impedance mismatch. memory-audit-001 validated they DO work for bounded sub-agent tasks within a domain (adversarial-pair audits, parallel sub-agents with interplay).
- **Mental model: files for fleet, teams for swarm.** Persistent cross-domain agents coordinate via files+inbox+PROVENANCE. Transient intra-domain sub-agents coordinate via Teams.
- **tmux send-keys is dangerous** — a confused Prome could destroy a peer agent via injected keystrokes with no audit trail. Hard no. tmux pipe-pane is OK as a forensic tool only, not primary read channel.
- **The April 14 parked "messaging overhaul"** is the right work to resume, narrower scope: drop HERMES, standardize `_prome-spawned.md` + PROVENANCE convention, add boot-time inbox-triage to each agent's CLAUDE.md.
- **Second-order problem surfaced by Will:** how does a sender know what's relevant to a receiver without reading the receiver's full domain? Answer: don't make senders smart — make receivers self-publish a thin `TRIGGERS.md` (entities + thresholds + hot questions) that senders consult cheaply. Generalizes WALTER's WATCH_FOR pattern from external signals to internal findings.
- **The staleness problem driving Will's operational fatigue is cadence, not coordination.** Inbox finish reduces friction of relaying but doesn't make agents self-driving. Cadence-automation (scheduled fleet-scan) was discussed and explicitly deferred — Will wants to keep human-in-the-loop first.
- **Permission-cascade lesson named:** `--dangerously-skip-permissions` propagates to dispatched anonymous Claudes; those Claudes can spawn persistent peer agents in user's tmux without confirmation. Same shape as the 4/16 cron incident. Worth a future auto-memory entry if pattern recurs.
