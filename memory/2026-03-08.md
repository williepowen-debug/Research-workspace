### KB Schema Research & Decision
- Will ran research prompt on 3 LLMs (deep research doc, compressed brief, structured spec)
- All 3 converged on same gaps: Stale_By, Admiralty Code confidence, epistemic typing, explicit provenance
- Cross-analyzed all outputs, adopted best elements from each
- Final schema: **13 columns**

```
ID | Date | Group | Entity | Fact | Source | Conf | Epistemic | Status | Stale_By | DerivedFrom | Vectors | Notes
```

**New fields vs old 9-col:**
- **Conf** — Admiralty digraph (A1–F6). Source reliability × information credibility. Default F6.
- **Epistemic** — EMPIRICAL / ESTIMATE / ASSUMPTION
- **Stale_By** — expiration/review date, null if static
- **DerivedFrom** — parent KB IDs (provenance chain)

**Key decisions:**
- Un-merged Conf from Source (all 3 outputs argued agents don't experience field fatigue)
- Un-merged DerivedFrom from Vectors (different questions: thesis links vs provenance)
- Rejected EventDate/bi-temporal (Stale_By handles freshness more directly)
- Rejected Scope_Bounds JSON, Context_Anchor, Authoritative_Override (overhead > benefit)
- Simplified Epistemic from 4 values to 3 (dropped REPORT — Admiralty Conf handles that)
