# Review pilot v1 — local feasibility variant

Status: DEVELOPMENT until FREEZE.json and the pre-evaluation Git commit exist. Original public protocol remains a planned draft. This implementation does not publish to the public demo.

## Question and treatment

Does a separate reviewer session improve structured research deliverables over continued-context self-review, given the same model, evidence, checklist and three-turn opportunity? No direction of effect is required for a useful result. The treatment includes fresh-session framing and conversation-role/history differences. It does not isolate psychological independence, a whole fleet, persistent specialization or a particular prompt phrase.

Twelve synthetic evaluation tasks: four source-dependence, four supersession, four correction-application. Each family contains a no-change control. Two repetitions in each condition give 48 scheduled runs; repetitions are clustered within twelve tasks. Three distinct practice tasks are excluded. Corpus and answer keys are AI-authored, independently checked before freeze; human validation remains pending.

Turn 1 receives question, field specifications, initial documents and seeded initial state. Turn 2 receives the same updates in both arms and the same review checklist. In self-review it continues the analyst conversation; in separate review a new session receives the original task message, exact draft and update/review request. Turn 3 continues the original analyst and receives the updates plus exact review text. Keys and split/control labels are not sent. Output is JSON containing field/value/source-ID rows; correction tasks include separately scored canonical and downstream fields. This measures produced structured artifacts, not actual disk-edit execution.

The first draft is scored against initial_key. Final/last deliverable is scored against final_key. Review flags and changes are evaluated against the final evidence. Consequently a repaired field can reflect applying new evidence, not necessarily fixing an error against the original information. Paired workflow comparison is the primary contrast. No-change controls test damage to correct content.

## Runtime and limits

Owned Codex app-server stdio; model gpt-6-astra, reasoning effort low, CLI 0.153.4. The requested/returned identifiers are retained. An immutable provider snapshot is not exposed: this is an identifier-and-settings pin, not proof that backend weights cannot change. Empty task cwd, no repository instruction files, supplied-evidence-only instructions, shell/patch/multi-agent/apps features disabled, web search disabled, read-only network-disabled sandbox. Any observed tool or interactive request aborts the run and is retained as failure. No production desk is launched or stopped.

One experimental turn active at a time. Same maximum three app-server turns per arm; hidden provider retries are not separately observable and are not claimed as exactly three model invocations. No API keys are available; authenticated subscription access is used. Actual per-run monetary charges are UNAVAILABLE, not zero or an API-price estimate.

The installed interface provides no verified hard per-turn token ceiling. This is a disclosed deviation from the public draft's hard equal-total-token design. A numerical inter-turn stopping threshold is set in settings.json using practice only. Before a next turn, stop if cumulative observed totalTokens meets/exceeds that threshold. A single turn may exceed it. Count input (including cached/replayed context) plus output; reasoning is a reported subset of output and cached input is a subset of input, neither added again. Record categories separately. Missing or inconsistent usage stops the run; no free additional turn. This is equal opportunity plus observed usage, not an enforced equal-token experiment.

Ninety seconds per turn, zero automatic retries. A failed/timeout/malformed/tool-using turn stays in the denominator; grade the last available deliverable against final evidence, with status separately reported. Two consecutive failed runs stop the batch; all unattempted scheduled rows remain NOT_RUN, not erased. Every attempt is written separately; rerunning into an existing output directory is refused. No resume/retry of a stopped evaluation under the same registration. Randomize task/repetition pairs, then condition order within each pair with seed20260908. No prompt edits during evaluation.

## Scoring and reporting

Exact string values and allowed supporting source-ID sets are fixed in keys. Fields specify the required format. Every field appears exactly once; missing/extra/duplicate fields, extra output keys, unsupported citations and malformed JSON fail acceptance. Each answer needs a nonempty, duplicate-free subset of its allowed source IDs. This tests predefined citation eligibility, not semantic adjudication of arbitrary prose. Values and citation correctness remain separate measures; an acceptable deliverable passes every required check with valid shape.

Report first/final acceptance, per-field value/citation checks, remaining errors, newly damaged fields, and review flags classified valid/invalid and visibly acted-on/ignored. Acting on a flag requires a changed artifact row matching its proposed value and cited sources; matching an already-present value alone is not evidence of action. No composite quality index. Show every scheduled result, per-family totals and per-task/repetition paired differences. No significance testing or general superiority claim from this small constructed sample. Ceiling results remain results; do not harden tasks after inspecting evaluation.

Human validation mode defaults to automated feasibility first, with human validation PENDING, after an asynchronous preference question to Will. A randomized output-ID bundle excludes condition labels; the mapping is separate. No human/independent/blind grading is claimed until performed and masking assessed. Construction, independent review, grading and operational human verification labor are distinct; minutes are UNMEASURED unless recorded prospectively. Record any in-run intervention explicitly; no time-saving estimate inferred from commit history. Turn latency excludes launch/setup and must be labeled accordingly.

Full messages, returned model metadata, selected lifecycle/usage events and final structured artifacts are retained. Runtime infrastructure source session_bridge.py is hashed in the freeze. Experiment workers receive only public_task fields, updates and visible prior outputs; no answer key or grading feedback enters any condition.
