## Idea by idea

### 1. Receipt command — **BUILD, as a preparer that leaves the commit to PROME**
*What exists:* `scripts/orch_log.py` has `check · append · view · rotate` and no row-update mode; rows are hand-edited in place (the header says cells update at consumption). `orch_closeout.py` keys touches by a sha256 of the first five columns, so a second row for the same touch is a duplicate-key error; receipts must edit the existing row. The commit-msg hook (`scripts/githooks/commit-msg`) enforces the 100-character subject natively; `PROME/tools/commit_check.py` already handles a staged `git mv` source. CLOSEOUT.md:81 keeps consumed moves in a separate, earlier commit; repair B's proposal says "no new Git wrapper".
*Gap:* no tool verifies a cited commit, moves the memo, writes the ledger line and updates the row's `delivered`/`notes` cells with the JSON kept last.
*Verdict:* worth building, with one design change from the idea as listed: the tool **prepares** (verify commit · `git mv` · ledger line · row update with JSON-last enforced · a ready-made ≤100-char message file) and **PROME runs the pathspec commit** — no commit authority inside a script, so nothing to square with repair B or carve-out ①. It also writes the `consume:<AGENT>` token into the prepared message. *Effort:* half a day plus tests (ordinary · duplicate touch key · missing commit · JSON-last · CRLF). *Canon:* one process change; CHECK_STANDARD §14 rc discipline; no charter edit. *Removes:* ~4 tool calls per packet (16 tonight), the JSON-last class of defect, and the FILED/CONSUMED ambiguity.

### 2. Desk status one-liner — **BUILD SMALL; most parts exist**
*What exists:* `PROME/tools/desk_activity.py` (per-desk pending paths and path-attributed last self-commit, the L455 rule); `PROME/tools/session_presence.py --desk` (JSON per desk, always prints every due row, 60-second snapshot expiry, presence always UNKNOWN by design); `session_bridge.py` (process + `claude agents --json` inventory, works without Codex); `agent_freshness.py --agent` (unread from-desk packets in PROME's inbox, dirty paths, pending inbox); `inbox_census.py`; `spawn_list.py` (no `--desk` filter); `spawn_slate.py` lists last memos **sorted by filename**, which COMPLETION_SPEC:25 forbids for a live-state question (commit time, never filename) — a defect to fix in passing.
*Gap:* no single read-only call; no per-desk unpushed attribution (repo-wide ahead/behind only); two "last commit" definitions side by side (path-scoped vs subject+path).
*Verdict:* a thin wrapper that calls the five existing functions and prints one line (pending · last self-commit · ahead/behind repo-wide · last memo by commit time, in inbox or processed · next due row · census · shell-side session evidence) — and says "ListAgents same minute still required" exactly as `session_presence` does. *Effort:* a day; the `--desk` filter on spawn_list and the commit-time sort on spawn_slate are the real work. *Canon:* preflight rule unchanged (UNKNOWN never absence); one process change. *Removes:* the eight hand-run preflight chains per orchestration evening.

### 3. Receipt-class auto-filing — **NOT NOW; re-scope to a classifier that prints, never files**

*Gap:* the filable class is undefined and the measured candidates are fewer than claimed (24 exact `None.` out of 113).

That keeps consumption a live-session act (the spec's line) and still removes the per-packet open-and-scroll. *Effort:* half a day. *Canon:* none touched if it never writes.

## Appendix (22:1x ET) — answers to the three pre-approval questions on the receipt command (Will's outside reviewer, relayed 22:11 ET)

**Verification of the ledger repair, re-run after the repair (not asserted):** `orch_closeout.py` at 22:1x ET — "Extra data" parse errors 28 → **0**; today's rows read as 4 ASKED→receipt (ANVIL, closeout-plan helper, ARGUS, TERRY) and 4 UNKNOWN for an unrelated, pre-existing reason (`timestamp absent` on the afternoon helper rows written before this session); PROME's 12 doorbell rows to Will-launched sessions carry `state: UNKNOWN` by design (WQ-249 scope excludes them). rc stays 1 on the 549 legacy rows without structured evidence. All 29 repaired rows parse.

**Q1 — one invocation, many packets?** No rule requires one commit per packet. `CLOSEOUT.md:81` requires consumed moves in a commit SEPARATE from (and earlier than) the closeout candidate, not separate from each other; tonight's boot filed 35 in one commit. Three constraints bind a batch: (a) each packet keeps its own ledger line (memo path · sender · cited commit · disposition) and its own ORCH_LOG row update, so identity and provenance survive the shared commit; (b) the commit message carries one `consume:<AGENT>` token **per sender** in the batch (BOARD spec §5.1 reads the token from subject or body — the multi-token reading to be confirmed with WALTER, the spec's owner); (c) the batch REFUSES any packet whose `WILL_NEEDS` is not "None" or whose `FOLLOW-UP` is not "None" — those need a WQ/DOCKET registration first (COMPLETION_SPEC:70-72) and are listed back for hand handling. Design adopted: validate all → apply all → verify ledgers → PROME reviews the diff → one pathspec commit.

**Q2 — idempotency and partial failure.** Preflight before any write: cited commit exists (`git cat-file -e`); memo is in `PROME/inbox/` and NOT already in `processed/`; the ORCH_LOG touch row exists, its notes cell parses (JSON last), and no receipt marker for this memo is present; ledger file and ORCH_LOG have no CRLF; every target path is inside PROME's own directories (allowlist: `PROME/inbox`, `PROME/reports`, `PROME/state`) — nothing under `AGENTS/`. Idempotency key = memo filename + cited commit sha, written into the ledger line and the ORCH_LOG receipt text; a re-run finds the key and skips that packet. Write order: ledger line → ORCH_LOG row (temp file, then atomic rename) → `git mv` last. A failure after the memo move but before a ledger write cannot occur in that order; a failure between ledger and ORCH_LOG leaves both uncommitted in the working tree, visible in `git status`/`git diff`, and the re-run converges (ledger key present → skip; ORCH_LOG marker absent → write). No commit happens inside the tool, so no partial state is ever recorded in history. The reviewer's caveat is accepted: a tool that writes ledgers holds operational authority even without committing; the path allowlist and the no-`AGENTS/` rule are the fence.

**Q3 — narrowest realistic test.** A throwaway git worktree (`git worktree add /tmp/… HEAD`, removed afterwards) seeded with three representative historical packets copied back into `PROME/inbox/`: a pure receipt (TERRY's 10/14 acceptance-ack), one with a FOLLOW-UP (BOND's 10/14 transition-workbook note), one with a WILL_NEEDS (BROCK's 10/14 bounded-corrections). Expected outputs are written first (the exact ledger lines, ORCH_LOG cells and processed paths). Cases: ordinary (the receipt files, the other two are refused and listed); idempotent (run twice, byte-identical result); partial failure (`--fail-after ledger` flag, then re-run converges); wrong owner (a packet path under `AGENTS/<desk>/inbox` is refused); duplicate touch key (a second row for the same touch is refused, never appended); CRLF ledger (refused before writing). Pass = `diff` against the expected files is empty and `orch_closeout.py` reads the worktree's ORCH_LOG with zero parse errors.

**Order accepted from the reviewer:** build and validate the receipt command alone first; the classifier stays read-only (filed · consumed · awaiting action · blocked · unresolved, never changing a state); the desk status wrapper after; the retires line rides the scheduled 10/25 review rather than a new process. The single-session bundling of all three is withdrawn.
