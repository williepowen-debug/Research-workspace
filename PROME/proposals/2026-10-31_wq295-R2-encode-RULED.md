## 1. The rule as ruled (verbatim from row 295)
> R2 as ruled: a WEEKLY or MONTHLY desk past its clock with no dated row is a Tier-1 wake (`CADENCE-DUE`), beside dated rows and never instead of them; EVENT-DRIVEN and ON-DEMAND desks never wake by age. The three riders, verbatim from `PROME/plans/2026-09-26_wq295-R2-wake-schedule.md`: ① a cadence wake never displaces a dated-row wake for the cap — dated rows fill the four slots first, cadence wakes take what is left and otherwise roll to the next boot with room · ② the clock starts from the desk's last SELF-commit, never from a PROME packet or a WALTER delivery into its directory · ③ an EVENT-DRIVEN desk with no dated row for ≥14 days is surfaced in the boot report as UNREACHED (not woken).

From the proposal's R2 letter (still binding where the riders do not differ): WEEKLY = more than 7 calendar days since the last own commit; MONTHLY = past the same day next month. The wake is an L0 drain of the whole inbox plus a cadence self-check ("what did my domain do since my last session?"). A cadence wake never grades anything on the desk's behalf and never marks a BOARD item consumed. `spawn_list.py`'s exit-code contract is unchanged.

## 2. Reading choices — each is PROME's, stated so the reader can check it
- **"No dated row"** = no row in what `spawn_list.collect()` returns at horizon +14 days with the desk as FIRST owner: PENDING DOCKET rows and LIVE GATES rows due on or before as-of +14 days, overdue included, COVERED-suppressed rows excluded, any class (DARK, ACTIVE or LANDS-IN). This is exactly how the 9/26 schedule Will saw was computed (its header: "`spawn_list.collect`, horizon 14"). A desk named only as a second owner on a row is NOT governed by it (`spawn_list` wakes first owners only).
- **Rider ③'s "no dated row for ≥14 days"** = the same test for an EVENT-DRIVEN desk (no first-owner row within +14 days), as in the schedule's own WAL example ("no dated row inside 14 days").
- **Clock** = the existing `cadence_note` boundary: WEEKLY is past when MORE than 7 days have elapsed since the last self-commit (exactly 7 is within); MONTHLY is past after the same day next month, clamped to month-end. Last self-commit = `Liveness.last_self_commit` (subject AND touched paths are the desk's own — the L455 rule), which is rider ②.
- **DAILY** is outside R2 (the ruling names WEEKLY and MONTHLY). WALTER is the only DAILY desk and is Will-launched; it stays annotation-only.
- **Launchable only:** a desk can be CADENCE-DUE only if its ROSTER class is ACTIVE, TIER-2 or SPECIAL (`spawn_slate.LAUNCH`, imported, not copied); a SPECIAL desk's own ROSTER launch rule still governs at spawn time.
- **Cap with C6:** dated wakes fill the cap first; a cadence wake takes only a slot left under the BASE four, because C6's eight applies only when every desk woken that boot is woken on a due dated row. The instrument prints this; PROME enforces it at spawn time (it has never counted slots).
- **Visibility (report-only, no new authority):** in the same block the tool NAMES, never skips: launchable desks absent from the cadence table, UNDECLARED, duplicate or unknown tokens, desks with no qualifying self-commit, git failures, and cadence-table desks that are not launchable — each CANNOT-EVALUATE, never a wake (spec point 5, proposal acceptance test 4). It also lists past-clock desks that a dated row governs, with the row key. Reason: ISHM (TIER-2, absent from the table) went dark 10/26 and nothing named it until NEXUS did on 10/31 (DOCKET L899).
- **Separate block, untouched contracts:** CADENCE-DUE rows print in their own block after the dated rows. `collect()`, the `Row` shape, the slate's conservation count, `session_presence.py` and the exit code (2 UNKNOWN · 1 DARK · 0) are unchanged. The boot gate's spawn-list line adds the cadence ids and reads ⚠️ (advisory) while any CADENCE-DUE row exists.
