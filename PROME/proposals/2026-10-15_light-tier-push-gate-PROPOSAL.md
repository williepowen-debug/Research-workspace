## 2. The conflict, and why a failed verification stopped nothing (unchanged in substance)

The tier table and `prome_gate.check_review_manifest(tier)` make an ABSENT or PRIOR-closeout review advisory below Standard and blocking at Standard/Heavy, while an APPLICABLE review whose content changed (rc 1) blocks at every tier. Step 10 is written tier-blind: *push only if `--verify-review` returned 0*. At a Light closeout no freeze is taken, so the only manifest on disk is a prior closeout's; the verifier correctly answers CANNOT-EVALUATE, and the step cannot be satisfied. Nothing mechanical joins that answer to `scripts/safe-push.sh` (which takes no precondition input) — the join is the operator's shell line, and a `;` is a sequence, not a conditional. The gate records nothing about the tier it ran, so no tool can read what the operator chose.

## 3. The revised correction (bounded; existing tooling only)

**Principle (unchanged):** the closeout gate — the instrument that already takes the tier and already runs the checks — records ONE receipt; ONE push verb on the existing commit wrapper reads the receipt and the existing review verifier over the COMPLETE outgoing delivery and either calls the existing push script or refuses. No new review layer, no new check class, no fleet audit. **What v2 adds:** the receipt is bound to content and declarations (SP3); applicable review failures keep blocking at every tier (SP4); the delivery is the whole outgoing range with carried work accounted for (SP5); and the post-commit re-check path is defined.

### 3a. `prome_gate.py closeout --tier <t>` writes a BOUND receipt — `PROME/state/closeout_gate_receipt.json`
Written at the end of `mode_closeout` (boot/refresh write nothing); fields:
- `tier`, `rc` (aggregate), `blocking_fail` and `errored` (names), `recorded_at`, `head` (HEAD at run time), `tree_clean` (bool).
- **`delivery`** — the candidate the gate saw: `{path: content_id}` over the same scope the freeze uses — `argus_scope.build_scope(baseline, perimeter, include_pending=True)` lanes OWNED + SHARED + UNATTRIBUTED — where `content_id` is `argus_scope._content_id(path)` (sha256 of the working-tree bytes; `None` for a deleted path). This is what the gate's checks ran over.
- **`declarations`** — exactly as passed: `memory` (`[]` for `--no-memory`, else the slugs), `superseded` (`[]` or the pairs), plus `memory_paths_observed` = `_dirty_memory_paths()` at run time.
- `baseline` — `_current_baseline_sha()`; `review_manifest` — `{present, baseline, verdict}` as found.
Reuses `_content_id`, `build_scope`, `_dirty_memory_paths`, `_current_baseline_sha`; ~30 lines; no existing check changes class or meaning. The receipt is per-clone run state (gitignored like `SPAWN_SLATE.md`), never a reviewed candidate member.

### 3b. `commit_check.py push --tier <bounce|light|standard|heavy> [--push-cmd …]` — the ONE push verb
Each step is a refusal (rc 1, one line beginning `NOT PUSHED:`) that stops before any push; no step prints anything that reads as a push receipt (safe-push's line stays the only one).
1. **Outgoing delivery.** `git fetch origin master`; `base = origin/master`; `range = base..HEAD`. Empty range ⇒ "nothing to push" (rc 0, no push call). Collect every commit in the range and every path it changes (`git diff --name-status base HEAD` plus per-commit `--name-status` so a path added then reverted is still seen).
2. **Receipt present and binding.** Refuse unless the receipt exists, is readable, `tier == --tier`, `rc == 0`, `errored == []`, and **`head` is `base` or `HEAD`** (a receipt taken before the commit at the push base, or after the commit at the tip with `tree_clean` true — the ordinary post-commit/retry path). Any other `head` ⇒ "receipt taken at <sha>, which is neither the push base nor the tip — re-run step 9". Missing, unreadable or mismatched ⇒ "UNKNOWN never pushes".
3. **Content binding (SP3).** For every path changed in PROME's part of the range (step 5 defines it), the committed content at HEAD (`argus_scope._committed_content_id(path, "HEAD")`) must equal `delivery[path]` in the receipt, and the path must be IN `delivery`. A path in the range but absent from the receipt (added after the gate), or whose bytes differ (edited after the gate), ⇒ refuse: "<path> changed/added after the gate — re-run `prome_gate closeout --tier <t>` at the tip, then push". A path in `delivery` but not in the range is fine (the gate saw a dirty path PROME chose not to commit); it is printed as "not shipped". Later edits therefore INVALIDATE coverage; the recheck is the existing gate, re-run (3a's post-commit form), never a lighter check.
4. **Declarations (SP3, memory).** Every `memory/auto/*.md` path in the range must be the file of a declared slug (`memory/auto/<slug>.md` ∈ `declarations.memory`); a range that ships any memory path under a `--no-memory` receipt, or a memory path whose slug was not declared, ⇒ refuse: "memory path <p> shipped without its declaration — re-run the gate with --slug". `superseded` cannot be bound to content and is carried as declared; the verb prints it.
5. **Complete membership and carried work (SP5).** Partition the range's commits using the receipt's lane rules (`AUDIT_PERIMETER.tsv` via `build_scope`'s classifier): a commit is **PROME's** if every path it changes is OWNED/SHARED/UNATTRIBUTED under PROME's perimeter or in `delivery`; a commit is **carried** if every path it changes is EXCLUDED under PROME's perimeter (another owner's directory, root docs PROME does not own). A commit that mixes a PROME path with another owner's path ⇒ refuse ("<sha> changes both a PROME path and <other path> — not a PROME delivery and not pure carried work; split or re-run the gate at the tip"). PROME's commits form the delivery checked in steps 3, 4 and 6. Carried commits are **named** (sha · subject · owner directory) with the line "carried, not audited by PROME — their owners' closeouts govern (push-train pattern, `scripts/safe-push.sh` header)"; they are never audited and never block, except that a carried commit touching a PROME-owned path is by definition PROME's and falls under step 3. This is the existing push-train policy made explicit, not a fleet audit.
6. **Review, applicability first, then tier (SP4).** Run `argus_scope.verify_review(paths=<every path changed by PROME's commits across the WHOLE range>, ref="HEAD")`. Define **applicable** = a manifest exists AND its `baseline == _current_baseline_sha()`.
   - Applicable and rc 1 (CHANGED-SINCE-REVIEW or UNREVIEWED addition) ⇒ **refuse at EVERY tier** — the existing blocking behaviour, preserved.
   - Applicable and rc 2 (completeness could not be established) ⇒ refuse at every tier (UNKNOWN is not a pass).
   - Applicable and rc 0: at Standard/Heavy the verdict must read `REVIEWED` (FROZEN ⇒ refuse, "freezing is not an audit"); at Light/Bounce rc 0 suffices and the verdict is printed.
   - Not applicable (absent, or a prior closeout's baseline): at Standard/Heavy ⇒ refuse with the verifier's own line; at Light/Bounce ⇒ permitted, printed as "review NOT APPLICABLE at <tier> (absent/prior manifest) — delivery = bound receipt + intent + membership".
   Standard/Heavy therefore keep freeze → audit → committed-content verification → conditional push, now over the whole range instead of HEAD's paths (stronger, not weaker).
7. **Intent ↔ commit.** Existing `verify("HEAD")` must return 0 (the intent file names HEAD's exact paths); for a multi-commit PROME delivery each earlier PROME commit must also match the intent recorded for it — `commit_check` writes one intent per commit today; the verb reads the per-commit record it keeps from step 1 (a small `intents.jsonl` beside the manifest, written by `commit`; ~10 lines) and refuses on any mismatch.
8. **Push.** `subprocess.run(push_cmd)` with `push_cmd` = `bash scripts/safe-push.sh` by default, `--push-cmd …` substituting an isolated command for tests; the verb returns safe-push's rc (0 · 1 · 2) unchanged. `safe-push.sh` itself is not modified.
Remove `--push` from the `commit` subcommand. **If the intended commit changes before pushing** (an amend is forbidden; a follow-up commit, an edit, a revert): steps 2–4 refuse until the gate is re-run at the tip; a receipt is single-use in the sense that it binds one tree — the retry path is `prome_gate closeout --tier <t>` (clean tree, `head == HEAD`) then `push --tier <t>`.

### 3c. `PROME/CLOSEOUT.md` step 10 (the letter) and the runner's step 5
Replace the three-line recipe with: *commit with `commit_check.py commit --stage -F <msgfile> -- <exact paths>`; then `python3 PROME/tools/commit_check.py push --tier <the tier you ran at step 9>`; it refuses unless the step-9 receipt carries that tier with rc 0, taken at the push base or at the tip, bound byte-for-byte to every PROME path in the outgoing range and to the memory declarations; carried commits by other owners are named, not audited; an applicable review that reports changed or unreviewed content refuses at every tier; Standard/Heavy also require the review to read REVIEWED; safe-push's line remains the only push receipt. If the verb refuses, re-run step 9 at the tip and retry; never push by another route.* Tier table unchanged. Both runner copies carry the same single command. Step 12's baseline record stays after the push (it is excluded from every manifest already).

**Not done by this proposal:** no new audit or reader; no change to any gate check's class or meaning; no change to `safe-push.sh`; no fleet-wide audit of carried commits; no change to boot.
**Replaces:** the operator-typed verify→push chain (failed three times tonight) and the `--push` flag.

## 5. Residue and limits, stated now
- The receipt binds the paths the gate's scope saw. A path outside PROME's perimeter that PROME nonetheless commits (a Will-gated root doc) is EXCLUDED by the perimeter and would classify the commit as mixed ⇒ refused; that is intended (such commits are rare and Will-gated) and the operator re-runs the gate at the tip, which binds it via `delivery` only if the perimeter lists it — a root-doc commit therefore needs the perimeter row it already should have. Named here so it is not discovered at the first such push.
- `superseded` declarations cannot be bound to content; they ride as declared.
- The verb does not re-run the gate; the recheck is the existing gate, re-run. A receipt never outlives a tree change.
- Implementation = one process change (the next slot after Will's word), acceptance file = § 4, one independent read by a reader on Opus with its own counterexamples (a tool on a Will-facing control, WQ-447). Until then: no interim bypass — a Light push that cannot satisfy step 10 is reported as a blocked delivery (COMMITTED only) or waits for a reviewed closeout.
