## 1. How the rows were ordered (the criteria, so the order can be argued)
1. **Consequence to Will or the book first:** a defect that can leave Will's ruling unconsumed, mis-state a gate, or hide a desk's due wake outranks a defect that only wastes PROME's own time.
2. **A guard that passes the class it was built for** (fail-open) outranks hardening of a guard that works.
3. **A rule Will already ruled whose tool still contradicts it** (encode owed) outranks a new idea.
4. **Small and bounded beats large,** at equal consequence: a one-cell fix takes the slot a redesign would otherwise hold for a week.
5. **Residue ledgers are swept, not built:** a row that lists flags gets one verification pass, then a tombstone or re-registration per item.
**Purpose test (WQ-299 test 2):** a FORGE market-data tool or a news-collection lane tool PROME repairs serves gates and desks — DOMAIN by purpose, outside the R1 ceiling, however PROME-owned. **Grouping rule:** rows that share one file and one acceptance set take ONE slot; the slot is named by its lead row.
