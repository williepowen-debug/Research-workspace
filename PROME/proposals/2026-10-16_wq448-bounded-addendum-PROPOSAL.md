## D1 — SP3: the receipt binds a STABLE snapshot (amends v2 § 3a)
**Defect (CATO):** v2 takes content ids at the END of `mode_closeout`, after the checks read live files at different moments; a file edited after its check but before the snapshot is hashed under an old passing result.
**Mechanism:** `mode_closeout` takes the snapshot FIRST — `S0 = {path: content_id}` over the freeze scope (`build_scope(baseline, perimeter, include_pending=True)`, lanes OWNED + SHARED + UNATTRIBUTED) plus the two declaration inputs — before any check runs; it takes `S1` the same way after the last check. The receipt is written ONLY when `S0 == S1`; it carries `S0`. Any difference ⇒ no receipt, one line `NOT RECEIPTED: <path> changed during the gate — re-run at a quiet tree`, rc unchanged otherwise (the checks' verdicts still print; only the receipt is withheld). Dirty-path discovery between snapshots (a path present in S1 absent from S0) is a difference. Nothing else in the gate changes; cost = one extra hash pass (~hundreds of files, well under a second today).
**Acceptance:** **A17** (🔴 overlap, CATO's ordering) — a fixture gate run in which an injected callback edits one in-scope path between two checks ⇒ no receipt file, the NOT RECEIPTED line names the path, every check still reports; the same run without the edit ⇒ receipt with `S0` whose ids equal the committed bytes. **A17b** — a path CREATED during the run ⇒ no receipt (missing-information half). **A17c** (ordinary) — two consecutive quiet runs ⇒ identical `delivery` maps.

## D2 — SP5 race: an IMMUTABLE push target through the ACTUAL push (amends v2 § 3b step 8; a bounded, explicit change to `scripts/safe-push.sh`)
**Defect (CATO):** the verb validates a tip, then calls unchanged `safe-push.sh`, which pushes `HEAD:master`; a commit added between validation and the script's push ships unchecked (CATO reproduced it with the pinned script and a substituted push).
**Mechanism:** the verb records the validated tip `T` (full sha) and invokes `bash scripts/safe-push.sh --ref T`. `safe-push.sh` gains that ONE optional argument: with `--ref <sha>` every step that today reads `HEAD` reads `<sha>` instead — the branch assertion (the sha must be on `master`'s first-parent line: `git merge-base --is-ancestor <sha> master`), the ff-check (`origin/master` ancestor of `<sha>`), the ahead count, the log of what goes up, the push itself (`git push origin <sha>:master`), and the post-push confirmation (`<sha>` an ancestor of the freshly fetched `origin/master`). Without `--ref` the script behaves exactly as today (the other desks' closeouts are untouched). If `HEAD != <sha>` at push time the script pushes `<sha>` and prints `NOT SHIPPED (after the validated tip): <n> commit(s) <shas>` — the later commits stay local and need their own release. The shared-script edit is ~12 lines, additive, flag-gated; it is named here as in-scope because CATO asked that the scope be explicit rather than promised untouched.
**Acceptance:** **A18** (🔴 concurrent, CATO's race) — fixture: validated tip `T`, then a follow-up commit, then the verb runs the real pinned `safe-push.sh --ref T` with fetch/push substituted ⇒ the fake push receives `T:master`, not the later tip; the NOT SHIPPED line names the later commit; the confirmation is asked about `T`. **A18b** (ordinary) — `--ref` equal to HEAD ⇒ byte-identical behaviour to today's script on the same fixture (same lines, same rc). **A18c** (wrong owner) — `--ref` of a sha not on `master`'s line ⇒ ABORT before any push. **A18d** — no `--ref` ⇒ today's behaviour, unchanged (regression guard for every other desk).

## D3 — SP5 carried work: ATTRIBUTION is explicit, never inferred from the audit perimeter (amends v2 § 3b step 5)
**Defect (CATO):** v2 classified every SHARED/UNATTRIBUTED path as PROME delivery and refused commits mixing them with EXCLUDED paths; the real DEWEY delivery `46299b920` (own output EXCLUDED · PROME inbox packet EXCLUDED · four recipient packets SHARED) would be refused although it is one owner's legitimate commit. The perimeter classifies what PROME AUDITS; it does not say who AUTHORED a path.
**Mechanism:** a commit's class comes from two existing facts, in order. (1) **The intent record** — `commit_check.py commit` already writes an intent per commit; from the addendum's cutover commit onward it also writes `attribution` for every SHARED/UNATTRIBUTED path in that commit: `PROME` (bound into the delivery and the receipt) or `CARRIED:<DESK>` (named, not audited). (2) **Absent an intent record** (every commit before the cutover, and every commit made by another desk's runtime, which never calls PROME's wrapper): the commit's subject convention — the fleet form `<DESK>: …` / `<DESK> -> <RECIPIENT>: …`, the same rule `spawn_list.py` already uses for desk-commit attribution (L455, tested) — names the owner; a commit whose subject names a desk other than PROME and whose paths are all EXCLUDED or SHARED is **carried** under that desk; a PROME-subject commit with SHARED paths is PROME's delivery and must be bound (so a PROME-subject commit from before the cutover whose SHARED paths are not in the receipt refuses — re-run the gate at the tip binds them); an UNATTRIBUTED path with neither an attribution nor a desk subject ⇒ refuse, `UNATTRIBUTED <path> in <sha> — add attribution via the intent record or name the owner`. No other owner's history is rewritten or split; the perimeter is not broadened to earn a pass.
**Acceptance:** **A19** (🔴 overlap, CATO's real shape) — a fixture reproduction of `46299b920`'s path classes under a DEWEY subject ⇒ carried, named `DEWEY`, not audited, push permitted. **A19b** — the same paths under a PROME subject with the SHARED packets bound in the receipt ⇒ PROME delivery, permitted; with one SHARED packet unbound ⇒ refused (changed/added after the gate). **A19c** (missing information) — an UNATTRIBUTED path, no intent, subject names no desk ⇒ refused, no push. **A19d** (ordinary carried) — a desk-only commit (all EXCLUDED) ⇒ carried, as v2 A11. **A19e** (cutover) — a commit older than the cutover with no intent record is classified by rule (2) and never by the absence of a record.

## D4 — INITIATOR-INDEPENDENT enforcement at the installed `pre-push` hook (new; amends v2 § 3b step 8's reliance on the verb alone)
**Defect (CATO, 21:31 ET):** the installed `scripts/githooks/pre-push` (`core.hooksPath = scripts/githooks`; installed by `install-git-hooks.sh`, which `safe-push.sh` runs first; ordinary direct `git push` also hits it) enforces ancestry only; another desk's push — through the shared script OR plain `git push` — carries PROME's withheld commits to origin with no PROME release check. A verb-only control leaves both routes open.
**Mechanism:** the verb, on a permitted push, writes a per-clone, gitignored **release record** `PROME/state/release/<tip-sha>.json` `{tip, tier, receipt_sha256, verified_at, range_base}` BEFORE calling the script. The hook gains one leg after its ancestry check: for each pushed update of `refs/heads/master`, run `python3 PROME/tools/commit_check.py hook-check <remote_sha>..<local_sha>` (the same classifier as D3, read-only, no gate run): every commit in the range classified as PROME's delivery must be `<=` some release record's `tip` whose `tip` is an ancestor-or-equal of `local_sha` and whose `range_base` is an ancestor-or-equal of `remote_sha`; otherwise the hook exits 1 with `pre-push: PROME commit <sha> has no release record — PROME runs \`commit_check.py push --tier <t>\`; carried pushes wait for it`. Carried commits (D3) pass on ancestry alone. The hook therefore refuses the same train whichever desk or route initiates it. **Stated limits:** a local hook is bypassed deliberately by `--no-verify` or by changing `core.hooksPath` — this is ACCIDENTAL-bypass protection, named as such; no remote permission or CI writer is proposed (CI never becomes an acceptance writer, root canon); a desk's push is slower by one classifier run (~1 s). A PROME commit made AFTER its release (a later tip) has no record and is refused until re-released — intended, the same rule as D2's NOT SHIPPED line.
**Acceptance:** **A20** (🔴 wrong owner, CATO's case) — fixture clone with the hook installed; another desk's direct `git push` carrying an unreleased PROME commit ⇒ refused by the hook, nothing on the fake origin; the same via the pinned `safe-push.sh` ⇒ refused the same way. **A20b** (positive) — after `push --tier` wrote the release record for that tip, both routes push. **A20c** (ordinary carried) — a range of only carried commits ⇒ passes with no record. **A20d** — a PROME commit after the released tip ⇒ refused until re-released. **A20e** — the bypass is documented, not tested (a test proving `--no-verify` bypasses would be decoration).
