## What is true today (verified at the artifacts, 12:1x ET)
1. `git config pull.rebase` = `false` in this clone, so a **plain `git pull` MERGES**. A merge pull with a dirty tree succeeds whenever the incoming commits do not touch the dirty paths — it does not refuse. DEWEY's claim is correct.
2. **`git pull --rebase` refuses whenever ANY tracked file is modified or staged, whoever owns it** ("cannot pull with rebase: You have unstaged changes" / "Your index contains uncommitted changes"). Untracked files do not block it, with one exception the reader measured: if an incoming commit ADDS a path that already exists untracked locally, Git aborts ("untracked working tree files would be overwritten") and nothing is lost. That refusal is exactly the protection the root rule wants, applied mechanically.
3. Root `CLAUDE.md` § Git Protocol "Never" list (L105) says: *pull when other agents have uncommitted local changes (sole exception: session-end step 3's non-ff recovery, and only after its dirty-path overlap check passes)*. `docs/GIT_WORKTREE_PROCEDURES.md` § Before pulling steps 1–2 say: check for changes outside your directory; if any, **STOP. Do not pull.** `PROME/BOOT.md` step 0 says: *If dirty/untracked/staged, do not pull.*

## The change (exact text; one edit per file, same sitting, after the plan read and Will's word)

### A. Root `CLAUDE.md` L105 — replace the clause `pull when other agents have uncommitted local changes (sole exception: session-end step 3's non-ff recovery, and only after its dirty-path overlap check passes)` with:
> pull any way other than **`git pull --rebase`** — never a plain `git pull` (this clone's `pull.rebase` is `false`, so a plain pull MERGES around other agents' dirty files instead of refusing), and `--autostash` only inside session-end step 3's non-ff recovery, after its dirty-path overlap check (the one place a stash that holds other agents' files is tolerated). Git refuses a rebase pull while ANY tracked file is modified or staged, whoever owns it; that refusal IS the rule, never an error to work around: stop, do not stash, reset or commit another agent's work, continue on the checkout you have (`git fetch origin` and read `origin/master` for anything you need), and pull again after they commit. If the rebase stops on a conflict in a commit you did not author (`git log -1 REBASE_HEAD` names it) ⇒ `git rebase --abort` (fetched refs stay updated; pop any stash you made) and flag to PROME; a conflict in your own commit is yours to resolve. Untracked files block only when an incoming commit adds the same path — move yours aside, never delete, pull again. A desk charter's bare "`git pull`" boot line means this form.

### B. `docs/GIT_WORKTREE_PROCEDURES.md` § Before pulling — replace steps 1–3 with:
> 1. `git pull --rebase` — the only pull form. Never a plain `git pull` (merges; `pull.rebase=false`), never `--autostash` (session-end step 3 excepted).
> 2. **The dirty-owner stop is Git's own refusal.** If it refuses on modified or staged files that are YOURS: commit them pathspec-scoped (preferred), or `git stash push -- AGENTS/<YOUR_NAME>/` → pull → `git stash pop` — and pop even if the pull was refused. If the blocking files are another agent's: STOP; do not stash, reset or commit them; continue on your current checkout, `git fetch origin` and read from `origin/master`; pull again after they commit. If Git aborts because an incoming commit adds a path you hold untracked: move yours aside, never delete, pull again.
> 3. If the rebase stops on a conflict inside a commit you did not author (`git log -1 REBASE_HEAD`): `git rebase --abort` (fetched refs stay updated; pop any stash you made), flag to PROME. A conflict in your own commit is yours — step 5 governs the files.
Steps 4–5 unchanged.

## What does NOT change
Pathspec commits only · never force · never resolve another agent's conflicts · session-end step 3's non-ff recovery and its dirty-path overlap check (the only place `--autostash` is allowed) · the carve-outs · ONE machine at a time (`MACHINE_LOCAL.md`) — that rule is about machines, not desks.

## Why this is a tightening, not a loosening
The current rule asks every agent to run a judgment check ("are other agents' directories modified?") that Git already runs mechanically and more completely (it also catches staged files and files outside `AGENTS/`). The current rule's literal reading on untracked files produces false alarms that train desks to ignore it. After the change, the only pull that remains possible is the one that cannot sweep anyone's TRACKED work (a rebase still rewrites other desks' unpushed local commit hashes — accepted at root step 3, "verify by subject" — and still aborts safely on an untracked same-path collision).

## Neighbours considered (WQ-229)
ordinary: clean tree ⇒ rebase pull as today · overlap: your own dirty files AND another desk's ⇒ Git refuses; commit yours, still refused until theirs commit — correct · wrong owner: a desk's rebase replays another desk's unpushed local commits (hash rewrite) — already accepted at root step 3 ("verify by subject"); conflict inside such a commit ⇒ abort, never resolve (new step 3) · missing information: `pull.rebase` unset on a fresh clone — Git 2.43 refuses a plain pull on divergent branches ("Need to specify how to reconcile divergent branches") and merges only on a fast-forward; the rule names `--rebase` explicitly so the config does not matter · concurrent: two desks pulling at once — Git's index lock serializes; a refusal is retried, never forced.
