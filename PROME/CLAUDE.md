## Session Process Controls (WQ-140, forward-only) · **FREEZE (WQ-299 R3, Will-ruled 2026-09-26 13:07 ET): no new bullet enters this section before 2026-10-25 except paired with a named consolidation in the same edit; spine audit #15 carries a consolidation PROPOSAL (C2–C4, named in the WQ-299 record), approved by Will candidate by candidate; automability is never a criterion for retiring a duty — ownership, uncertainty and review obligations stay whether or not a check exists; the charter target under 20,000 B (`measure.py`) measures the pass and licenses nothing.**

- **Measurement — instrument, never prose (C1):** every REPORTED byte count / line count / crc receipt comes from `PROME/tools/measure.py` — the sole approved source (wc semantics, labeled units, re-reads the file at receipt time; `--selftest` is its falsification set). Never ad hoc `len()`. **And a document never carries a figure a reader can recompute from an instrument:** a document never carries a figure a reader can recompute from an instrument (its own byte count, a to-the-minute stamp of itself, a file's current size) — it names the instrument (`measure.py`, `git show <sha>`) instead. A self-describing figure is stale by the next edit and reads as an error in every cold read. Same lesson as root rule #4, applied to our own prose.
- **Confidence tokens** on claims in audit/verification reports: **VERIFIED** (checked at the artifact) · **INFERRED** (supported, not directly established) · **SEARCH-NOT-FOUND** (query returned nothing) · **UNKNOWN**. An absence claim upgrades SEARCH-NOT-FOUND → VERIFIED only after the owner-declared path/identifier AND any documented fallback are checked — a broader grep is not an upgrade. *(Registered — `STATE_VOCABULARY.md` Class 13, encoded 2026-09-01.)*
- **Review budget (L511):** **Episode** — one change to one artifact (a repair, a canon edit, a rotation, an archival split), first edit to disposition; a read spanning several artifacts counts once in each; a new session, a renamed defect or a new label never resets an episode's count, and approval does not reset it; a later, materially different defect is a new episode. **Reads** — WQ-178 governs its classes: one plan read, one result read, and a third ONLY when a ❌ fix on the result changed a rule's meaning, for rotations and archival splits as for canon; a byte count, a stamp or a pointer form never earns a read. Three independent reads per episode is the outer ceiling, never an allowance; parallel readers each count; Will may authorize a named further read. Missing read history is UNKNOWN: a baseline read of the acceptance file (`reads:` line, `PROME/tools/tests/README.md`) precedes any further round, and a count is never invented. **Procedure exception** — on a procedure file (a manual, runner or skill executed as written), a required read-only execution check may occupy the third read within the ceiling without a rule-meaning fix — never a fourth, never an automatic third on other work. A clean text review does not establish executability or cancel a required execution check; an unperformed required check stays explicitly PENDING · UNVERIFIED and disclosed, and any further read needs Will's named authorization. **Early stop (WQ-165's test, inside the budget)** — stop at ❌ = 0, or after two consecutive reads whose ❌ are all basis/pointer class; an action-class ❌ forces another read only while the budget allows one, and past that point forces a disposition, never an extra read. **Disposition (WQ-229 states)** — a fix made after the final read is unreviewed and never INDEPENDENTLY VERIFIED. **Withholding follows consequence, not defect class:** any unresolved defect that could materially change a decision or instruction — a consequential basis or pointer error included — is WITHHELD from operational use, at an early stop as at the ceiling, whatever the file: the claim or instruction is replaced by a pointer to its authoritative source and last reliable version (a commit); where no reliable source or prior version exists it is marked UNAVAILABLE — do not act, never pointed at a known-bad version. Evidence stays in git and required archives; the defect goes into the closeout report and a DOCKET row; a tool or gate is withdrawn or disabled (R2). A STILL UNRESOLVED label beside a live instruction does not satisfy this. **Corrections (the two-correction stop)** — two correction passes on one file in a session (a pass = one sitting's fixes, committed or not) ⇒ any further correction to that file needs an independent read, counted inside its episode's budget — `[[finding_a_correction_pass_is_unreviewed_work]]`. A **sourced receipt** — a dated fact with its source that changes no existing claim or instruction (e.g. *"onward routing PENDING until a WALTER commit evidences it"*) — is not a correction and needs no read beyond the closeout's own; an addition that approves, changes a quantity, re-grades or claims completion alters the instruction it touches, even appended, and needs that change's applicable review.
- **Pre-edit cold read** for root canon · registry-wide transformations · archival splits · broad batches: a cold reader inspects the proposed findings/diff + invariants BEFORE implementation; post-edit validation is still required (different failure modes). Audit passes deliver the five-field assertion-ledger format: claim → exact artifact → verification command → observed result → proposed change.
- **Read budget (WQ-178):** any edit in the Pre-edit-cold-read class above (root canon · registry-wide transformations · archival splits · broad batches — plus a verbatim MOVE of text between files and any canon amendment) gets ONE blind read on the PLAN (the proposed text + invariants, before any edit) and ONE on the RESULT. After a read, fix ❌ ONLY; every ⚠️ goes into a **declared residue block** — a dated paragraph in the artifact itself (or, for a canon file, in its ruling record) listing each un-fixed flag — unless the fix is a one-word typo. The third read, the episode ceiling, withholding at the limit and the correction count → the **Review budget** bullet in this section. **(WQ-299 R2)** An externally blocked repair is recorded as blocked in the closeout report — it neither disappears nor becomes a standing prohibition on necessary maintenance.
- **Canon drafts live in the ruling record, transplanted once:** an amendment to a canon file (`FORGE/PREDICTION_DISCIPLINE.md`, root `CLAUDE.md`, `AGENTS/DAEDALUS/BLUEPRINTS/*`) is drafted in its proposal record (`PROME/proposals/<date>_<topic>-PROPOSAL.md` before the word, renamed `…-RULED.md` at the word) and cold-read THERE (the plan read), then inserted into the canon file in ONE edit; the result read may force AT MOST ONE further edit of the canon file (❌ only), after which residue is declared in the record. - **Repair-completion discipline (WQ-229):** for any fix to a check, gate, instrument or tool, **write the ACCEPTANCE CONDITIONS before editing** — properties in the defect's terms, not a restatement of its symptom. **Test the NEIGHBOURS, not just the reproduction** — **CONSIDER** all five categories, **ordinary · overlap · wrong owner · missing information · concurrent activity**, and write a one-line justified **N/A** for any that does not apply (contract + fixture rules: `PROME/tools/tests/README.md`; the miss that kept F1 open was an OVERLAP — a path both committed and pending). ⚠️ **Consider, not perform: requiring five mechanically on every small repair IS the paperwork reflex this rule exists to reduce** (external review refinement 2). **A completion note distinguishes four states and never merges them: IMPLEMENTED · TESTED · INDEPENDENTLY VERIFIED · STILL UNRESOLVED** — passing the author's own tests establishes *implemented*, never *verified* (`finding_adoption_is_not_validation`) — and **PROME supplies that note UNPROMPTED; Will gives the instruction once, never per repair** (refinement 1). **A CONSEQUENTIAL repair** — one touching a gate, a shared contract, a Will-facing surface, or a defect that has already recurred — **goes to an independent reader BEFORE it is called fixed**, and that reader devises **at least one counterexample of its own** rather than re-running the author's suite. - **Spawn-closeout discipline (WQ-249):** **a spawn is not complete when the desk DELIVERS — it is complete when the desk has been ASKED to close out and PROME holds the answer, or has RECORDED that it went dark before the ask.** **PROME owns this, never the desk:** an idle desk cannot know the terminal is about to close, so a desk going dark unasked is an ORCHESTRATION failure.
