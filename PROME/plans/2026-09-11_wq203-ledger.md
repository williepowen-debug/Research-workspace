## Deliverable
1. **`PROME/registry/WQ_LEDGER.tsv`** — append-only, tab-separated, header row + one EVENT row per change. Columns (14): `wq` · `event` ∈ {BACKFILL, REGISTERED, RULED, DECLINED, CLOSED, UPDATED} · `at` (YYYY-MM-DD, HH:MM ET when known, else the row's date) · `title` (the bold lead, ≤120 chars) · `type` · `needed_by` · `since` · `status_after` ∈ {OPEN, ANSWERED-OWED, BLOCKED, ANSWERED-BLOCKED (answered AND ⛔ waits — the deck's two independent booleans, ⚠️10), RULED, DECLINED, CLOSED} · `verdict` = the lead token the fleet WROTE, kept as written ∈ {APPROVE, RULED, DECLINE, CLOSED-BY-PROME, OVERTAKEN, RESOLVED, EXECUTED, SUPERSEDED, WITHDRAWN, TERMINAL, —} — **mapping (⚠️9):** DECLINE ⇒ DECLINED; APPROVE / RULED / RATIFIED ⇒ RULED; OVERTAKEN / SUPERSEDED / WITHDRAWN / TERMINAL / EXECUTED / RESOLVED / CLOSED ⇒ CLOSED (the token survives in `verdict`) · `will_verbatim` (the quoted word if the row carries one, else EMPTY) · `rec` (PROME rec at the time, ≤300 chars) · `record` (the ruling record path or the row's record cell) · `source` (which file/section the event was read from) · `written_at` (the ledger write stamp, from the clock). Rows are NEVER edited or deleted; a correction is a new UPDATED event. The current state of WQ-n = its last event row.
2. **`PROME/tools/wq_ledger.py`** — imports the deck's parsers so there is ONE queue parser in the fleet. **Deck changes this build makes so that holds (all in `decision_deck.py`, covered by its selftest):** `parse_decided(q_path=None, arch=None, ledger=None)` — injectable paths (fixture-drivable; defaults unchanged) · `parse_archive(text, source)` — PER-LINE shape dispatch (bare-number first cell + ≥6 cells ⇒ open-style; `**NNN Title**` + 3 cells ⇒ done-table), replacing the file-level fallback (❌3) · `verbatim_of(cell)` — the quote extractor (rule 4 below) · `parse_ledger_decided(path)` — terminal-state rows from the ledger · `_root()` — git from the FILE's directory, then the cwd, then the file's depth (⚠️7). The ledger tool's own regexes touch only ITS cells (dates, tokens) and the parser-independent cross-count (I3) — never a queue row. Subcommands: `backfill` (one-time: writes one BACKFILL event per WQ number found in the live OPEN + RECENTLY DONE + every archive — first-seen wins, same precedence as the deck: LIVE OPEN over anything (a row mid-rotation is still Will's open item), then the live done table, then newest archive; refuses to run if the ledger already has rows; its receipt prints the deck's distinct-number count AND a parser-independent plain-regex cross-count over the same files, and returns rc 1 on a mismatch) · `sync` (idempotent: re-parses the live queue; for each WQ whose parsed state differs from the ledger's last event — new number ⇒ REGISTERED; lead now RULED/APPROVED/DECLINED/CLOSED ⇒ the matching event with the verbatim quote pulled from the row; a row that left OPEN for RECENTLY DONE with no lead change ⇒ CLOSED; same state ⇒ nothing) · `check` (rc 0/1/2 per CHECK_STANDARD §9: header + column count + event AND verdict vocabularies + `at` dates parse + monotone `written_at` + no duplicate (wq,event,at,status) + **the SEAL**: every tool write stores `<rows>\t<crc32 of the whole file>` in the sidecar `WQ_LEDGER.crc`; `check` recomputes and fails on any byte change since the last tool write — a hand edit, a deletion or a reorder of ANY prior row fails, which is what "append-only" means here; the tool itself only ever opens the ledger in append mode) · `state` (prints the current state table, one line per WQ) · `--selftest` (a frozen fixture under `PROME/tools/tests/fixtures/wq_ledger/` — NOT the live queue; `finding_regression_test_pinned_to_a_live_surface_rots_on_the_next_edit`).
3. **Deck integration:** `decision_deck.parse_decided()` reads the ledger's terminal-state rows (RULED / DECLINED / CLOSED) FIRST; archives remain a fallback ONLY for a WQ number absent from the ledger (transition safety), and the Decided tab's card footer names the source ("ledger" vs "archive/…"). The deck's `rulings` store pickup (BOOT 3b) is unchanged; the `sync` step runs at closeout AFTER the queue's paired write and BEFORE the deck regen (CLOSEOUT symmetry table: one new row; `/closeout` runner: one pointer line — layering rule, manuals own rules).
4. **Verbatim rule (`decision_deck.verbatim_of`):** `will_verbatim` = the FIRST quoted span (`"…"` or `“…”`, with or without the `*` italics) that follows the word **verbatim** in the cell, copied exactly. A quote with NO "verbatim" anchor ⇒ EMPTY by design (the anchor is the fleet's recording form for WILL's word; a desk's quoted words and Will's un-anchored in-session speech are never promoted to the cell — a reader wanting them reads the row). Rows with several anchored quotes take the first (the ruling; later quotes are amendments the row text keeps). Never a paraphrase. Taps carry the deck's note text under the same anchor ("note verbatim: …").

## Invariants the result must hold
- I1 Append-only ENFORCED, not promised: the `.crc` seal (rows + whole-file crc32, rewritten by every tool write) makes `check` fail on any change to any prior row; plus `written_at` non-decreasing and a byte-identical header. Tested in `--selftest` by hand-editing a prior row of the fixture ledger and asserting rc 1.
- I2 One parser: every queue ROW comes through `decision_deck` functions (`parse_open`, `parse_decided` → `parse_archive`, `verbatim_of`); `wq_ledger.py`'s own regexes touch only its own cells and the I3 cross-count. Any parser gap is fixed in `decision_deck.py` (with its selftest) and inherited.
- I3 Backfill completeness, checked by an INDEPENDENT instrument: the backfill receipt prints the deck's distinct-number count beside a plain first-cell regex count over the same files (zero free parameters); a mismatch returns rc 1 and blocks the install. A closed-in-place OPEN row (dropped by `parse_open`) would show as a mismatch here — the latent case the read named (⚠️8).
- I4 The deck still renders: `python3 PROME/tools/decision_deck.py --selftest` passes after the integration; the Decided tab row count is ≥ the pre-integration count (archives still cover what the ledger lacks).
- I5 Idempotence: running `sync` twice in a row appends zero rows the second time (asserted in `--selftest` on the fixture).
- I6 No live measurement in prose: this plan and the tool's docstring name the instrument (`wq_ledger.py state | wc -l`, `measure.py`), never a count that goes stale.
- I7 Byte discipline: the ledger is NOT a boot read (no read-cap concern); the deck reads it programmatically. It never rotates — history is the point.
- I8 Scope: nothing about HOW Will's rulings are recorded changes (the row text + the proposal records stay canonical; the ledger is a projection written from them). If the ledger and a row disagree, the row wins and `sync` writes an UPDATED event — the ledger never silently "corrects" a row.
