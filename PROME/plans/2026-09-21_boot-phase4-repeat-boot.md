## Implementation plan

1. Extend `boot_read.py` through a small `boot_reuse.py` helper with optional `--read-state <outside-repo-json> --context-id <id>`, `--ack-read` and `--reuse` switches. No switches means today's full reader. Only full views of the two explicit instruction paths are eligible; all other paths/views always emit text. A completed contiguous pagination must be explicitly acknowledged with its digest before it can be reused. Emitting EOF alone is insufficient.
2. Bind receipts to resolved repository, context identity, ET date, schema, source digest and policy digest. The policy digest covers both eligible files, root/PROME CLAUDE, AGENTS, READS, both boot skill indices and the reader/reuse code. Changing any basis invalidates reuse. New context, date change, missing/malformed/incompatible baseline or missing policy inputs falls back to full text. Never create a read receipt from an arbitrary last-page seek, interrupted chain or changed-source continuation. A cache only reports retained instructions, never boot completion or authenticated runtime context.
3. Serialize receipt updates with a nonblocking file lock and atomic replacement. Busy/unwritable state falls back to the full read path, without marking completion. State must be outside the repo and distinct from source/basis files; missing parent is a fallback, not permission to create directories. Recheck source and policy around recording/reuse; a detected change refuses reuse. The caller must use a new context ID after compaction, handoff, new session or any doubt about retained instructions. No cross-session reuse.
4. Add `boot_session.py --refresh`, valid only beneath an existing valid completed original boot (rc 0/1). It reruns the same gate checks via a `refresh` mode with the BOARD scan's `--advance` omitted. All existing checks, severities and coverage remain; no cached mechanical verdict. Fresh logs and observation receipt live in a uniquely allocated refresh subdirectory. Original attempt/completion remain unchanged. Missing/malformed/rc2/interrupted original attempts return UNKNOWN without invoking any child. A refresh never upgrades an incomplete advancing attempt. Plain retry behavior stays unchanged.
5. BOOT/skill instructions require fresh repeat checks plus renewed private-ruling pickup, corrections, capability/preflight, dated obligations and market-data-at-use procedures. Missing private tools remain PARTIAL, not “no new rulings.” No new gate directory or raw gate invocation bypasses the original one-shot guard. A new genuine session performs a full boot with a new context.

## Acceptance conditions — before implementation

- Ordinary: acknowledged contiguous full reads of either eligible instruction file can be reused in the same retained context; every other document/log still emits its contents. No receipt is a boot-completeness claim.
- Overlap: changed instructions invalidate otherwise unchanged reads; old completed receipt plus new ruling/correction/deadline still triggers fresh work. State files can contain multiple eligible documents without one acknowledging the other.
- Wrong owner/context: repo/context/day/view/path mismatch cannot reuse; external or symlinked sources cannot impersonate either approved instruction file. No foreign state/ledger mutation.
- Missing information: absent/corrupt/incompatible baseline, basis file, context or interrupted page chain never produces a reuse success. Explicit acknowledgement requires recorded contiguous EOF and matching digest. Missing/unreadable source remains error, never clean empty.
- Concurrency: source/policy changes and competing state writers fail safe; retries do not duplicate BOARD advancement. Incomplete original boots cannot launch refresh or gain a completed advancing receipt.
- Time: advance the fixture clock with identical files; reuse falls back across ET dates and the refresh invokes time-sensitive checks again. A due-date transition must become visible without any source edit.
- Same-day arrivals: new fixture BOARD/correction/ruling data remain discoverable; BOARD refresh sees new ACTION signals without advancing the cursor. Private Artifact pickup stays mandatory at every repeat and is never represented by a disk digest.
- Preserve Phase 3 view, raw-read digest behavior and all gate severity/rc contracts. Full-read fallback is always available. Use disposable fixtures only, strict ResourceWarning, plan and result reviews with independent counterexample. No live boot/refresh in this implementation session.
