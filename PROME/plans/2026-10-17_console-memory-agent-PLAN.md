## 1. The pieces, in plain words

| Console object | What it is | Why it matters here |
|---|---|---|
| **Agent** | A saved, versioned job description: model, instructions, tools, integrations. Built once, reused. | This is the "who". Edits create a new version; old sessions keep theirs. |
| **Environment** | The sandbox computer each run gets (files, bash, web on/off). | Set networking to `limited` and allow only what the job needs. |
| **Session** | One run of the agent. Streams events; ends idle. | Ephemeral by default — nothing learned survives unless a memory store is attached. |
| **Memory store** | A workspace-level folder of small text files (≤100 KB each) that persists across sessions, mounted into the sandbox at `/mnt/memory/<name>/`. Every change is an immutable version with an audit trail and redact. | **This is the externalized memory.** The agent reads and writes it with ordinary file tools. Max 8 stores per session; read-only or read-write per store. |
| **Scheduled deployment** | A cron schedule that fires a session on its own (minute granularity, IANA timezone, up to ~9 min jitter). Carries a per-run dollar cap. | The "morning check-in" or "evening sweep" shape. Manual run available for testing. |
| **Vault** | Credential store (OAuth for MCP servers, env-var secrets substituted at egress). | Never put keys in memory stores or prompts. |
| **Session budget** | Hard dollar cap per session at list prices; pauses, never terminates. | Guard the $200. |
