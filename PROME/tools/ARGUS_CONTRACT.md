# Explicit delivery contract (ARGUS schema 2)

Use this workflow for concurrent closeouts after the October19 repair acceptance. `argus_scope.py --record-review` without `--contract` retains the legacy strict behavior; it does not silently migrate or downgrade an existing review. Receipt exclusions and the legacy consumed-move workflow are unchanged. A new schema2 closeout classifies its PENDING observed inventory (any porcelain state, untracked included) and its own OWNED-lane paths; **committed-only paths outside PROME's OWNED lane are attributed by their own commits and need no `observed` entry (WQ-485 A, Will 2026-10-22 12:10 ET; recorded in the manifest as `attributed_by_commit`; acceptance `PROME/tools/tests/ACCEPTANCE_argus_contract_wq485_2026-10-22.md`). Before 10/22 every committed path since the baseline needed a classification (307 paths, four freeze iterations on 10/22);** outside that exemption, path ownership and commit subjects remain reading hints, never proof of delivery or non-reliance; inside it, a `PROME` commit subject or a from-PROME filename REMOVES the exemption (PROME must deliver or observe such a path), it never grants one. **The perimeter every schema-2 (contract) verify classifies with is PINNED in the manifest at the freeze (`perimeter`: the rules as loaded plus the file's byte digest; L796 ❌2 repair 2026-10-24, acceptance `PROME/tools/tests/ACCEPTANCE_closeout_gate_perimeter_pin_2026-10-24.md`): the live `PROME/state/AUDIT_PERIMETER.tsv` is never read at verify time, a post-freeze edit of it is an OWNED arrival that blocks until delivered in a re-freeze, and a manifest without a pin runs strict. A perimeter changed since the baseline must be DELIVERED at the freeze (never attributed by commit, never observed-only); `.gitignore`/`.gitattributes` edits at the root or in a folder the pinned rules do not class EXCLUDED are never advisory; a nested ignore file inside an EXCLUDED folder stays advisory and can hide a new uncommitted file below it from the working-tree gate (step 10 still refuses a force-added commit) — residual fix DOCKET L835. The legacy schema-1 path (`--record-review` without `--contract`) still reads the live perimeter and is outside this guarantee.** **Freeze rule 2026-10-29 (Will 14:05 ET; acceptance `PROME/tools/tests/ACCEPTANCE_freeze_foreign_pending_2026-10-29.md`): a pending path outside PROME's OWNED lane under the pinned perimeter, not delivered, not an ignore/perimeter file and carrying no PROME authorship evidence (the overlap included when its commits are all non-PROME) is RECORDED under the manifest's `foreign_at_freeze` and needs no `observed` entry; OWNED, PROME-evidenced and guarded pending paths still require one or block.**

Prepare a JSON plan outside the repository, or include that plan itself in delivery. Its shape is:

```json
{
  "delivered": {"PROME/report.md": "Authored in this session; exact task/provenance"},
  "evidence": [{"path": "AGENTS/OWNER/report.md", "commit": "persisted commit SHA",
    "mode": "historical", "claims": {"PROME/report.md": "Dated owner result being consumed"}}],
  "observed": {"AGENTS/OTHER/pending.md": {"owner": "OTHER", "not_relied_on": true,
    "reason": "Actual contribution provenance and why no delivered claim relies on this version",
    "basis": {"path": "AGENTS/OTHER/receipt.md", "commit": "persisted commit SHA"},
    "quote": "Exact attribution passage from that receipt"}}
}
```

Delivery includes all claimed changes since the recorded baseline, including earlier commits, pending edits, deletions and nested/shared paths. Evidence requires a persisted version; `historical` pins that version, while `current` additionally requires matching current/delivered bytes. Both roles may apply to a delivered file. A changed live version of historical evidence needs its own unrelated-version classification; the pinned claim remains unchanged. Uncommitted evidence actually needed by a claim remains a real blocker. Never commit another owner's work merely to clear it.

From repo root:

```sh
python3 PROME/tools/argus_scope.py --record-review --contract /tmp/prome-delivery-plan.json
```

Review the frozen contract and classifications, then run `--mark-reviewed "actual reviewer receipt"`. Promotion, the normal gate and post-commit verification use the same contract. The immutable contract digest binds delivered bytes, earlier versions and dependencies. Observed attribution remains an accountable human judgment, not automated authorship authentication.

If proven unrelated work arrives or changes, supply only its attributed classifications in a JSON mapping and run `--observe /tmp/prome-observed.json`. This appends captured versions and leaves the contract/review intact. No blanket exclusions; ambiguous arrivals fail — with ONE named exception at both verify forms (CLOSEOUT.md step 8 live-fleet rule, Will 2026-10-22; extended to the `--ref`/`--snapshot` forms by WQ-517 A, Will 2026-10-24) and, for a path the desk committed and is still editing whose commits are all non-PROME by subject, by WQ-448 re-scoped (Will 2026-10-29; reported `FOREIGN-PENDING-OVER-COMMITTED`): a PENDING-ONLY path with no commit in baseline..HEAD, not OWNED under the pinned perimeter and not PROME-evidenced, is reported as `FOREIGN-PENDING (advisory …)` and does not block. New delivery or relied-on evidence requires re-freeze and changed-portion review. Do not use observation to remove a delivered/current-evidence obligation.

**WQ-583 (Will 2026-10-31 20:26 ET, verbatim "can you do this part now"; DOCKET L912; acceptance `PROME/tools/tests/ACCEPTANCE_wq583_candidate_moves_reuse_2026-10-31.md`; tests `test_argus_wq583.py`):**
- **Candidate off the shared branch.** Every schema-2 freeze also writes the delivered bytes as an immutable commit K (parent = HEAD at freeze) referenced only by `refs/prome/argus-candidate` — on no branch, so no desk's safe-push can publish it. ARGUS reads the candidate (`git diff <baseline>..K -- <path>`, printed by the scope listing). The working-tree verify (gate, `--mark-reviewed`) checks delivered bytes AT K; a later working edit of a delivered path is listed `POST-FREEZE EDIT` and does not block. The `--ref`/`--snapshot` forms stay strict.
- **Delivery.** `--deliver-candidate -F <msg> [--carry <path> …]` makes ONE master commit of K's bytes on top of current HEAD (compare-and-swap; other desks' commits kept), then syncs the shared index for exactly those paths. It refuses: verdict not REVIEWED for this contract; a candidate path changed on master since the freeze; the shared index holding another version of one; a post-freeze edit not named with `--carry`; a subject over 100 characters; and, just before master moves, any refusal by the repository's pre-commit or commit-msg hook run on the delivery's own index (account guard, DOCKET line stability) or a hook that edits that index. It prints the SHA and the paths for the verify below. Carried edits ride the step-12 bookkeeping commit.
- **Byte-identical moves** (origin gone and present AT THE BASELINE, same-basename destination new since the baseline, bytes equal to the origin's baseline bytes — a version gained inside the window is new content, never a move — the same file mode, exactly one pairing, both legs on the same side of PROME's tree (`PROME/` or an OWNED lane, versus everything else), and the destination's pinned lane equal to the origin's, or SHARED → EXCLUDED (a consumption) — never from a less-audited lane into a more-audited one, never a live file into an inbox; no pinned perimeter ⇒ no moves) are recorded under the contract's `mechanical_moves`, need no `delivered`/`observed` entry, are accepted at every verify form while they still hold; only PROME's own moves (both legs on PROME's side) are accepted among a PROME commit's actual paths — a desk's move never rides a PROME commit. Never the perimeter, an ignore/attributes file, a receipt path or an explicitly delivered path. PROME's own pending moves (both legs in `PROME/` or an OWNED lane, e.g. `FORGE/` → `FORGE/_archive/`) ride the candidate; a desk's move of a `from-PROME` packet is recorded, never committed by PROME.
- **Reuse.** A re-freeze on the same baseline after a REVIEWED manifest records each delivered path whose bytes equal the reviewed version under the contract's `reused`; plan-declared reviews (`"reviewed"`) are switched off (WQ-584, read #3 ⚠️3: self-attested). The scope listing marks reused files; claims about them elsewhere stay in scope. Reuse inherits whatever REVIEWED meant, including routine fixes disclosed as unreviewed.
- **Derived list.** `"auto_delivered": true` derives `delivered`: OWNED paths under the pinned perimeter; outside that lane, only paths with NO pending edit that a `PROME`-subject window commit touched or that carry a `from-PROME`/`MSG-PROME` name, plus PROME's own NEW pending `from-PROME` packet in a shared inbox — absent at the baseline and at HEAD (never `via-PROME`; a desk's edit or deletion of an older packet is the desk's; a pending edit outside PROME's lane may be another desk's, so PROME names it or classifies it); `"exclude": [paths]` keeps a path out — minus move legs; provenance comes from the commit subjects; explicit entries override. A PROME file in a shared folder with no PROME evidence — the daily `memory/<date>.md` — cannot be derived: the freeze prints every such path as `FOREIGN at freeze` — move each one that is PROME's (the daily memory file, `USER.md`, a Will-approved root edit, a PROME FORUM post) into `delivered`. Residue: an OWNED file another desk wrote is claimed as PROME's (as the hand rule already required).

After the exact-path commit (or `--deliver-candidate`), resolve and save its full SHA as A, then run `--verify-review --ref <A> --paths <exact commit paths>`. The verifier also checks actual commit paths, the complete delivery set and full inventory; an omitted/truncated list does not hide an added path. Delivered content, current and historical evidence, actual commit paths, history and snapshot paths are strict; only a foreign path that is pending-only, or committed by its own desk and still pending with its committed side attributable by its own non-PROME commits (WQ-517 A; WQ-448 re-scoped 2026-10-29), is advisory. Ancestry alone proves inclusion, not unchanged current artifacts. Relevant changes withhold current/publication certification while A remains historical.
