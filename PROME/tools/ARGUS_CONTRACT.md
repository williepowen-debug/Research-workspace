Schema 3 binds `contract.policy = {language: "argus-path-v1", source_sha256, rules}` inside the reviewed contract hash. The top-level perimeter mirror must agree exactly. Freeze parses and hashes one byte read; verification uses only the pinned rules. Missing, malformed, unsupported and schema-1/schema-2/unversioned manifests return CANNOT-EVALUATE / rc 2; no legacy operational verifier or no-contract freeze remains. Historical approvals stay historical; re-freeze produces FROZEN and requires an actual authorized review.

`argus_policy.py` is the one interpretation for ordered rules and paths. First match wins; unmatched is UNATTRIBUTED and protected. Patterns support literal paths, terminal `/**` subtrees with literal/whole-segment `*` prefixes, and exact-depth wildcards with optional final `*.<suffix>`. Literal tokens/suffixes use ASCII letters/digits/underscore/dot/hyphen; empty, `.`, `..`, `.git` segments and every other glob expression are rejected. `/**` requires at least one additional segment. Paths are case-sensitive, repository-relative, without normalization; Unicode/dotfiles/newlines match segment predicates normally. Invalid/undecodable inventory paths fail evaluation. Existing delivery safety is stricter: newline/CR/tab delivery paths are explicitly refused because index-info delivery is line-based.

The perimeter and root ignore/attributes controls are always guarded. A visible nested `.gitignore`/`.gitattributes` is guarded exactly when its parent has any protected descendant under the pinned policy (including unmatched paths and the control itself). Exact reversed-trie predicate partition and bounded automaton exploration replace probes/witness guessing. True means guard; false permits only the ordinary exclusion/attribution route; state-limit (100,000), invalid policy or evaluation error means CANNOT-EVALUATE, never exclusion. Standard/Heavy's actual ARGUS consumer preserves rc 2 for uncertainty; FROZEN or changed candidates block with rc 1. Light retains an advisory only when no receipt exists; an existing unevaluable receipt or a verifier crash returns rc 2 even at Light. This narrow consumer change enforces explicit uncertainty rather than treating invalid policy as permission.

No ownership/authorship authority is granted by classification. Existing commit attribution, foreign pending handling, evidence, moves, candidate delivery, and strict ignore-file treatment at committed/snapshot verification remain. A changed perimeter must be delivered, never observed-only or attributed away. Committed-only paths outside OWNED remain attributable to their own commits unless PROME evidence or a control guard forbids it. Pending foreign paths are recorded under `foreign_at_freeze` under the existing ownership/evidence conditions.

**Visibility boundary:** this analysis applies to controls the existing Git inventory exposes. Self-ignoring untracked `.gitignore`, `.git/info/exclude`, global excludes and index flags can conceal paths without an inventory entry. No general inventory redesign, concealment guarantee or monitor is introduced. Attributes are guarded as controls, not claimed to hide files like ignore rules.


Delivery includes all claimed changes since the recorded baseline, including earlier commits, pending edits, deletions and nested/shared paths. Evidence requires a persisted version; `historical` pins that version, while `current` additionally requires matching current/delivered bytes. Both roles may apply to a delivered file. A changed live version of historical evidence needs its own unrelated-version classification; the pinned claim remains unchanged. Uncommitted evidence actually needed by a claim remains a real blocker. Never commit another owner's work merely to clear it.
