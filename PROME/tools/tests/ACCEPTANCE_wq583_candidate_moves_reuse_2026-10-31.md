## Acceptance conditions (properties)
- **AC1 — fixed candidate, off the shared branch.** A schema-2 freeze writes an immutable commit object K (parent = HEAD at freeze) holding the delivered paths at their frozen bytes, referenced only by `refs/prome/argus-candidate` — never by `refs/heads/*`, so no desk's safe-push (which pushes master) can publish it. K's blob for every delivered path equals the contract digest, checked at freeze; a mismatch (a filter rewrote bytes, the file changed mid-freeze) refuses the freeze. The manifest records K; `validate()` re-checks K against the contract.
- **AC2 — post-freeze edits do not break the review.** With a candidate, the working-tree verify (`--mark-reviewed`, the closeout gate) checks delivered content AT K; a delivered path whose working bytes differ from K is listed `POST-FREEZE EDIT (not in the reviewed candidate …)` and does not block. Current-evidence, inventory, foreign and guarded-file checks are unchanged. The `--ref`/`--snapshot` forms stay strict.
- **AC3 — delivery ships exactly the reviewed bytes.** `--deliver-candidate -F <msg> [--carry <path> …]` creates ONE master commit N whose candidate paths equal K's blobs and whose other paths equal current HEAD (other desks' commits since the freeze are kept). It refuses: verdict not REVIEWED for this contract · HEAD not on master or K's parent not an ancestor of HEAD · any candidate path changed on master since the freeze · the shared index holding a version of a candidate path other than HEAD's or K's (another session staged it) · a post-freeze edit not named with `--carry` (so a forgotten ❌ fix cannot silently stay behind) · subject empty or over 100 characters. The master update is compare-and-swap (`update-ref <new> <old>`). After it, `--verify-review --ref N --paths <printed paths>` passes.
- **AC4 — byte-identical moves are mechanical.** A pair (origin O absent now and present at the baseline · destination D absent at the baseline · same basename · D's current bytes, and D's committed bytes if committed, equal O's baseline bytes · exactly one such pairing) is recorded under the contract's `mechanical_moves`, needs no delivered/observed entry, is accepted at every verify form while it still holds, and is allowed among a delivery commit's actual paths. Never mechanical: a byte difference, a renamed basename, an ambiguous pairing, the perimeter, any `.gitignore`/`.gitattributes`, a receipt path, a path the plan delivers explicitly. A pair that stops holding after the freeze falls back to strict handling. PROME's own PENDING moves (both legs in PROME's inbox tree) ride the candidate so they ship with the delivery.
- **AC5 — exact-version review reuse.** At a re-freeze on the same baseline after a REVIEWED manifest, each delivered path whose bytes equal the previously reviewed (or previously reused) version is recorded under the contract's `reused` with the prior contract digest. A plan may declare `reviewed: {path: {commit|sha256, receipt}}` for an earlier independent review; accepted only when the delivered bytes equal that exact version. A changed path is never reused. ARGUS's listing names reused paths and the changed portion; claims ABOUT a reused file in other files stay in scope.
- **AC6 — derived delivery list.** A plan with `"auto_delivered": true` derives the delivered set: every inventory path OWNED under the pinned perimeter, every path a `PROME`-subject window commit touched, and every PENDING SHARED-lane path with PROME filename evidence — minus mechanical legs and receipt paths. Provenance is written from the commit subjects (and "pending at freeze"). Explicit `delivered` entries add to or override it. Every other path keeps today's rules (commit attribution, foreign-at-freeze, observed, guarded files).
- **AC7 — no regression.** The four existing ARGUS test files pass; any test changed because of AC2's intended behaviour change is named in the completion note.
