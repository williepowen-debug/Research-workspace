**The defect in its own terms:** a decision with named choices reaches Will as Approve / Decline, so a tap cannot say WHICH choice; the Deck paraphrases nothing today but offers nothing either, and a queue row holding two decisions (WQ-302) can only be ruled as one.

## Acceptance conditions (properties)
- **AC1 — plain rows unchanged (ordinary):** a row whose `options` cell is empty (or whose sidecar has no such column) renders its `<article>` byte-identically to today's card; its tap payload is unchanged (`{wq, verdict, note, ts, build, consumed, source}`).
- **AC2 — options render verbatim with consequences:** a row with `options` renders ONE button per option in the owner's own label token, the option text and its consequence line as copied; no Approve/Decline on that card; `if_yes` / `if_no` are not rendered on an options card; `if_nothing` and the PROME rec stay; a Later button and a note per decision unit.
- **AC3 — exact terms at the tap:** a tap on option B stores `verdict="CHOICE"`, `decision_id`, `choice={label,text,consequence}` exactly as rendered, `options_shown=[{label,text}…]` equal to the rendered set, `build`, `note`, `ts`, `consumed=false`, `source`; a Later tap on a unit stores `choice=null` with the same `options_shown`.
- **AC4 — validation against the OFFERED set, never a letter grep:** the generator parses the owner artifact's option block registered in `options_source` (`<path>#<section number>`; shape = a markdown table whose first cell is `LABEL` or `LABEL: text`) into the offered set and FAILS THE BUILD (no file written) unless the Deck set equals the offered set label-for-label AND each Deck option text is a prefix of the offered text (after markdown-strip and whitespace collapse). The failure names the diff (offered-but-missing · deck-but-not-offered · text mismatch) and the WQ.
- **AC5 — fail closed on an unreadable shape (missing information):** a missing `options_source`, a file/section not found, or a section with no label-shaped table rows ⇒ NO options rendered for that unit, the card falls back to today's plain Approve/Decline/Later controls, and a build warning names the WQ and the reason. Never a letter match.
- **AC6 — separate decisions, independently recorded:** a row whose `options` cell holds N blocks (`UNIT: …;; UNIT: …`) renders ONE card with N decision units, each with its own `decision_id` (`<wq>.<UNIT>`), buttons, note and tapstate; the store snapshot keys on `decision_id` so a tap on one unit never changes the other's state.
- **AC7 — pickup contract:** `PROME/BOOT.md` step 3b says how a CHOICE tap is written into the queue (`tap via Decision Deck <ts>: CHOICE <decision_id> = <label> — <text as stored> <note>`), that pickup groups by `decision_id`, writes the STORED text never the queue's current text, and that a multi-unit row stays OPEN while any unit is unruled and names both states.
- **AC8 — selftest:** `decision_deck.py --selftest` on the live sources covers ≥1 options row and ≥1 plain row and validates every options row against its source; `tests/test_decision_deck_split.py` gains fixture tests for AC1 · AC2 · AC4 (three failure shapes) · AC5 · AC6; the runtime fixture (`decision_deck_runtime.cjs`) covers AC3 (a unit CHOICE tap and a unit LATER tap) and keeps the plain-tap assertion.
- **AC9 — reference page unaffected:** the reference view (Decided / In-flight / Docket) carries no store client and no `data-v` controls, as today; its Decided view shows a CHOICE ruling through the record text pickup writes (the stored label), nothing new rendered.
