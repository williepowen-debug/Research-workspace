## Acceptance conditions (properties)
- **AC1 — plain rows unchanged (ordinary):** a row whose `options` cell is empty (or whose sidecar has no such column) renders its `<article>` byte-identically to today's card; its tap payload is unchanged (`{wq, verdict, note, ts, build, consumed, source}`).
- **AC2 — options render verbatim with consequences:** a row with `options` renders ONE button per option in the owner's own label token, the option text and its consequence line as copied — **the consequence is the card row's own remaining cells, verbatim (checked at build, AC4); PROME's words appear only inside a marked `[PROME: …]` bracket** (amended after read 1 ❌2, 2026-10-09 13:1x ET); no Approve/Decline on that card; `if_yes` / `if_no` are not rendered on an options card; `if_nothing` and the PROME rec stay; a Later button and a note per decision unit.
- **AC3 — exact terms at the tap:** a tap on option B stores `verdict="CHOICE"`, `decision_id`, `choice={label,text,consequence}` exactly as rendered, `options_shown=[{label,text}…]` equal to the rendered set, `build`, `note`, `ts`, `consumed=false`, `source`; a Later tap on a unit stores `choice=null` with the same `options_shown`.
- **AC4 — validation against the OFFERED set, never a letter grep:** the generator parses the owner artifact's option block registered in `options_source` (`<path>#<section number>`; shape = a markdown table whose first cell is `LABEL` or `LABEL: text`) into the offered set and FAILS THE BUILD (no file written) unless the Deck set equals the offered set label-for-label AND each Deck option text is a prefix of the offered text (after markdown-strip and whitespace collapse). The failure names the diff (offered-but-missing · deck-but-not-offered · text mismatch · **consequence not a verbatim copy of the row's cells with `[PROME: …]` brackets removed**) and the WQ.
- **AC5 — fail closed on an unreadable shape (missing information):** a missing `options_source`, a file/section not found, or a section with no label-shaped table rows ⇒ NO options rendered for that unit; **that unit** falls back to plain Approve/Decline/Later controls — on a single-unit row that is today's plain card byte-for-byte; on a multi-unit row the unit keeps its own `<wq>.<UNIT>` id so the other unit's rule stays separate (amended after read 1 ❌4) — and a build warning names the WQ and the reason. A unit may also be DECLARED plain (`UNIT: PLAIN :: reason`) when its options are deliberately withheld, e.g. the owner card is stale. Never a letter match.
- **AC6 — separate decisions, independently recorded:** a row whose `options` cell holds N blocks (`UNIT: …;; UNIT: …`) renders ONE card with N decision units, each with its own `decision_id` (`<wq>.<UNIT>`), buttons, note and tapstate; the store snapshot keys on `decision_id` so a tap on one unit never changes the other's state.
- **AC7 — pickup contract:** `PROME/BOOT.md` step 3b carries ONE grouping rule (by `decision_id`, absent ⇒ the WQ) and says how a unit tap is written into the queue (`tap via Decision Deck <ts>: CHOICE <decision_id> = <label> — <text as stored> — <consequence as stored> <note>`; a unit's APPROVE/DECLINE/LATER the same way), that pickup writes the STORED text and consequence never the queue's current text, and that a multi-unit row stays OPEN while any unit is unruled and names both states (amended after read 1 ❌3/❌5).
- **AC8 — selftest:** `decision_deck.py --selftest` on the live sources covers ≥1 options row and ≥1 plain row and validates every options row against its source; `tests/test_decision_deck_split.py` gains fixture tests for AC1 · AC2 · AC4 (three failure shapes) · AC5 · AC6; the runtime fixture (`decision_deck_runtime.cjs`) covers AC3 (a unit CHOICE tap and a unit LATER tap) and keeps the plain-tap assertion.
- **AC9 — reference page unaffected:** the reference view (Decided / In-flight / Docket) carries no store client and no `data-v` controls, as today; its Decided view shows a CHOICE ruling through the record text pickup writes (the stored label), nothing new rendered.
