So a pending edit that inserts an EXCLUDED row above `PROME/**` turns OWNED arrivals — the perimeter file included — into `FOREIGN-PENDING (advisory)` with rc 0. The committed side has the same shape: `attributed_by_commit()` also re-reads the live perimeter at verify time, so a post-freeze perimeter edit can flip a committed-only path from "needs classification" to "attributed by its commits".

## Design (one change to one artifact, `PROME/tools/argus_contract.py`)
- `freeze()` records `manifest["perimeter"] = {"sha256": <sha256 of the perimeter file bytes>, "rules": [[pattern, class, reason], …]}` — the rules it actually loaded — OUTSIDE the contract (the contract digest keeps its shape, as `attributed_by_commit` does). No readable perimeter at the freeze ⇒ `{"sha256": null, "rules": null}` (strict, same as today's `attributed_by_commit` behaviour).
- `verify()` classifies with the PINNED rules, never the live file: `foreign_pending` and `attributed_by_commit` both take the pinned rules. A manifest without a `perimeter` key, or with `rules: null`, runs STRICT (no advisory branch, no commit attribution) — fail closed. A malformed pin (bad class, wrong shape, bad digest) is CANNOT-EVALUATE (rc 2), never a pass.
- `PROME/state/AUDIT_PERIMETER.tsv` itself is hard-coded never-advisory (belt and braces under the pinned `PROME/**` OWNED row).
- The advisory line names what was established: `FOREIGN-PENDING (advisory, owner UNVERIFIED — <class> lane, no PROME evidence): <path>` (prefix `FOREIGN-PENDING (advisory` unchanged so CLOSEOUT.md's quoted token still matches).
