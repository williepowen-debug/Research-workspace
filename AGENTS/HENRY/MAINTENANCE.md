### 2026-07-23 (~21:30 ET) — BUGFIX `gamma_flip.py`: NaN openInterest poisoned every output (the tool emitted confident garbage; now fails loud)
- **Trigger:** boot 7/23 section (b) printed `Net GEX +nanB/1% · regime POSITIVE · no flip in ±10% band · put wall 8,100 (above the call wall 6,360)` off **71 contracts** — vs 6,206 on 7/17. Nonsense on its face (put wall above call wall), and the standalone CLI printed **NEGATIVE** on the *same* run where boot printed **POSITIVE**.
- **Root cause — one bug explains all of it.** The filter read `oi = r["openInterest"] or 0`. **`x or 0` does NOT catch NaN — NaN is truthy**, and `NaN <= 0` is False, so NaN-OI contracts passed the guard (the *IV* filter caught NaN correctly by accident: `0.03 < NaN < 2.5` is False). One NaN OI → `gam * oi` = NaN → the whole GEX sum = NaN. Downstream, NaN silently took the wrong branch of every comparison: `regime` = `"NEGATIVE" if g0 < 0 else "POSITIVE"` → **POSITIVE**; the CLI's `"POSITIVE" if g0 > 0 else "NEGATIVE"` → **NEGATIVE** (the contradiction — same NaN, opposite labels); flip detection `(v1<0) != (v2<0)` → False≠False → never fires → "no flip in band"; walls `max(cg, key=cg.get)` over an all-NaN dict → NaN comparisons all False → returns an **arbitrary** strike. Every symptom, one root.
- **⚠️ CORRECTION (same session, Will asked me to retry the pull): my first root-cause for the THINNESS was WRONG.** I wrote "yfinance's IV feed is degraded — most rows carry NaN IV." **That was an assumption I never instrumented.** Counting the actual rejections: of **7,514** raw rows in the ≤35d window, **7,278 were dropped for `openInterest == 0`** — only 85 for NaN OI and 32 for out-of-band IV. **Volume and IV are fully populated** (542 of 561 contracts traded on the front expiry); it is the **`openInterest` field specifically that yfinance is returning as ZERO** across ~97% of the ^SPX chain (max OI of **3** on the 7/24 expiry; SPX monthlies should show hundreds of thousands). So: a **field-level provider outage on OI**, not an IV problem — and not something a retry fixes. **The NaN bug above is still real and still the cause of the *garbage output*; the thinness had a different cause than I claimed.** Lesson: I diagnosed a data problem by assumption and shipped it in a commit — instrument the rejection counts before naming a cause.
- **What changed:** (1) `_isnan()` helper + explicit NaN guard on strike/OI/IV. (2) `MIN_CONTRACTS = 400` **thin-chain guard** — returns an error rather than a reading when the usable set is too degraded to locate a flip. (3) NaN guard on `g0` itself. Fail-loud over fail-silent, per `[[finding_fail_loud_on_incomplete_data]]`.
- **Verified:** post-fix both surfaces now return `chain too thin: 98 usable contracts (< 400); yfinance IV/OI feed degraded — no gamma read this run`. No number emitted.
- **✅ RESOLVED SAME SESSION — CBOE wired in as the PRIMARY source; the gamma read is RECOVERED, not lost.** Since the outage is yfinance-field-specific, I went to the exchange: **CBOE's public delayed-quote chain** (`https://cdn.cboe.com/api/global/delayed_quotes/options/_SPX.json`) carries **real OI — 21,110 rows >0, ~21.7M contracts** — plus IV, at the same spot (7,408.2998). `compute_gamma_flip()` now takes `source="auto"` (**CBOE first, yfinance fallback**), returns `source` in its dict, and the CLI/boot print `src=`. **CBOE is exchange-primary for OI, so this is an upgrade, not a workaround** — yfinance was always a second-hand redistributor of this field.
- **📊 THE RECOVERED READ [7/23 EOD, src=cboe]:** **flip ~7,496** (35d, 6,909 contracts) / ~7,492 (14d) · **Net GEX −$45.2B/1% = NEGATIVE** · **SPX 7,408.30 is −88pts BELOW the flip** · call wall 7,500 · put wall 7,500 (35d) / 7,300 (14d). Flip stable across horizons (4pt spread) = sign and level both robust.
- **⚠️ Do NOT read the 7/17→7/23 flip delta (7,522→7,496) as a pure market move — it is CROSS-SOURCE** (yfinance then, CBOE now) and therefore confounded. What IS clean: today's sign and magnitude, from the better source.
- **🚫 Volume is NOT a substitute for OI (documented in the code).** GEX weights by the *stock* of outstanding contracts dealers must hedge; volume is one session's *flow*, heavily 0DTE churn. Weighting by volume yields a number shaped like a GEX that isn't one — the exact proxy-masquerade the 7/17 lesson warns about. Explicitly refused.
- **Meta-lessons (both logged to LESSONS):** (1) a *validated* tool (validated 7/17 vs 2 trackers) degraded into confident nonsense without erroring — **validation certifies a tool against good input, not its behavior on bad input**; (2) **I named a root cause from assumption and committed it** — the fix was one `Counter()` over the rejection reasons, and it overturned my diagnosis in one run.
