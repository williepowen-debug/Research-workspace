# WALTER process and check audit — October 31, 2026

**Result: there is useful work to remove, but the largest runtime costs are not the clearest retirement candidates.** The best first pass is to remove obsolete instructions and routine historical checks, reduce repeated bookkeeping, and repair two misleading diagnostics. No operational process, check, routing rule, approval or file has been retired by this audit.

Will requested a sweep for redundant, obsolete or superseded processes/checks. This is the diagnostic and concrete proposed pass under WALTER Rule 8; approval to audit is not treated as approval to retire the still-registered burst-window policy. Existing authorities continue to govern until the agreed changes land.

## Coverage and measured cost

Inventory: **4,324 tracked WALTER files**, including **4,102 paths classified as history/evidence** and **222 operational or candidate paths**. These classes describe locations, not judgments of present usefulness. Reviewed the active charter/process chain, tool inventory, candidate source implementations and call sites, current warnings, relevant owner rulings, tests supporting the proposed changes, and cross-desk references. Historical file bodies were searched where relevant, not all read whole. Gitignored intake/credentials and foreign owner edits were excluded from the inventory. There are **35 Python files under tools/: 19 non-test tools and 16 test modules**.

Ran all **38 registered doctor checks**, read-only, in canonical order in one process: **17.273 seconds**, producing **118 diagnostic records** (78 INFO, 37 LOW, 3 MED). This is one warm-working-tree observation, not a benchmark or defect-detection-rate study. Detailed dispositions: `CHECKS.tsv`; captured results/timing: `doctor-profile.json`.

Four delivery/consumption checks account for **14.251 seconds (~83%)**. They answer different questions: was a copy written but unpublished; does a claimed delivery agree with origin; was a delivered ACTION consumed; did a move actually declare consumption? **Keep those protections.** Mere shared access to the same ledger does not make their guarantees redundant. No cross-process caching or replacement framework is proposed.

The retired cron and TERRY checks together took **0.018 seconds**. Removing them primarily reduces obsolete instructions and noise, not runtime. `outbox_age` alone emitted **73 of 118 records**, including **35 LOW** warnings. Its 0.001-second runtime is cheap; repeated human review of completed artifacts is the cost.

## What looks redundant but should stay

- **BOARD counts versus generated content:** `board_reconcile` checks ToC/section totals; `index_generated_fresh` compares the source projection and actual sorted row content. One does not cover all of the other.
- **Delivery, consumption and the current closeout receipt:** the receipt checks a declared date cohort and commit/evidence claims; doctor also checks other historical/in-flight delivery paths and recipient declarations. Their scopes differ.
- **Intake detection versus threshold verification:** the lane supplies onsets and source health; the registered threshold scan supplies basis, calendar, persistence and owner-specific conditions. Removing one wholesale would lose coverage.
- **Input manifests versus signal counts:** input items can be killed, folded or noted. Counting BOARD files cannot prove input completeness.
- **Signal intake template and live cross-reference caches:** the template has external users. Only RED and REGINALD cache files currently exist; the generic dispatch instruction should say “where present,” not imply a missing cache is a mandatory build. REGINALD's live convergence references prevent wholesale archival. Its old header date does not erase its October 11 section refresh.
- **Existing test modules:** old filenames do not prove obsolete tests. Tests are not run by normal doctor boot. Retire tests only when their protected behavior is deliberately retired; preserve false-assurance, correction-identity, source-basis and input-preservation fixtures.

2. **Simplify and repair existing checks/processes:** F05, F08, F09 and F10. One implementation of each distinct guarantee; run static checks when their inputs change. Keep the delivery protections despite their cost.
3. **Explicit policy decision:** F02 burst-window retirement. My recommendation is retirement, retaining normal FLASH dispatch. No replacement window mechanism or new study proposed.
4. **Owner/backlink-dependent history:** F07 shared BASIS and F11 candidate archives. WALTER supplies precise changes; shared declarations remain with PROME, domain interfaces with their owners.
