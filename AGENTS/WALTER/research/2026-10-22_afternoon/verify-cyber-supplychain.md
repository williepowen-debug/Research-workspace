## Claim 2: "pip install is compromised"; upgrade pip to 26.2.2+ and uv to 0.13.4+

| Sub-claim | Grade | Evidence | Source (date) |
|---|---|---|---|
| pip/PyPI is "compromised" | FALSE as worded | Nothing was compromised at pip or PyPI. The issue is a trust-store problem: pip bundles certifi's CA list on top of the OS store, so old pip keeps trusting the weak-key intermediates even after the OS removes them | discuss.python.org thread, Seth Larson (PSF), 2026-10-20 |
| Upgrade pip 26.2.2+ and uv 0.13.4+ | CONFIRMED | Python.org announcement lists minimums: certifi 2026.10.19, pip 26.2.2, uv 0.13.4, sigstore 4.5.1, conda 26.9.4, pixi 0.82.1. Also says rebuild container images with layer cache off | discuss.python.org thread, 2026-10-20 |
| Official advisory exists | PARTLY CONFIRMED | Astral: GHSA-hq85-5cpj-mr62 "Removal of emSign root certificate", published 2026-10-20, severity High, affected uv below 0.13.4. PyPA/pip: no standalone pip GitHub advisory located; the official channel found is the Python.org (PSF) post and the pip 26.2.2 release | github.com/astral-sh/uv/security/advisories/GHSA-hq85-5cpj-mr62 |
| Risk is real (on-path attacker with a mis-issued cert could impersonate pypi.org / python.org) | CONFIRMED as a capability | Python.org post says failure to upgrade could expose TLS clients, including python.org and pypi.org, to MITM. Requires an on-path position and a forged chain (pypi.org-style leaf signed with a recovered key) | discuss.python.org, 2026-10-20 |
| Any attack reported | UNVERIFIED / none found | Python thread reports no exploitation. Same for Talos, Google, Cloudflare | as above |
| Gaps worth knowing | CONFIRMED | Official Docker python images reportedly ship pip 26.2.1 (not covered); venvs keep the certifi they were built with; pip 26.2.2 does not support Python below 3.10; Node.js fix pending as of 2026-10-21 per secondary sources; CPython issue 160040 proposes blocking the keys in the ssl module | discuss.python.org thread replies; Cloudflare blog; CoinDesk |
