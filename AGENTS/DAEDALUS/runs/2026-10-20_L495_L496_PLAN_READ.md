## Counterexample (my own)
Leg built to the letter for P1: lane emits canary WATCH_HIT item with reserved phrase `daedaluscanaryphrase`, registered to test owner "CANARYTEST". intake_scan (fixed version, post cc9c14017) emits rec with owners=["CANARYTEST"]. WALTER's 7e worklist prints the line, verdict PASS (key present, today's date). But routing at the consumer for real desks is keyed on owner -> desk worklist; a regression that drops items whose owner is a REAL desk (e.g. owner lookup/dispatch map keyed on live-desk list, or `owners` filter applied after "known desk" check) never touches CANARYTEST, which is routed through the "(unknown)/test owner" branch. The canary passes while every real-desk hit is dead at that desk's inbox. AC8 count reconciliation only catches it if records are counted before the owner filter. Fix: canary must exercise the same owner->desk dispatch path as a real desk (a designated test desk entry in the same map), asserted at the dispatch output, not only in the worklist.
Second: P3 on laptop - run-stamp gitignored; LIQUID boot returns UNKNOWN every laptop session, normalised, then ignored (AC4 fatigue) while a real stale arbiter continues.
