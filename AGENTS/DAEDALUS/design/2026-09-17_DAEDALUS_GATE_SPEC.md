## 1. What it is, and is not
- An ORCHESTRATOR. It invokes the checks the charter already names, each as a direct subprocess (no shell, no pipe), captures each child's **native rc** and log, maps rc → a **class** using that child's OWN documented contract, and writes a receipt. It adds two read-only checks of its own that no child covers (PATTERNS_HOT conservation; STATUS stamped today) and records two declarations (consumer-check scope; rule-declared-this-session).
- It does **not** commit, push, regenerate, rotate, or edit any file outside its receipt directory and `runs/GATE_LOG.tsv` (one appended row per real run). Commit and push stay separate, by hand, per root Git Protocol.
- A green aggregate is not its output. Its output is the per-step table plus a §2 perimeter line.

## 2. Classes (five, kept distinct — CATO's requirement)
| Class | Meaning | Moves rc? |
|---|---|---|
| `CLEAN` | child rc 0 with no separately reported obligation; read-cap requires a valid assessed result with rotation_due=0 | no |
| `DUE` | child reports OWED WORK (sweeps_due rc 1 = a sweep is due; read-cap rc 0 with rotation_due>0; orphan_check `[likely YOURS]`; ledger nudge rc 1; consumer_check 🔴 owners; memory-length rc 1/2 = flag PROME) | **no** — listed loudly; the closeout message must carry it |
| `ADVISORY` | child rc 1 whose contract says advisory (claim_check; read_cap at BOOT) | no |
| `BLOCKING` | child rc 1 whose contract means a defect the desk must fix before closing (corrections unreceipted; read_cap at CLOSEOUT; complete_check pairing/symmetry/placement; memory_index_check --strict; verify_push NOT-ON-ORIGIN; PATTERNS_HOT conservation broken) | rc → 1 |
| `UNKNOWN` | child rc 2, child missing/unrunnable/timeout, an UNDECLARED conditional, or a runner-internal read failure | rc → 2 (**dominates**, §9) |
| `NOT-APPLICABLE` | a conditional step skipped under an EXPLICIT declaration, reason printed | no |
| `ENUMERATED` / `DECLARED` | listings (inbox, git state) and operator declarations — recorded, not graded | no |

Overall rc: **2** if any UNKNOWN · else **1** if any BLOCKING · else **0**. DUE never lowers to "clean" and never raises to "fail"; it is the third thing.

## 4. Receipt
**October 9 reporting repair:** native child rc is retained. B4/C7 use the existing `--charter-mode explicit` option because the charter now requires explicit root/local reads, including while owner application of READS is pending. A successful read-cap child must emit exactly one final `READ-CAP-RESULT v1` line with mode=agent, desk=DAEDALUS, rc=0, assessed=1 and nonnegative integer rotation_due. Git fetch failure names its actual error and labels ahead/behind CACHED, preserving the foreign-dirty pull hold. `<receipt-dir>/<UTC-stamp>_<mode>.json` + `logs/<step>.txt`. Fields: mode · ts · HEAD · **fingerprint** (sha256 over HEAD + `git diff HEAD -- AGENTS/DAEDALUS scripts` + sorted untracked list under AGENTS/DAEDALUS + sha256 of the runner file) · steps[] {id, name, cmd, rc, class, reason, log, finding lines} · counts by class · perimeter line. `verify-receipt <path>` recomputes the fingerprint: `VALID` or `INVALIDATED (head|tree|runner changed)`. Default receipt-dir = the session scratchpad (`$CLAUDE_SCRATCHPAD` or `/tmp/claude-1000/daedalus-gate/`); receipts are NOT committed — the one-row `runs/GATE_LOG.tsv` append is the committed trace (date · mode · HEAD7 · rc · counts · receipt sha8).

## 7. Candidate v2 contract — settled before implementation, October 4

Authority: Will's explicit approval of `design/2026-10-04_CLOSEOUT_BOUNDARY_PROPOSAL.md`, including R1–R3. This additive interface replaces legacy assurances only when explicitly invoked. No new tool or ledger.

**Commands:** `closeout --candidate <scope.json> <usual declarations>` captures before/after around the existing registry; produces a version2 receipt. `candidate-verify <receipt> --review <review.json>` checks present working identity/results/review. Add `--commit <full object ID>` to compare the immutable commit before push; add `--delivery` after safe-push to fetch origin and check that exact commit's membership. Capture the commit ID from the commit output, never assume later HEAD is ours. Legacy `verify-receipt` remains identity-only (VALID may match failed checks); legacy `verify --subject`/`verify_push.sh` remain subject/tip heuristics for legacy runs, not v2 substitutes. v2 verification prints JSON dimensions and writes no tree/log file.

**Scope schema1 (JSON):** `schema:1`, nonempty `candidates:[{path, reason}]`, `dependencies:{C0: {paths:[], optional_paths:[], globs:[], context:[], completeness:"..."}, ... C10:...}`, `bookkeeping:[{path,reason}]`, `separate:[{path,reason}]`, `review_required:true|false`, `review_policy:"canonical source/reason"`. Exact normalized repository-relative paths; no wildcards in candidate/exclusion paths. Only runner-owned GATE_LOG may be excluded inside the repository in this version; generated receipts/logs stay outside the repository. Persisted receipt copies and review reports are separate delivery follow-ups or declared review evidence, never directory exclusions. A false bookkeeping reason is a review defect, not something a byte checker can judge. Candidate modes/bytes and tracked before-images are captured; absent tracked candidate means deletion; absent untracked candidate is UNKNOWN. Unsupported special files or directory symlink traversal are UNKNOWN. Symlink blobs bind link target; followed inputs require explicit dependencies. Candidate author declaration is not an authority grant.

Every actual registry step must have a dependency entry and a nonempty completeness statement; this is a human assertion subject to independent consumer review, not automatic discovery. Paths bind contents; optional paths bind explicit absence; globs bind exact membership plus contents. The running runner, scope source and normalized invocation (`no_superseded`, actual OLD/NEW pairs, `no_memory`, slugs, `rule_declared`, `complete_since`, and effective `ctx.today`) are automatically bound. Invocation identity is historical; receipt directory and later verification options do not alter it. Each context item has `kind` and `basis` (`current` or `historical`), plus a reason: `day` binds local date and timezone; `runtime` binds interpreter/version/platform/cwd plus hashes of PATH, LANG, LC_ALL, LC_TIME, TZ, PYTHONPATH and PYTHONHASHSEED (no general environment dump); `history` binds `git log --format=%H -- <paths>` with nonempty exact `paths`; `status` binds `git status --porcelain=v1 --untracked-files=all -- <paths>`. No arbitrary shell commands or environment dump. Used context unsupported by these forms must be declared in `limitations:[...]` on that step; it makes that step's input identity UNKNOWN. Historical context is compared during checks, retained at original time on reuse; it never establishes a present-state result. All file inputs remain current. No global HEAD invalidator; HEAD is provenance and candidate before-image only.

Before/after candidate, dependency and context snapshots must match; missing inputs remain UNKNOWN. Endpoint capture cannot detect change-and-revert. At verification current context is recaptured, historical context is explicitly reported as historical. Relevant own-directory dirty/untracked inventory must be candidates, GATE_LOG, or individually classified separate work; external authored paths are explicit declarations. This cannot discover an intended but never declared artifact. Changed-path comparison against the actual commit's sole parent rejects undeclared additions, omitted changes and different bytes/modes/tombstones. Unchanged included artifacts must match its tree. Unrelated commits may occur before/after ours; candidate before-images must still match the actual parent. Merge commits unsupported/UNKNOWN. Git-filter conversion is rejected by raw blob comparison. Review evidence may be added after candidate freeze as below; it cannot change the reviewed candidate.

**Receipt v2:** legacy result fields retained plus `version:2`, `candidate:{scope, scope_path, before, after, boundary_sha256, errors}`. Snapshots include candidates {before-image, final image}, per-step dependencies/context, runner hash and scope hash. Boundary digest binds scope + pre-check snapshot. Capture errors/during-check drift are permanent in that receipt and cannot be cleared by restoring bytes later. Recompute stored digest/shape at verification; missing/duplicate step IDs, unknown class values or absent result reasons are UNKNOWN. Receipts are evidence records, not authenticated signatures; deliberate forgery is outside the assurance.

**Review schema1:** `schema:1`, `boundary_sha256`, `status:ACCEPTED|QUALIFIED|EXEMPT`, `reviewer`, `policy`, `reports:[{path,sha256}]`, `limitations:[]`. Required review needs ACCEPTED, named reviewer and at least one report whose raw bytes match. QUALIFIED remains review-pending/UNKNOWN until a bounded follow-up accepts the final candidate. Exemption only if scope explicitly declares review not required, with policy/reason. The review statement is a human attestation; a verifier cannot establish that a reader read honestly or validate authority. Required report bytes and the review JSON itself must be present unchanged in an actual candidate commit (or its parent). They are finite evidence additions, never permitted to change candidate files. No report/self-hash recursion. Later corrections require new capture/review; later delivery-only addenda are separate commits with their own applicable checks/review and name the frozen earlier commit.

**Eligibility (fixed, not caller-configurable):** all BLOCKING rows remain blockers even alongside UNKNOWN. All missing boundary/review/input information withholds assurance. UNKNOWN results for C0 (cadence/profile maintenance) and C3 (ledger nudge) alone are disclosed maintenance limitations; all other UNKNOWN results withhold candidate eligibility. This never certifies C0/C3 clean, waives maintenance, or permits an actual BLOCKING row to be reclassified. DUE remains owed, ADVISORY remains advisory, DECLARED/NOT-APPLICABLE retain their reasons. `checks` reports every result, blocker and unknown; `eligibility` is separately CLEAN / WITH-DEBT / BLOCKING / UNKNOWN. rc2 if any required assurance is UNKNOWN; else rc1 if any BLOCKING; else rc0 (possibly WITH-DEBT). An rc0 is still not approval, consumer acceptance or whole-sweep completion. If a maintenance dependency itself is unreadable, its input assurance remains UNKNOWN; no blanket exemption for missing boundary evidence.

**Acceptance:** extend the existing `--selftest` with isolated repositories, no live owner systems. Cover all proposal cases (including CATO's three), malformed/legacy receipts, bad scope/review, commit parent/content/path/mode/deletion mismatches, history/context drift and fresh-origin membership/failure. Record commands, raw outputs, code hashes, independent patch/caller review and later author edits in the dated build record. No activation claim from fixtures alone.
