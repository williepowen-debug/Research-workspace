## Q5 — `standing_floor_bytes` field in READS.tsv vs a header line the instrument greps

**Recommend: a HEADER LINE in the surface itself, written by the owner.** Reasons, each checked:

1. **READS.tsv forbids it by design.** `PROME/registry/READS.tsv:65`: *"⛔ NO BYTE COLUMN, AND THAT IS DELIBERATE … A stored byte figure is a stale mirror within hours"* (also READ_CAP rule 13, :20). A floor is a stored byte figure, and Q6 shows it going stale.
2. **The field would not reach the named desks.** Only **9 readers** declare READS rows (BOND · BROCK · CREED · DAEDALUS · NEXUS · PROME · RED · WALTER · YURI; `awk` over READS.tsv). BRENT's own output says *"this desk has no declaration in PROME/registry/READS.tsv"*. A READS field misses BRENT, REGINALD, CARL, MARCO, LIQUID and TERRY, which is 6 of §5's 7 desks.
3. **Wrong key and wrong owner.** READS rows are keyed by READER (rule 15). A floor is the OWNER's classification of its own content (draft §4:44 says so). A cross-agent surface would carry N copies that can disagree. READS.tsv also lives in `PROME/registry/`, so a desk could not write its own floor without PROME. That breaks the root Git Protocol's own-directory boundary.
4. **Precedent and plumbing exist.** Rule 7 (:13): "a split file names its own" re-trigger. `_head_lines()`/`generated_banner()` already grep the head of the file (read_cap_check.py:584–598).

**The cost, and its control:** a header is exactly what rule 7 says decays. So the header form is acceptable **only with** the refutation leg (declared floor > current bytes ⇒ REFUTED) and the expiry leg (past `recheck` ⇒ EXPIRED, revert to `rotate-tier`). Suggested token: `READ-CAP-FLOOR: <n> B · measured <YYYY-MM-DD> · excluded <block list with bytes> · recheck <YYYY-MM-DD>`.
