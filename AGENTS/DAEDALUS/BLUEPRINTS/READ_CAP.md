# READ CAP — the fleet byte budget for boot-mandated reads (fleet build standard, P1)

**Owner:** DAEDALUS · **Ruled:** Will, in-session 2026-08-28, verbatim **"P1 approved go ahead"** — wiring-sweep proposal P1, evidence `runs/2026-08-28_WIRING_SWEEP/RUN_RECORD.md §4/§9` · **Instrument:** `scripts/read_cap_check.py --agent <NAME>` (shared; constants live there and nowhere else) · **Kin:** PAT-111 (a mandated read larger than the read instrument's cap silently degrades every boot to fragments) · PAT-086 (a line cap on a surface whose growth mode is bytes is aimed off-axis).

## The rule (STRICT — a wrong reading has a cost)

1. **Any surface a desk's boot protocol tells a session to READ WHOLE stays under the byte budget: 32,550 B** = 60% of the harness single-read cap (25,000 tokens × 2.17 B/token measured on fleet markdown ⇒ cap ≈ 54,250 B; 60% is headroom for the ratio's content-dependence and intra-session growth).
2. **The budget binds ABOVE any owner-set number.** An owner-declared budget may be tighter, never looser (TERRY's self-set 150,000 B was 2.8× the physical cap and passed its own check).
3. **Per surface, never a joint cap.** A joint STATUS+brief cap is not actionable by an owner whose brief is a NEXUS-schema surface (CARL pilot, 8/27).
4. **Owners choose HOW, never WHETHER.** Two remedies are confirmed on three seats (WATT · HENRY · CARL): **(a) two-state rotation** — verbatim, crc-stamped blocks to `archive/`, contiguous-only, never deletion (`STATUS_TWO_STATE_PILOT.md` carries the mechanism and the falsifier); **(b) hot/cold split** — a generated hot index over a cold register (`FLEET_DIRECTORY.md`/`FLEET_MAP.tsv`, `PATTERNS_HOT.md`/`PATTERNS.tsv`, `STATE_VOCABULARY.md`/`_PROVENANCE.md`).
5. **Rotation tiers:** start rotating at **≥75% of budget (24,412 B)**, stop **<70% (22,785 B)** — so a surface does not re-breach the same week (PAT-055 regrowth).
6. ⛔ **Never respond to a breach by raising the budget. The read cap is not ours to move.**
7. **A remedy leaves a DATED RE-TRIGGER, never a leanness claim** *(WALTER 2026-08-28 — `IRAN_WAR.md` line ~30 said "holds ONLY the current verified state" after a 6/28 split; the body regrew to 4.9× the cap underneath it over two months, and every reader had a written reason not to check)*. Write *"Split 2026-06-28; re-check size at any append or on 2026-09-28, whichever first"* — never *"this file holds only …"*. **The header did not become false by being wrong; it became false by being left.** A size remedy that runs once and boasts is worse than none, because it disarms the next check (`finding_header_edit_is_the_edit_most_mistaken_for_maintenance`). `read_cap_check` is the re-trigger for STATUS-class surfaces; a split file names its own.
8. **Rewriting the boot step from "Read X" to "read the header of X" is a PARTIAL fix, not a clean one** *(WALTER)*: the read becomes honest and the file drops off the whole-read list — but it is still over the cap for anyone who needs it whole. The instrument prints such files as `ℹ️ scoped read on an over-cap file` so the partial fix stays visible; the file's own owner still owes a split or a re-trigger under rule 7. **Which modes this rule governs (ruled 2026-09-01, DAEDALUS, off PROME's READS build — `PROME/registry/READS.tsv` `mode` column):** a `whole` or `scoped` read over budget ⇒ **remedy owed** (this rule); a `summary` or `grep` read over budget ⇒ **the cold/on-demand class of the table below — nothing owed on cap grounds** (PROME's v1 checker over-claimed against `DOCKET.tsv`, 219,609 B, read by a script that prints one advisory line — that file owes nothing). The `mode` is a claim about the SESSION's operation, not the file, so its `declared_by` provenance must be visible.
9. **Line counts are not a guard.** A line cap may stay as a style rule; it certifies nothing about readability (BOND 640 B/line · BRENT 905 · VULCAN KB 1,478).

10. **A COUNT-keyed retirement rule does not bound a BYTE-keyed surface** *(SHADE 2026-08-28 via PROME)*: "retire the oldest delta each closeout" was in force and obeyed, and the file breached anyway — each new delta arrived larger than the one retired. A byte remedy names bytes: per-section measurement before the cut (three of SHADE's "substantial" passes delivered 93–239 B each), and the session delta lives in `research/`, never in the state file.
11. **Verify a verbatim rotation by RECOMPUTING the crc, never by trusting the banner** *(SHADE 2026-08-28)*: a banner claiming `tail -n +8` over a 6-line header silently dropped the original's first line (STATUS short by exactly 15 B) and would have certified a corrupted archive. The recompute is one command; the banner is a claim.
12. **On an over-cap surface, the section that vanishes is whatever convention puts LAST** *(MIDAS KB-091 via PROME, 8/28 — 20/37 desks over the cap that morning)*: for STATUS files that is the Will-facing BOTTOM LINE. This is the argument for the budget, not for moving BOTTOM LINE — but a desk over budget should know which section its reader is not seeing.
13. **A read-cap census ages in hours on an active desk** *(PROME 8/28 P2 datum)*: HENRY's LESSONS measured 53,375 B in the packet, 54,248 B when HENRY read it — two bytes of headroom; three desks were one edit from the cap that day. `--agent` at every closeout is the instrument; a census is a snapshot.

14. **The declaration follows the boot VERB, and a desk's own `STATUS.md` is a `whole` read unless its boot step literally scopes it** *(ruled 2026-09-01, DAEDALUS, answering PROME 8/31d — 20 of 39 STATUS files over budget, BOND at 295% of the physical ceiling)*: root canon makes STATUS the universal boot read and the step says "Read STATUS.md" — that is `whole`, whatever a 160 KB file makes the session do in practice. Declaring `scoped` to match the behaviour the cap forced would launder the breach (`finding_loosening_a_check_to_kill_a_false_alarm_inverts_the_failure_direction`). A desk whose boot step genuinely reads "header + live tables" declares `scoped` **and still owes the remedy under rule 8**. Either way the 20 desks owe rotation or split — the 8/28 P1 packets already say so per desk; READS.tsv makes it visible from the reader side.
15. **A cross-agent mandated read is counted in the READER's perimeter — in full, every reader, every time — and a breach found there emits an OWNER-directed notice** *(Will-ruled 2026-08-31 in the WALTER window; the split is PROME's 8/31b recommendation, adopted)*: the cap protects the reading session's context, so the cost belongs where it is paid (three desks reading one file = three sessions paying — double-counting across desks is CORRECT); the remedy stays with the owner under rule 4, and an owner that never reads its own file (RED does not boot-read its trigger registry) learns of the breach only if the reader's check routes it. `READS.tsv` carries `reader` and `owner` as separate fields for exactly this. A verdict that cannot name the readers it counted is not a fleet verdict.

16. **A read is `scoped` only if the scope is ADDRESSABLE WITHOUT READING THE WHOLE — a named section, a marked block, a bounded head/tail, or a sorted/indexed region. A predicate over unindexed rows ("scan for items where X") is a WHOLE read with a scoped OUTPUT** *(ruled 2026-09-02, DAEDALUS, adjudicating NEXUS's `PREDICTIONS_MONITOR.md` as the non-interested party — WQ-163 item 1; the ruling goes AGAINST my own prior correction)*. Rule 14 said the declaration follows the boot VERB and left "literally scopes it" to the reader. **The verb is the wrong discriminator; addressability is the right one.** NEXUS's boot step says *"open `PREDICTIONS_MONITOR.md`, scan for items whose trigger date has passed"* — my instrument scored that `scoped` and silently dropped a 59,146 B file (109% of the physical cap) from the fleet report. But the triggers live in four unsorted tables and many are *conditions, not dates*, so the predicate cannot be satisfied from any bounded region: **the step scopes what the session MARKS, never what it READS.** ⚠️ **The correction that dropped it traded a loud false-positive for a silent false-negative** (`finding_loosening_a_check_to_kill_a_false_alarm_inverts_the_failure_direction`) — an over-count is visible, an omission is not — **and the original packet had already named the right disposition ("a whole-read claim on a file this size is the defect either way") before the correction discarded it.** Two errors, opposite directions, same file, net zero flags: `finding_a_correction_pass_is_unreviewed_work` in its sharper form — *the correction was right about the original's REASON and wrong about the FILE.* **Consequence for the instrument: a `scoped` classification must PRINT the line it scored on. A row that disappears has to leave a trace.** Consequence for R7 stage 2: a declared `mode` in `READS.tsv` is **validated against every other surface where that desk describes the same read, and a disagreement is a loud rc=1, never a silent exclusion** — the owner's declaration is exactly what was self-contradictory here (NEXUS's own charter says both "scan" and "Full at boot", the latter citing the former as its authority). *(Found by NEXUS from the desk side while blind to my packets — the blind-leg commission working as designed, on the one case where the instrument did not.)*

17. **A split CHOOSES which of two costs to pay, and must MEASURE the one it chose in the same commit that makes the split** *(MIDAS KB-MID-108 via PROME 2026-09-02, ZHAO KB-ZHAO-140; adopted as canon by DAEDALUS 9/2)*. The single question: **"where did the cut material go, and is that destination on the reading path?"** **On the path ⇒ the split cannot reduce reading cost** — measure the new boot-read TOTAL and stop claiming a saving (MIDAS: 37,528 → 67,247 B, +29,719, 0 stranded). **Off the path ⇒ enumerate every obligation that moved and re-home each one** (ZHAO: 78,588 → 66,749 B, −11,839, **1 stranded owed action**). Not lose-lose: the per-surface cap exists to stop SILENT truncation, so paying total bytes is a GOOD trade — **the defect is not knowing you paid.** **A split that reports only its win is a claim, not a fix.** ZHAO's rider: *a mostly-closed item reads as closed* — partial closure is evidence of attention, not of completion. ⚠️ **The off-path branch is the dangerous one and it compounds rule 4's freedom:** moving a container off the boot path makes any live obligation inside it *more* invisible, not less (`finding_live_claim_in_a_closed_container_is_invisible`) — first live application 9/2, NEXUS's ARCHIVED gate-adjudication blocks, which carry live cross-desk watches inside sections labelled archived.

## What binds and what does not

| Surface | Bound by this rule? |
|---|---|
| `STATUS.md` | **Yes, every desk** — root canon makes it the universal boot read |
| Any file a boot step says "Read …" whole (`THESIS.md`, `SCRATCH.md`, `MEMORY.md`, `CALENDAR.md`, a brief) | **Yes** |
| `CLAUDE.md` | **No** — auto-loaded into context, not a Read; large charters cost context, not truncation (watch, don't rotate on this rule) |
| `KB.tsv`, `LESSONS.md`, ledgers read by `grep`/scripts, archives, `*_HISTORY.tsv`, reader reports | **No** — cold/on-demand surfaces are the split WORKING; a large one is discovery, never a defect |
| A file ANOTHER desk's boot mandates (`AGENTS/RED/registry/FALSIFICATION_TRIGGERS.tsv` via WALTER 6b) | **Yes — in the READER's perimeter** (rule 15); the owner remedies |
| A desk with no STATUS by design (DEWEY, RAV) | **Cannot be measured by any STATUS-relative instrument** — it needs an `EXEMPT-BY-DESIGN` attestation row in READS.tsv so `UNKNOWN` is never read as exempt (ask to PROME, 9/1) |
| `memory/auto/MEMORY.md` | **No — a DIFFERENT cap** (25,600 B auto-load, `harness_caps.env`); do not conflate the two constants (`finding_instrument_reports_clean_against_the_wrong_reference`, n=9) |
| **A shared REFERENCE REGISTRY consulted at write time** (`BLUEPRINTS/STATE_VOCABULARY.md`, `STRICT_TEXT.md`, `CHECK_STANDARD.md`) | **No — on-demand consult class, same as a KB.** *Added 2026-09-02 after the owner (me) spent a session blocked on a budget that never bound the file.* Root canon and the desks that cite these say tokens *"come from"* them and *"check your ACTION lines against"* them — a **lookup**, not a boot Read; `read_cap_check --agent DAEDALUS` confirms the boot perimeter is STATUS · FLEET_DIRECTORY · PATTERNS_HOT · sweeps/REGISTRY.tsv and **not** STATE_VOCABULARY. ⚠️ **My own STATUS board carried *"hot half at 99.4% of budget — rotate first"* as a blocking precondition on three separate encodes.** The number was real (32,487 B) and measured against a budget that does not apply — `finding_instrument_reports_clean_against_the_wrong_reference` **n+1, on my own file, about my own rule, blocking my own work.** The hot/cold split (`_PROVENANCE.md`) is the mechanism WORKING; a large hot half here is discovery, never a defect. **Still owed under rule 7:** an on-demand registry names its own dated re-trigger instead of inheriting a cap — a leanness claim is what rule 7 forbids, and "not bound" must not become "not watched." |
