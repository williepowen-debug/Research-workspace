## 1. THESIS STRUCTURE (REGINALD / LIQUID / OTTO)

Decompose the thesis into **independent causal channels** — not correlated risk factors. State for each: mechanism, speed, and what would confirm/break *that channel alone*.

- **Channel/leg grid** (REGINALD): entity × channel exposure where relevant; mark multi-channel exposure as **non-linear** risk, not additive.
- **Failure-legs + migration** (LIQUID): if the thesis can reroute when one leg resolves, say so — list the legs as buffers and the migration path.
- **Transmission-stage table** (OTTO): for contagion theses, a stage-by-stage table (`stage | mechanism | current state: confirmed/open/falsified`). This is the live "where is it actually manifesting?" checklist.

## 2. CONVERGENCE MATRIX (BOND / NEXUS) — the cross-agent backbone

**Required handle: a universal 5-point score, ADDED alongside (never replacing) your richer local representation.** The 5-pt is the comparable handle that lets PROME/NEXUS stack agents and know *where to look*; your local labels (HENRY's CRACKING/RE-ARMED, VIOLET's 45-pt, LIQUID's DORMANT→TRIGGERED states) carry *what it means* and stay canonical. The 5-pt is a lossy triage projection of the rich state — that loss is acceptable *because* it routes attention back to the nuance, it doesn't substitute for it.

- **Keep your local scoring** at whatever granularity your domain needs. Do not flatten it.
- **Add a `Score (1–5)`** column mapping that local state onto the universal scale (5 🔴🔴 firing → 1 ⚪ dormant) — the shared interface.
- **Composite** as transparent arithmetic (BOND): e.g. `Total 42/70`. No hidden weighting.
- **Independence column** (NEXUS): note shared antecedents — two vectors on the same root count once. *(Conformance: the most-commonly-missing handle in pre-2026-06-27 agents — check it first when firming; tracked fleet-wide in `upgrades/HANDLE_SWEEP_independence-action.md`. N/A for genuinely single-channel agents.)*
- Required columns (interface minimum): `# | Vector | Score (1–5) | [your local state] | Independence | Key Signal | Upgrade Trigger`.

*HENRY's one real gap was having NO comparable handle at all — not having rich local labels. The fix is to ADD the 5-pt, not remove the labels.*

## 3. THRESHOLDS (HENRY / LIQUID / BOND)

*Reconciliation (BOND vs HENRY conflict): durable **rules** carry NO live values (anti-drift); the live **read** lives in STATUS with `[src M/D]` + as-of. Same metric, two surfaces — never one drifting copy.*

- **Durable banded rules** (HENRY), in CLAUDE.md / a stable doc: `Metric | Yellow | Orange | Red | Routes to →`. Routing is inline and addressee-specific.
- **Live banded read**, in STATUS: current value + as-of + which band + cushion. Sourced, dated, never naked.
- **Conjunction triggers** (LIQUID): compound `A AND B` where a single metric would knee-jerk. ⚠️ **A conjunction must be base-rated CONDITIONAL ON ITS OWN TRIGGER STATE — never unconditionally, and never leg-by-leg** (PAT-072, BRENT 2026-07-30). Legs that are healthy alone *and* healthy jointly on an average day can be jointly **impossible** in the only state that matters: BRENT's `{OVX <44.2 AND ratio <2.89}` opened on **50.4%** of sessions and on **0 of 38 escalation days in 753 sessions**, because a calm-state leg negates an escalation trigger (`corr = +0.483`). **The screen is free and needs no data** — write the trigger's semantic in one clause and each leg's in one clause; if any leg is the negation, precondition or calm-form of the trigger, the gate is a candidate. Generalized: *any metric measuring "the move hasn't happened yet" is 0% on days the move is happening.* Also check **joint improbability** (near-independent rare legs required in one window — BRENT's diesel falsifier = 0.6%) and **veto discrimination** (a leg that fires identically in the true and false worlds is decoration). **⚠️ And the cheapest test of the four — COUNT THE CONNECTIVES IN vs OUT.** A state machine that **arms disjunctively** (any 1 of N) and **disarms conjunctively** (all N benign) is a **ratchet**: `P(enter) ≫ P(exit)` for *any* legs whatsoever, correlated or not. That is arithmetic, not a base rate — no domain knowledge needed, and it is invisible to leg-level *and* joint testing because the defect lives in the **relationship between two gates**, not inside either clause. Symmetric, or conjunctive-in/disjunctive-out, is the conservative shape. **Registration requirement: a compound gate ships with `P(all legs | trigger state)` or an explicit "not base-rated" admission** — and with a **sessions-armed-and-unopened counter**, which is what catches this live rather than three years later (BRENT's was shut 11 of 11 post-arm sessions in real time). *Count the plain arm: a counter gated on "armed AND still relevant" is itself a compound gate and inherits the bug.* **Write the RATIONALE beside the conjunction.** From the condition alone, a deliberately-accepted asymmetry and an unnoticed one are byte-for-byte identical — so a one-line *why both legs* is what lets any reviewer (or screen) clear your gate instead of flagging it. Two agents cleared this way in the 7/30 screen on exactly one adjacent sentence each. Full design + fleet screen → `design/COMPOUND_GATE_AUDIT.md`.
- **Reference-discipline bundle (forum-4 N3, Will-ratified 2026-08-11 — ONE rule, four clauses; mirrored per the rulings-record from `FORUM/2026-08-10_positioning-exhaustion/04_synthesis/01_SAM_joint-synthesis-FINAL.md` §7):** any published comparison or reference claim carries **(a)** ≥2 alternative references [BRENT]; **(b)** extremum/percentile claims made on the SAME variable — else publish the comparator's percentile on that variable [MIDAS]; **(c)** a commensurability check on any live reference [ORACLE]; **(d)** the EPOCH scale variable AND sample start/end WITH the reason for the start [SAM]. Deliberately adopted as one rule — four separate rules would be the accumulation the forum's own rule 8 forbids. *(Companion at registration time: the N1 deadband mandate — distance-in-median-units, branch base rate, NO-VERDICT base rate, observed-support, leg-suppression — enforcement wiring = the `deadband_check` queue row, Will-gated.)*
- **Futures-bar / capture-time rule (forum-4 N5, Will-ratified 2026-08-11): WALTER owns the canonical five-clause text** — `SIG-W-20260811-002` **at v1.1 (2026-08-13, capture-time clause (i-b) adopted; corrects the reference-boundary error in the original 8/11 v1 — settlements struck at 14:30 ET, not at the 17:00/18:00 session ends)**. This blueprint carries a POINTER, not a mirror, by DAEDALUS disposition 8/12: one home per fleet rule, and the owner is a routing agent whose circulation already reached every desk. Orientation sentence only: *a futures bar is a QUOTE until something external says it is a SETTLEMENT — say which one you have, and stamp when you pulled it.* Not mechanically checkable (per WALTER's own limits note) — authorship discipline; no CHECKS row exists or should. **Version-pinning discipline (WALTER SIG-W-20260813-020 ASK, 2026-08-14):** the version above is what was current when this pointer was written; if WALTER version-bumps N5 again, this pointer moves in the same touch — a bare pointer silently resolves to whatever version exists at read time, which is right today and a failure mode tomorrow.
- **KILL_MEMO** (LIQUID): for any cascade trigger, a pre-written ladder file (durable, decoupled from STATUS rewrites).

## 4. INVALIDATION / EXIT (LIQUID / HENRY / BRENT)

- **Channel-kill vs thesis-kill** (LIQUID): distinguish a dead *channel* from a dead *thesis*; allow partial kills + state the migration path. Prevents false thesis-death.
- **Standing-rule-vs-state triad** (HENRY): live table — `leg | standing rule | current state @ level | FIRED / NOT-FIRED` + a literal fired-count.
- **Bidirectional "cleanest flip each way"** (BRENT): name the single thing that would falsify the thesis in BOTH directions, testable at the next data release.
- **Session counts mandatory**: "sustained" always carries an `N+ sessions` count. No vague thresholds; none already-breached at write time.
- 🔴 **A CONJUNCTIVE KILL FAILS SILENTLY — apply §3's satisfiability test hardest HERE** (PAT-072 §3). The same defect has opposite observability by gate direction: a broken **deploy** gate is loud (capital sits, someone eventually asks why nothing fired — which is exactly how BRENT's was caught), while a broken **kill / stand-down / retirement** gate raises no question at all, because *a kill that cannot fire is indistinguishable from a thesis that is still true.* Nobody complains about an alert that never stands down; it reads as vigilance. **Consequence: carrying a dead thesis as live — the failure this fleet exists to prevent.** So: every `AND` in a kill, stand-down, exit or retirement criterion states **which state it must fire FROM** and is base-rated in that state; multi-channel quiet-period conjunctions (`all N channels quiet for D days`) are the highest-risk shape and need at least one historical window that would have satisfied them. If none exists, **the thesis has no exit** — say so on the surface rather than leaving the criterion standing. **EXECUTABILITY IS A SEPARATE AUDIT AXIS from statistical validity (adopted 8/7 off BRENT's 8/2 self-audit, PROME-routed; n=3 incl. `finding_executability_is_a_separate_audit_axis`): ask separately whether the gate can be GRADED and ACTED ON inside the window where its instruments actually quote.** BRENT's premise audit cleared DEPLOY GATE v2 with a confident all-clear while silently modeling daily-close cadence — the gate had a ZERO-minute execution window (OVX final bar = USO options close) and no audit axis existed to see it. A pre-registration must name an instrument that trades in its grading window; a gate must name one that trades in its ACTION window.
- ★ **A DATED FALSIFICATION SURFACE IS A BUILD REQUIREMENT AND AN L3 REQUIREMENT** *(2026-08-07, off Falsification Sweep run #1 finding F5 — GRANDFATHERED, PAT-075 precedent: binds new builds immediately; existing agents get dated retrofit triggers, never a same-day demotion).* The kill rail must live on a surface the Falsification Freshness Sweep can DATE: either a standalone file (`workbook/EXIT_PROTOCOL.md` / kill-tree doc) or a STATUS/TRADE exit-rules section carrying an in-content stamp (`Kill rail re-derived: YYYY-MM-DD`). Exit-rule prose inside an undated section does NOT satisfy this. *(Corrected 8/7, same day, off the Production Review re-reads — the sweep's F5 headline "5 newest builds have NO falsification surface" was substantially a DETECTOR artifact: 4 of the 5 — WATT triad w/ a resolved MISS through it · OSPREY numbered kill routes, known-defective and correctly refusing self-repair · AEOLUS per-channel bidirectional flips w/ one already marked falsified · MIDAS in-thesis "What KILLS v2" block, exercised — HAVE live falsification discipline in local forms the scan could not NAME or DATE; only VULCAN was genuinely rail-less. "No datable surface" must never be read as "no falsification discipline.")* Consequence for the retrofit path: for existing agents the fix is **EXTRACT-AND-STAMP** — give the existing rail a dated, separately-addressable home — never author-from-scratch over a rail that already works. A new build without this surface is not L3-eligible.

### 6b. SEEDING A NEW AGENT FROM A PARENT (splits, promotions, spinouts) — three checks, all cheap, all learned the hard way

*Source: the 2026-07-12 HAWK→{OSPREY, FALCON} split, audited by FALCON 18 days on (`builds/OSPREY_FALCON_BUILD.md` §2c). Applies to any build that divides an existing agent's content.*

1. **Allocate MECHANISM rows by where the mechanism CAN FIRE — never by where its instances happened.** A pathway row's historical examples are *evidence*; the mechanism is the *asset*, and it is usually theater-agnostic. **Test, one question per row not migrated to a child: *"can this mechanism fire in that child's theater?"*** If yes, the child gets a copy — **duplicating a universal mechanism across two children is correct, not redundant.** *(Live cost of skipping it: the refinery-hit→product-channel sign went to the Russia sibling only; the Gulf sibling re-derived it from scratch six weeks later, mid-event, having meanwhile carried the default-bullish reading of a refinery strike.)*
2. **★ NAME-THE-UNREPRESENTABLE-SHOCK.** For each new agent ask: ***"name a shock in this domain that NONE of the seeded rows has a row-shape for."*** If the answer is not "none," **seed the row, or write the exclusion down and name who owns it.** Rationale, and it is the strongest thing in this section: **a file with no row-shape for a class of event is silent about it in a way indistinguishable from that event not happening** — so *"that belongs to another agent"* and *"I am blind to it"* **look identical from outside, and only one is safe.** No diligence *inside* the agent recovers this; **reproducibility does not test scope match.** *(Live cost: both war siblings were seeded oil-only while Russia and Qatar — the world's largest gas and LNG exporters — sit in their theaters. A registered kill-switch resolved FAILED against a fact that had been true since before it was written, and ran four months behind a "zero confirmed barrels offline" broadcast to four agents.)*
3. **Write the FILES table in ROLE tense, not STATE tense.** *"the strike ledger; its own `swept-complete through:` header is the vintage"* — **not** *"32 rows, thin, backfill owed."* **Discriminator: provenance statements are permanently true ("seeded from HAWK, IDs kept for continuity"); quantity statements decay silently as the file simply grows; pointer statements ("current: `ANALYSIS_2026-07-12.md`") decay *dangerously*, aiming a boot-read at a superseded artifact.** Nobody re-reads a FILES table to check it against the files, so a build-time descriptor reads as a live description forever. **Point at the resolution rule (newest-dated file, the artifact's own header), never at a value you would have to maintain.**

## 7. STANDING DISCIPLINES (MARCO / NEXUS)

- **Mechanism-vs-thermometer split** (MARCO): separate high-confidence *mechanism* from its confounded *readout*; the thesis survives a bad thermometer.
- **EXPECTED_SIGNALS** (MARCO): track signals that *should* appear if the thesis holds — their absence is data.
- **Three-column Δ discipline** (NEXUS): `metric · Δ signed pp · last-updated`; bump only on material change.
- **Boot↔Closeout symmetry**: what you read at boot, you write back at closeout.

## 8. BOTTOM LINE (required)

End STATUS.md with 2–4 plain-language sentences: domain state now, the single most important thing, what's next. Update every session. STATUS under 250 lines — archive overflow to `domain/sources/`. **BYTE TIER (fleet convention, Will-ratified 2026-08-17 — ruling record `AGENTS/DAEDALUS/inbox/processed/2026-08-17_from-PROME_WILL-RULING-status-byte-tier-RATIFIED-*.md`; PAT-086 at n=3 with measured evasion: MEMORY.md 8/12 · PROME STATUS 8/16 · SAM +59% bytes under a satisfied line cap + BRENT 812 B/line, both 8/17):** the line cap alone measures the one dimension that stops moving — every STATUS cap carries a **byte budget** beside it (owner sets it; default = ~128 B/line × the line cap), and at any closeout reading **≥75%** of the byte budget the agent rotates its oldest history blocks **verbatim, crc-verified, into a dated archive file until <70%** — rotation, never deletion (the MEMORY.md flow-rule form). Owners implement locally; existing agents encode-on-next-STATUS-cap-touch.
