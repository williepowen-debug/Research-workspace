## Characteristic analytic error (watch this first)
- **Single-mechanism over-attribution.** MARCO's recurring failure mode: crediting a multi-causal price/quantity move to one channel. Twice-burned: **produce CPI** (v2.1 — freeze + tomato tariff + diesel/freight co-drive; labor demoted to one co-driver) and **April construction starts** (broad + rate/affordability-confounded; the South — the raid-target region — fell *least*, geography running *against* the raid signal). **Before crediting a multi-causal move to one channel: run the multi-causal check, and separate mechanism-intact from threshold-breached** ([[finding_threshold_vs_mechanism]]). The produce-thermometer demotion is the template for every "is this really my channel?" call. *(The June-2026 LFPR-collapse temptation — "the labor-force contraction IS the immigration shock" — is the same trap: it's also aging + discouraged workers + degraded CPS response. Immigration is a named material co-driver, not sole.)*
- **Load-bearing figure with a mis-attributed authoritative source (the "2.2M CBO" lesson, v2.6 2026-07-02).** MARCO's *founding* Channel-1 magnitude — "2.2M self-deportations (CBO)" — was **wrong on both count and source** and propagated fleet-wide for months. It was a *disputed DHS* claim (CMS "Two Million Deportation Myth"), NOT CBO (CBO removals ≈290K+30K); realized was ~1.0M foreign-born LF / ~1.5M pop. The attribution to an authoritative body (CBO) is exactly what made it sticky and un-questioned. MARCO's own NOTES.md/MAINTENANCE T1-B had flagged the tension; it took a PROME Tier-2 workflow-verify to force the reconcile. **Lesson: a number's *source attribution* is as load-bearing as the number — verify "who actually said this" for any smoking-gun figure, especially one attributed to a neutral authority; a self-flagged data-quality tension is a debt, resolve it, don't carry it.** (General principle → [[finding_number_carries_threshold_unit_source]] / root CLAUDE.md "agent data can be hallucinated — PSEC PIK was 8.6% not 35%".)

- **Universal claims about MARCO's own metrics, written in prose, escape the rigor MARCO applies to its own tests (2026-07-25, session 18; general principle → [[finding_prose_claims_escape_test_rigor]]).** Same session, two standards: ES-MARCO-08 (pre-registered test) got a BLS-API primary pull, a series-label catch (carried "+6.1% fresh F&V" was actually `SAF113` aggregate, not `SAF1131`), and a result reported *against* the thesis — while the sentence *"every FL metric I own is improving"* shipped in the same summary without `VX.tsv` ever being opened. It was false: three improved, while migration level, voter-net (−0.8%), Canadian air stack, FL capacity, MIA pax, hospitality **wages** (VX-FL-01 CRITICAL) and the FL insurance **cost** index (VX-3.01 BREACHED, 4.5x national) were breached/negative/unrefreshed. **MARCO-specific traps this exposed: (a)** the FL table was built from CORAL's inbound packet, not from MARCO's ledger — an inbox is a *delta feed* skewed to whatever a neighbour refreshed; **(b)** boot printed `42/57 vectors >60d` *before* the claim was written and it was filed as housekeeping — stale is **UNKNOWN**, not benign, and the refreshed subset is the biased sample; **(c)** the insurer-side Citizens figure (improving, fresh print) was substituted for the household insurance-cost index (breached) — migration responds to the household number. **Guard: any *every/all/none/uniformly* over MARCO's own metrics = a ledger claim → one grep of `VX.tsv` before it ships, stale rows counted UNKNOWN.** Note this is the same family as the two errors above — collapsing a heterogeneous set into one clean read because the clean read makes the better paragraph.

- **MARCO promoted a Channel-1 instrument and retracted it the same session (2026-07-25, s18/18b; general principle → [[finding_run_the_falsifier_before_promoting]]).** After produce CPI failed ES-MARCO-08 in the morning, MARCO promoted **wage divergence** (FL L&H +8.75% YoY vs national +3.87%) to primary instrument at MED-HIGH — into THESIS v2.7, STATUS, NEXUS_BRIEF, and **packets to LABOR and CARL**. The promotion text correctly named the falsifier, the undecomposed co-drivers (FL minimum-wage schedule, general tightness) and the confirmation panel. **All were runnable that day off the free BLS API.** Run hours later: **TX L&H −6.45pp vs national and FALLING**, with the largest immigrant workforce exposure and no state minimum above $7.25 since 2009; CA −1.94pp; AZ −1.05pp; 2 of 8 cells positive. FL's cell = **Amendment 2** ($13→$14 Sep-30-2025→$15 Sep-30-2026 = 7.7% statutory floor rise inside the YoY window, most floor-exposed sector). The named co-driver ate the whole signal. **MARCO-specific consequences: (a)** Channel 1 now has **HIGH quantity evidence and NO working price/cost transmission instrument** — both candidates dead in one session; **(b)** the honest next step is a **floor-controlled** specification (OFLC **AEWR** is the untracked candidate; TX is the natural control and currently says *no*), and if that also comes back null MARCO should downgrade Channel 1 from spine to "well-evidenced upstream fact, unproven downstream" rather than hunt a third instrument; **(c)** this is the *third* instance of the characteristic error at the top of this file — committed on the way **IN** to a new instrument, which the v2.7 text explicitly warned against and then did anyway. **Rule: run a runnable falsifier BEFORE promoting, not after.**

- **BASELINE/BASIS errors are now MARCO's most productive failure mode — five in one session (2026-07-31), each of which would have shipped a confident wrong mark.** This is a *sibling* of the single-mechanism error at the top of this file, not the same thing: there the fault is attributing a real move to one cause; here the number is correct and the **comparison** is wrong. The five:
  1. **Detection floor** — FL's +4.88pp wage gap sat *below* the ~6pp cross-state dispersion of the series it came from. Fresh, correctly pulled, and still not evidence.
  2. **Category filter** — a Google Trends pull of `'florida vacation'`/all-categories returned **+36.2%** vs 2024; the founding series is `'florida'` filtered to **Travel (cat 67)**, which returns **−43.8%**. *Sign reversed.*
  3. **Cross-month seasonality** — FL-03's CRITICAL rested on "+41% vs **Mar** 2024"; March is peak selling season and June is slow, manufacturing ~30pp out of nothing.
  4. **Median vs repeat-value index** — TX-02 carried a median SALE price; ZHVI is mix-controlled. Levels not comparable, only direction/duration.
  5. **Similar-name, different quantity** — CA FAIR Plan *exposure* ($768B) is not a *coverage gap*; substituting it would have falsely tripped a >$500B BREACH. Identical to the FL trap already on the books (household insurance **cost** vs Citizens **insurer-side exposure**, which moved *opposite* ways).
  **Guard: before re-marking any vector, state the baseline explicitly — which month, which category, which index, which quantity — and check it reproduces a carried figure.** In every one of the five the tell was available for free: the old baseline CSV header, a same-month series, the row's own threshold wording. **A staleness check cannot see any of this**, which is why refreshing a stale row is a *research* task, not a clerical one.
- **MARCO's own ledger has twice held the right answer while its narrative asserted the wrong one.** (a) Session 18: the FL table was built from CORAL's inbound packet without opening `VX.tsv`. (b) 2026-07-31: **`VX-2.04` carried CBO's correct figure (−290K to −525K) for six months while `VX-2.02` and the thesis spine asserted "2.2M, CBO"** — one row away, in the same file. **A load-bearing correction must sweep the VECTOR LEDGER, not just the narrative surfaces**; and when a figure feels authoritative, grep your own workbook before trusting the prose.

## Source-quality map (MARCO-specific; general principle → [[feedback_pull_live_primary_not_dashboard]])
- **Pull primary before transcribing any load-bearing figure.** Search snippets / trade-press garble exactly the decimals that drive canonical text + confidence changes. Session-14 alone: StatCan air mis-read as "+3.0%" (real −5.5%); F&V "+6.1%" looked identical across Apr/May (verify same series, not same number); housing regionals returned 3 conflicting reads from snippets; a CalculatedRisk slug was April **2025** not 2026. Canonical sources: **BLS / Census (NRC primary XLS) / StatCan Daily / Banxico / OFLC**.
- **Known garbled / blocked sources:**
  - *Banxico English trade-press* — garbles remittance prints (e.g. the "$5.69B/+26% Apr" claim). Use Banxico primary + watch count YoY as the clean SDL-01 readout.
  - *FLL airport pax* — **SOLVED 6/15 (was "PDF-blocked").** The Broward Aviation Monthly Statistical Summary IS a text-based PDF — `curl` it with a **browser User-Agent** (`-A "Mozilla/5.0"`, plain curl 404s/redirects to a Custom404 page) from `broward.org/Airport/Business/about/Documents/FLLstats_<month><year>.pdf` (filenames inconsistent — scrape the live hrefs off `…/Pages/Statistics.aspx`), then **pdfminer** it. WebFetch/WebSearch fail; download+pdfminer succeeds. Layout: TOTAL/DOMESTIC/INTERNATIONAL sections, APR row = [25v26%, 2026, 24v25%, 2025, 23v24%, 2024]; always compute the 2-yr stack vs 2024 (YoY is base-effect). **General lesson: for gov/airport PDFs, "non-extractable via WebFetch" ≠ non-extractable — try download+pdfminer with a browser UA before calling it blocked.**
  - *MCO airport pax* — STILL blocked: flymco/GOAA traffic-stats page is JS-rendered with no downloadable PDF. Defer to **BTS T-100** (airport-level pax, ~3mo lag → April lands ~July).
  - *CalculatedRisk / undated housing slugs* — check the YEAR in the URL (April-2025 vs -2026 collision).
  - *BLS WebFetch* — 403s on cpi.htm/pdf; use the cpi.nr0.htm summary via WebSearch + a secondary (Fox/Kiplinger) for table detail, and flag the fresh-F&V-vs-aggregate line as unconfirmed until the primary table is read.

- **Working data routes verified 2026-07-31 (all free, no keys):**
  - **DOL OFLC H-2A** — dol.gov sits behind Akamai but passes a **COMPLETE browser header set**; a User-Agent alone gets 403. Discover the filename from the live performance page — DOL publishes ONE cumulative FY-to-date file whose quarter suffix advances (`FY2026_Q2` → `Q3`) and the superseded name stops resolving, so any hardcoded list rots every quarter. → `tools/h2a_pull.py`.

  - **CA FAIR Plan** — `cfpnet.com/key-statistics-data/` carries dated PIF + exposure; WebFetch works.
