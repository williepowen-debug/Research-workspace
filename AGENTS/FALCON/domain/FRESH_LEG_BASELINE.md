## Notes on sourcing quality this session

- **PortWatch (leg 2) could not be scraped live** — `portwatch.imf.org` is an ArcGIS Hub SPA; `curl`/WebFetch return the JS shell, not the dataset. The 7/5 figure (34/88, 39%) is the most recent number surfaced via search-engine snippets citing the same page. **Recommend**: if FALCON wants a scriptable daily pull (baghdad_watch.py-style), the underlying ArcGIS **FeatureServer** endpoint would need to be identified via browser devtools — not done this session, flagged as a build candidate, not attempted blind.
- **Do not cite casualty-tracker aggregator sites** (`militaryspend.org`, `iranwarlive.com`, `factually.co`, `openthemagazine.com`'s "casualties rise to 200" headline) surfaced this session — these returned internally-contradictory output (one claimed the US-Iran war "is halted" under the June MOU, which is false as of today) and read as unreliable/possibly LLM-generated aggregators. Admiralty F6, do not propagate specific casualty tallies from them. The one verifiable data point: Qatar MOD said Al Udeid was hit 7/12 with **no casualties** (per trade-press pickup); IRGC's claimed destruction of Al Udeid's maintenance/command center is **UNVERIFIED** (no independent US/Qatari confirmation as of this session).
- **Two Hormuz-transit trackers give different baselines** (IMF PortWatch: 88/day pre-war; Hormuz Strait Monitor private tracker: 97/day pre-war, 32.1/day current) — flagged in row 2 so a future session doesn't accidentally blend them into one series.
