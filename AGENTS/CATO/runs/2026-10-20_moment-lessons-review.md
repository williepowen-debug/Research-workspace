## Decision-relevant assessment

- **Useful idea, weak first test.** Phase1 requires manual lookup at each moment; forgetting the lookup can reproduce the failure it is meant to address. Phase2 attaches reminders to tools, but a status claim made without running the tool still bypasses them. Commit/boot are observable tool events; relay/status-report/number-in-brief can happen entirely in prose. The proposal lacks a demonstrated means of reaching those moments. A week of manual use does not establish automatic cue delivery.
- **The withdrawal overstates the alternative.** An advisory is not enforcement, but this does not prove it has no value. Judgment-heavy tasks such as claim qualification and contradictory evidence cannot all be reduced to deterministic checks. Conversely, an optional five-line publication command cannot fix a skipped-check failure "for good." Existing safe-push fetches and checks remote ancestry, and the root protocol already requires evidence. Determine whether the failure is unavailable evidence, failure to invoke an existing operation, or misreading its output before adding code. A named-commit question must keep its exact identity and UNKNOWN on unavailable evidence.
- **Ranking can omit supposedly mandatory lessons.** The proposal defines H as "must surface" but caps output at3. check-change has4 H entries (rows6–9); number-in-brief has4 (rows11–14). Ranking by citation count can repeatedly exclude one. Citation count is not evidence of relevance to the particular action or lesson currency. Broad keys such as trade-card also span several distinct actions. This is a concrete design inconsistency, not a request for a more elaborate ranking system.
- **The adoption test is too permissive.** One documented correction is evidence of possible usefulness, not enough by itself to justify permanent integration. Distinguish an observed draft/action changed after a cue from retrospective "would have caught it." Any later trial should consider relevance, interruptions, effort and misses alongside a useful catch, using a few existing work examples rather than a new telemetry project. No need for a statistically powered study.
- **Scope and research claims need restraint.** Editing20 files is not the same as maintaining585 tags; expansion is a possible future cost, not a necessary phase1 expense. Conversely, the memory summary's references and analogy do not establish this design works in this runtime. The novelty and "research is clear" claims remain unverified here and are unnecessary to decide whether to try a small idea. Do not carry historical expiry preferences without the current no-nag rule; the proposal explicitly intends the October20 amendment, which must remain controlling.
