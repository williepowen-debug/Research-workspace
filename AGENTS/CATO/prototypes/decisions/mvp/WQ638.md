# Option A owner contract

**WQ-641 return:** installation may use the authorized fallback below. This section supersedes the earlier probe/install assumptions. App-only authority is OFF unless acceptance explicitly sets `app_only_enabled: true` and an actual timezone-aware `app_only_since` after proven live alerts. Absent/false/invalid settings mean matching chat on EVERY answer, in the UI, intake and preparation. Answers saved before that activation time cannot be upgraded retroactively. Do not install notification hooks in the fallback deployment.

New integration preparation fetches published state and requires a prior published received receipt for both chat and app-only rulings. App-only preparation additionally checks the current exact row/source and latest answer. Historical replay intentionally does not compare against today’s source or today’s enablement; valid older rulings remain valid. Legacy `/1` receipt history is retained. New `/2` replay requires a preceding received receipt.

A bad card source is isolated to that card; unidentifiable response/receipt corruption still stops the desk for reconciliation. Connection status is refreshed independently of transient operation messages. SessionStart claims a new watcher before waiting for the old lock; the former session cannot refresh or end the new lease. Headless input exits without starting a long-lived watcher. These mechanics are fixture-tested, not proof of live PROME notification.


WQ-638 A authorizes app answers for explicitly classified reversible internal decisions. Unknown scopes, trades, spending, external sends, held positions, security and destructive work still require matching chat confirmation. The app cannot authenticate Will separately from other programs under his login. PROME's condition/scope/conflict judgment and same-day readback remain human-in-the-loop owner obligations, not guarantees made by a parser.

## Source authoring

Use the existing `decisions-options` source and exact row hash. Change `schema_version` to `decisions-options/2` and add:

```json
"recommended_choice_id": "A",
"confirmation": {
  "mode": "app",
  "scope": "reversible_internal",
  "reason": "Only reversible internal work; no money or external action."
}
```

The recommended ID must be an existing choice or `null` for no recommendation. For protected/uncertain work use `mode: chat` with scope `trade`, `spending`, `external_send`, `held_position`, `security`, `destructive` or `other`. Legacy sources remain chat-required. No retrospective reclassification. A changed policy, recommendation, brief or queue row invalidates a pending answer. Adding conditions does not silently widen eligibility: PROME must inspect their meaning. New card authoring/backfill and loosening the row binding are WQ-639, outside this build.

Approve selects the explicit recommended choice and keeps the conditions exactly. Disapprove is a text rejection of that recommendation, with no alternative selected. Review and explicit Send remain; only Send may publish response files.

## Receive, rule, read back

`owner_receipt.py intake --write` prepares received receipts only after checking the published event/packet pair. Commit these via PROME's normal exact-path custody. This is acknowledgment, not a ruling. Read each answer, check chat for a different answer, and inspect all conditions. If conflict or scope uncertainty exists, ask Will; do not integrate. Chat-required cards keep the existing matching confirmation procedure.

For an app-eligible answer, read its exact answer/conditions back to Will that same day. `pending`/`intake` returns `readback_text`. Publish a normal `-RULED.md` with this additional fenced `decisions-app-authorization` JSON block:

```json
{
  "schema_version": "decisions-app-authorization/1",
  "response_id": "EXACT_EVENT_ID",
  "response_sha256": "EXACT_EVENT_SHA256",
  "scope": "reversible_internal",
  "conditions_within_scope": true,
  "no_chat_conflict": true,
  "readback_at": "ACTUAL_TIME_WITH_TIMEZONE",
  "readback_text": "EXACT_INTAKE_READBACK_TEXT"
}
```

These fields attest actual owner work; never manufacture them from the button alone. Then use `owner_receipt.py prepare --help` and its existing ruling arguments with `--app-only` instead of a chat confirmation. Receipt `/2` names app authority; `/1` remains unchanged. No script executes the ruling. Will can undo by naming the decision; PROME records the correction, preserving prior history.

## Live notification

Install the accompanying hook entries in PROME's `.claude/settings.json`, preserving every existing hook. Only this local Claude runtime is supported. Entries use the documented `asyncRewake` exit-2 wake mechanism (Claude Code 2.1.319 inspected; https://code.claude.com/docs/en/hooks). A single process-owned watcher checks a local SQLite queue every five seconds; it has a 12-hour maximum lifetime and never launches an agent, guesses a socket protocol, writes owner receipts or retries publication. PostToolUse and Stop rearm it after a notification. SessionEnd marks that registered session ended. Restart/resume PROME to load changed settings; existing sessions may require reload.

The app enqueues only a verified published pair. Its display reconciles delivered/unread answers idempotently, recovering an interruption between publication and notification. The alert contains fixed packet paths and hashes, never operator prose as instructions. Emission is attempted once per session; actual receipt is separate. An absent/stale/failed listener is UNKNOWN, an explicitly ended registered session is OFFLINE. Neither status guesses whether another PROME runtime exists. A connected listener normally alerts within seconds; no timing promise is made while disconnected, runtime-paused or at teardown. An alert never asserts that PROME has read or ruled.

Install requires WQ-638's one independent read without blockers, exact candidate hashes, published review and acceptance with `confirmation_policy: explicit-reversible-internal/1`. Retain `matching_chat_confirmation: true` as the fallback contract. Live owner acceptance/settings are not overwritten by this candidate.
