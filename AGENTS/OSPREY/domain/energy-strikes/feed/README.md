# Strike-feed output — two files per run, one ephemeral and one committed

**`FEED_CANDIDATES_YYYY-MM-DD.tsv`** — every kept candidate. **Git-ignored** (`AGENTS/OSPREY/.gitignore`): a working file, not the record.

**`MATCHES_YYYY-MM-DD.tsv`** — **COMMITTED** (added 2026-09-10; ⚠ silently git-ignored 2026-09-15 → 2026-10-08 by a `.gitignore` line, re-committed 10/8). One row per candidate the diff absorbed into an existing `strike_id`, with the tokens that carried the match and the matched row's facility. *Why it exists:* `FEED_CANDIDATES` is ignored, so before this file the **precision** side of the feed was unfalsifiable after the run — a false `<strike_id>` produces no `NONE` row, no KB mention and no artifact, so a recall-only acceptance test cannot see it (DAEDALUS review 2026-09-10, finding (b)).

## Reading a file

| Value in `ledger_match` | What it means |
|---|---|
| `NONE` | No ledger row within ±1 day sharing a **proper-noun, df<4** facility/vessel token → row it, or dismiss it with a reason in the note column. |
| `<strike_id>` | **A CLAIM, not a fact.** The `note` column names the tokens that carried the match and the ledger row's facility — **confirm that facility is the one in the headline before dismissing the row.** Post-patch residual false-absorption is 2/99 (2.0%) on the hold-one-out, not 0. |
| `BULLETIN — read manually` | The latest-dated bulletin (Palaemon, client-rendered), its window END inside the run's `days_back` window, and no doubt link (see `BULLETIN_NEWEST_UNSURE`): nothing is listed above any of its listings, every other link is dated, no dated link's FIRST listing below it is followed by a later-ending dated link (first listings only; L661 read 1 ⚠️1), and no title/slug disagreement of more than 180 days could change the row → open the URL first, before any name query (LESSONS 8). The `note` gives the window, its basis (title, slug, or a single slug date), its position in document order, how many times it is listed if more than once, and, if the body was under 1,500 chars, `[body not machine-readable …]`. `pub_date` = the window END; on a single-date basis the note says the END is unknown and the date may be the window START. |
| `BULLETIN_STALE` | The latest-dated bulletin ends before the cutoff (`run − days_back`). At the default `days_back` (≥ 10) this means the publisher stopped or the index is cached. Below 10, the label says that an on-time bulletin can read STALE at that window. On a single-date basis (no window parsed) the label says the date may be the window START, so an on-time bulletin can read STALE up to ~7 days early (the live index carries 8-day windows). **Counted in NOT_READ** (stale ≠ quiet; L624). |
| `BULLETIN_NEWEST_UNSURE` | One or more **doubt links**: a matching link that could be newer than the followed bulletin, or the followed bulletin's own date is in doubt. A link is a doubt link when it (a) is listed ABOVE any listing of the followed link (the live index is newest-first; a featured duplicate keeps its lower list position, L661); (b) has no usable date (unparseable, or a FUTURE start); (c) is first-listed below every listing of the followed link with a window END EARLIER than a dated link first-listed below it — out of date order (L661; FIRST listings only — a repeat listing does not count); (d) has a title window and a slug date more than 180 days apart, when that could change the row — on the followed link itself, or on a link whose slug date would be newer (L661); or (e) is the followed link and its anchor TITLE carries month text (a full or 3-letter month word, "Sept" included) outside the window that governs it, or carries month text and no window at all (L661 AC27, 2026-10-21, read 2 ❌1: a yearless, abbreviated or teaser-placed own window is invisible to the window patterns, so a later "next report" window could otherwise govern). (e) only adds a doubt. **Louder cost (read 3 ⚠️3, pinned):** any month word in a non-date phrase fires it, e.g. "September update | …", "(may be revised)", "Mar Gold incident", so a fresh, correctly dated bulletin reads UNSURE. If a publisher habitually puts a month in titles, every run goes UNSURE; fix the cause, never train yourself to skip the label. The `note` names each link and its reason; the followed link, if named, is marked `FOLLOWED LINK`. On a newest-first index (the live layout, verified on the 10/9 and 10/16 fixtures), a date defect on the real newest (past-year typo, title year typo, format drift such as "Oct" or "Week 41") lands here. ⚠️ **Not guaranteed — known silent cases include** (the list is not exhaustive): (i) a date-typo'd real newest listed below the followed link, with title and slug agreeing, when no dated link FIRST-listed below it ends later (e.g. LAST on the page); (ii) an under-dated typo that still fits the page's date order; (iii) a title/slug disagreement of 180 days or less (resolved to the title); (iv) every dated link below the typo'd newest is a REPEAT listing of a link above it (CX-E, pinned); (v) a forward-typo'd OLD link (title = slug, start ≤ run date) pinned on top becomes the followed bulletin and masks a stopped publisher (CX-D2, pre-existing); (vi) **a later window governs when the title's OWN date carries no recognisable month word** — absent (CX2-13: only a later window), misspelled ("Septmber"), numeric ("21.09 - 27.09"), glued ("27thSeptember", "Sept26"), non-English ("septembre") or a week number ("Week 39") — and a later window follows in the same anchor text; the stale bulletin then reads fresh (CX2-13 and the "Septmber" case pinned as DECLARED LIMITS; read 3 ⚠️1). Trigger is compound: teaser/clause text inside the matching anchor (0 of 28 live anchors on the 10/9 and 10/16 fixtures) AND an unrecognisable own month. The released code read STALE on these, so this is a narrowed fail-open, not a closed class. Louder, not silent: a number directly before a two-year window ("Issue 22 - 29th December 2026 - …") forms a one-year fragment that starts first ⇒ a false STALE or an unparsed title (AC28). Declared limits: `scripts/tests/ACCEPTANCE_L661_strike_feed_read3_residue.md` "Not in scope" (DOCKET L661, 2026-10-16). If the followed bulletin is also stale, the label says `BULLETIN_STALE` inside it. **Counted in NOT_READ** (L624 pass 2, read-2 ❌8; L661). |
| `BULLETIN_UNDATED` | No usable bulletin date (unparseable, or only future-dated typos) — freshness unknown. **Counted in NOT_READ** (L624). |
| `UNDATED` | No parseable publication date (non-bulletin rows) — never matches; safe direction. |

| Row in `title` | What it means |
|---|---|
| `FETCH_FAILED` | The source was **NOT read** this run — an absent feed must look different from a quiet one. |
| `EMPTY_FEED` | HTTP 200, zero items. Applies to **every** source kind since 2026-09-10 (it was RSS-only, so a dead HTML scraper was indistinguishable from a quiet week). |
| `PARSER_STALE` | Fewer items than the source's `expect_min_items` — the parser, not the source, is the likely cause. |

## Diff rule (v2, 2026-09-10)

Ledger tokens are **proper-noun tokens of the raw Facility+Region cell** (capitalisation read *before* lower-casing), minus any token carried by **≥4 ledger rows** — a token four facilities share is a category, not an identity, and the df test is self-maintaining as the ledger grows where a hand-extended stoplist is not. Measured hold-one-out on this ledger: **v1 15/99 (15.2%) false absorption → v2 2/99 (2.0%)**, true-dedupe 99/99 → 89/99 (89.9%). The recall cost falls in the safe direction: a missed dedupe emits a `NONE` a human reads.

## Acceptance test 2026-09-08 → 2026-10-06 — TWO legs

1. **Recall** (original): the feed surfaces ≥1 event the manual sweep missed, or an independent backfill finds 0 misses. *(Met on run 1: Kstovo/NORSI 8/26, Novorossiysk terminal 9/8-9.)*
2. **Precision** (added 2026-09-10, DAEDALUS ACTION 4): of the N `<strike_id>` rows in the committed `MATCHES_*.tsv` files over the four weeks, **M were confirmed at the named ledger facility**. Without this leg a 15–37% false-absorption rate would run the full window and be recorded as a PASS.
