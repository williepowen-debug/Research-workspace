| L-01 | 2026-07-11 | Keep the MONETARY and INDUSTRIAL channels separate — they send different messages and can move independently without contradiction (gold up on debasement + copper up on growth = reflation; gold up + copper down = risk-off/stagflation). Collapsing to "metals up/down" destroys the signal. This IS the agent's edge. | build session |
| L-02 | 2026-07-11 | MIDAS's edge is the *tell*, not the *price*: BOND owns the real-rate level, ZHAO owns China macro. MIDAS owns what gold's divergence FROM real rates says, and what copper says ABOUT China demand. Stay on the interpretation layer; hand the read to the level-owner. | build session |
| L-03 | 2026-07-11 | Gold's divergence from real yields is the signal, not gold's price. A high real yield (DFII10 2.31) with gold still bid = a fiscal-debasement + CB-buying premium. Track the GAP, not the level (mechanism-vs-thermometer). | build session |
| L-04 | 2026-07-11 | Born with the real-yield leg (FRED) but not spot (yfinance futures errored on test) — `metals_watch.py` is the priority first increment; validate ETF proxies (GLD/SLV/CPER/PPLT/PALL), and if built, wire the cadence durably into boot.py (PAT-041), not into SCRATCH. | build session |
| L-05 | 2026-07-12 | **CFTC COT data: WebSearch/WebFetch summarization hallucinates numbers — pull raw JSON directly.** First attempt at COT figures via WebSearch and WebFetch(publicreporting.cftc.gov) gave TWO different, mutually-inconsistent, and wrong number sets for the same gold contract. Direct `urllib` pull against the Socrata API (with schema-field verification) gave the correct, internally-consistent figures. Generalizes: any structured-data API (CFTC, FRED, EDGAR, etc.) should be pulled raw, not summarized by WebFetch's small model, when the exact numbers are load-bearing. | first real session |
| L-06 | 2026-07-12 | **A build-session's narrative framing is not itself evidence — verify it against the first live pull before propagating it.** The 7/11 build session characterized M1 as "gold structurally bid despite rising real yields" (a debasement premium) while explicitly flagging that no gold-spot pull had been done. This session's first pull showed the opposite (real-rate-consistent decline). The lesson isn't "the 7/11 session was wrong" (it flagged the gap honestly) — it's that an unverified framing sitting in STATUS/THESIS/KB for even one session can start reading as established fact if not re-checked at the first opportunity. Boot↔closeout symmetry should include re-testing inherited framings against fresh data, not just refreshing numbers under an unchanged narrative. | first real session |
| L-07 | 2026-07-12 | **A "% vs normal" threshold is meaningless until "normal" is defined — and the base you pick can flip the read.** Round-2 reported LME copper stocks "+110.9% YTD" (vs the Jan-2 level) — which was a multi-year LOW, so the YTD framing screamed "hot" while the absolute level was mid-range. Round-3 defined "normal" as the trailing-2yr rolling median (239,400t): the same 306,500t reads +28% = a modest Yellow, not an alarm. Any "+X% above normal" threshold must ship WITH its baseline definition (rolling median > arbitrary period-start), or the band call is an artifact of the anchor date. Generalizes to any of the fleet's "vs normal/baseline" bands. | round 3 |
| L-08 | 2026-07-12 | **Resolve dueling figures at the primary source and note WHY they differed — usually a stage/proceeding difference, not a contradiction.** Round-2 had the Russia-palladium tariff as "132.83% vs 828%" from two trade-press sources. The Federal Register (primary) showed 132.83% = the FINAL antidumping margin (doc 2026-08487, 5/1); 828% was an earlier PRELIMINARY figure. Not two claims about the same thing — a preliminary-vs-final timeline artifact. When primary-sourcing a disputed number, capture the proceeding STAGE + doc number, not just the winning figure. | round 3 |
| L-09 | 2026-07-12 | **"Primary-sourced" ≠ "machine-readable pull succeeded."** WGC's GDT Q1 Excel data file (the raw form) 403-gates automated curl (redirects to homepage), but WGC's own web pages ARE the primary source for CB gold demand and carry the published figures — fetchable. Upgraded the CB numbers PROV→CONF from the WGC page while documenting that the CSV/Excel wall persists. Don't conflate "the raw file resisted download" with "can't be primary-confirmed" — the authoritative publisher's rendered page is still primary. Log the wall so a future session doesn't re-hunt the same 403. | round 3 |
