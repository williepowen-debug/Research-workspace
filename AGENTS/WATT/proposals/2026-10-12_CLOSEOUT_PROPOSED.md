# PROPOSED — WATT closeout procedure

**Not active.** Prepared October 12, 2026 at Will's request for comparison/recommendation. Proposed successor to `CLAUDE.md`'s local CLOSEOUT PROTOCOL block; root Git rules and `PROME/COMPLETION_SPEC.md` remain canonical. No existing rule or permission is changed by saving this draft.

## When and how much

Run before ending a window, resetting context or a long pause. Declare **checkpoint / standard / heavy**. Checkpoint is for records-only/status endings; standard is the default for a completed owner research window; heavy adds validation for deliberate tool/protocol/thesis changes. Scope cannot excuse an existing root or desk obligation.

For a live event, save evidence and next action immediately. Closing a session does not grade the unfinished event or promise automatic monitoring. State the source cutoff, pending window and registered wake/owner.

## Standard sequence

1. **Reconcile current evidence and obligations.** Read STATUS/SCRATCH, open predictions, current inbox and relevant PROME receipts. Evaluate carried warnings against the named artifacts/commits. Separate research result, future observation, technical blocker and new operator decision. Do not re-show a discharged blocker.
2. **Write affected state once.** Update STATUS with observation date/cutoff separate from record-maintenance time. New facts to KB; moved channel state to VX; changed mechanism to FLOW and THESIS; changed trigger/posture to TRADE. Resolve due predictions at their original criteria and preserve the grade/history. No change: record a reason, preserve its real vintage. KILL_MEMO is excluded unless a deliberate authorized amendment is separately made.
3. **Reconcile dates and coverage.** Keep STATUS's wake set aligned with the desk's actually registered obligations and PROME docket identifiers. Preserve requested versus issued, forecast versus outcome, and partial-day versus completed-window distinctions. Confirm the next owner action/date; do not treat a registered wake as a running monitor.
4. **Current continuity.** Maintain one current pickup block in SCRATCH: state at writing, completed work, remaining work, next dated checks, source/approval walls, and mail/delivery status. Archive superseded session narrative verbatim when replacing it. Keep standing operational constraints readable; do not append a second competing current pickup.
5. **Mail and delivery.** For each consumed inbox item, ensure its integration/deferred disposition, board row where applicable and own archive move agree. Preserve independently delivered consumer packets. A file write/commit is not notification; queue acceptance is not consumption. Record each confirmed acknowledgment at the exact artifact version. PROME's receipt covers PROME, not every other consumer.
6. **Applicable checks and their perimeter.** Diff/TSV shape; root orphan, weekday, read-cap and ledger checks. Numeric change: root consumer scans cross-agent and self, with series/unit adjudication; auto-memory written: scoped index/length checks. Explain no-ops. A failed/skipped required check is UNKNOWN or incomplete, never “all checks passed.” Do not rewrite a historical capture solely to clear a lexical consumer hit.
7. **Final state and brief.** Stop substantive source edits. Commit the final STATUS/affected state with exact paths. Fold NEXUS_BRIEF as the last substantive write-back against that state; pin the actual STATUS source commit. Use compact/full form under NEXUS canon. A newer brief stamp does not freshen its underlying market data. Source edits after the fold require re-fold and affected verification.
8. **Persistence and publication.** Commit only owned paths and self-authored carve-out packets; run root Git mechanics as authorized. Preserve technical rejection history and honor its scope. Verify the actual authored commits/receipt against a fresh remote observation before claiming publication is pending or complete. A verified independent authorized push may discharge the publication obligation; no duplicate rejected push or workaround is needed. Do not pull over foreign dirty work or reimplement Git policy here.
9. **Bounded receipt and close.** Use one dated closeout receipt with scope, source vintage, changes/no-ops, check evidence/limits, authored commits, current publication/notification/consumption states, and next owner actions. Link historical rejections and supersede discharged warnings explicitly. Dated PROME delivery and verified queue notice follow COMPLETION_SPEC. Return the short user-facing result; no claim that every future event or recipient is complete.

## Source/write-back map

| Read or changed fact | Required write-back / explicit no-op |
|---|---|
| Channel score/read | STATUS; VX if its state changed; NEXUS; current SCRATCH |
| Mechanism/cost-allocation outcome | STATUS; KB; FLOW/THESIS; TRADE trigger if affected; consumer packet; NEXUS |
| Prediction resolver/deadline | Live/archive prediction row; KB; STATUS wake set; dated PROME packet if coordinator calendar affected |
| Inbox disposition | Integration/deferred artifact; board row where applicable; archive move; continuity if open |
| Recipient acknowledgment / origin ancestry | Same dated receipt/current pickup; derived “pending” wording corrected, history retained |
| Procedure or tooling amendment | Owning procedure/code and relevant validation; no implication of live market refresh |

Checkpoint applies this sequence only to changed facts and required current handoff/brief/persistence; it cannot waive mandatory rules. Heavy adds implementation-specific tests and document agreement. Proposed mechanical runner is a separate implementation step; this text does not authorize or install one.
