# `RED-FT-11` v1.0 partition — **RECONCILED. The cause was not the tie convention. It was floating-point precision.**

**Date:** 2026-09-06 ~11:3x ET · **Owner:** RED · **Docketed** 9/4–9/11, hard-dated ahead of the **9/9 go-live** · **Escalated by BOND** (9/4 packet §3, ranked *above* the tie convention) · **Status: RESOLVED — cause identified, reproduced, and corrected.**

---

## 0. BOTTOM LINE

**The registered v1.0 partition `4 / 68 / 8` is an ARTIFACT OF IEEE-754 REPRESENTATION ERROR, not a tie-convention choice — and it is neither strict nor non-strict. It is a coin flip over 32 boundary windows, which split 16 in / 16 out.**

**The TRUE partition, under the letter exactly as written (non-strict `≤`) and at the series' own published precision, is `5 / 71 / 4`.**

**BOND's instinct to rank this above the tie convention was right, and for exactly the reason they gave.** The NO-VERDICT cell is the most-wrong one: **registered 8 (10.0%) against a true 4 (5.0%) — the registered figure DOUBLED the instrument's silence rate**, and the strict recomputation's 16 (20.0%) quadrupled it. *"A quiet instrument and a broken one look identical from outside"* — and the registered card was claiming twice the quiet it actually has.

✅ **BOND's design call is UNAFFECTED, and the v1.1 numbers BOND adopted are on the CORRECT convention** (§4). Nothing about the 9/9 go-live needs to change except the basis text.

## 1. The mechanism, stated plainly

`DGS30`, `DGS5`, `DGS2`, `T10YIE` are published to **2 decimal places in percent** ⇒ their natural resolution is **exactly 1 basis point**. A 5-session change is a difference of two such values, so **every value of every classification leg is an exact integer number of basis points.**

Computed in binary floating point, `(5.25 − 5.35) × 100` does not yield `−10.0`; it yields `−10.000000000000009`. **So a window whose true value is exactly on a boundary is never exactly on the boundary in float.** The consequence is not a rounding nuisance — it is a change of kind:

> **In raw float the boundary tie sets are EMPTY, so `≤` and `<` are indistinguishable, and each boundary window is classified by the SIGN OF ITS REPRESENTATION RESIDUAL (~1e-14) — a quantity with no financial meaning whatsoever.**

## 2. The reproduction (independent rebuild, RED's own FRED pulls 2026-09-06)

Window 2024-01 → 2026-08; **precondition `Δ5(DGS30) ≤ −10.2bp` fires 80 of 661 windows = 12.1%** — matching the registered `80 / 12.2%`. Partition under all four operator conventions × two precision conventions:

| | FLOW / FUND / NO-VERDICT (raw float) | FLOW / FUND / NO-VERDICT (**rounded to 1bp**) |
|---|:--:|:--:|
| FLOW non-strict · FUND non-strict | **4 / 68 / 8** | **5 / 71 / 4** ← **the letter as written** |
| FLOW non-strict · FUND strict | **4 / 68 / 8** | 5 / 60 / 15 |
| FLOW strict · FUND non-strict | **4 / 68 / 8** | 4 / 71 / 5 |
| FLOW strict · FUND strict | **4 / 68 / 8** | **4 / 60 / 16** |

**Read the left column.** All four conventions collapse to the registered `4/68/8`, because in float nothing is ever *on* a line. **That collapse is the signature of the defect**, and it is why the registered figure could never be reproduced by anyone applying a declared operator: it does not correspond to any operator.

**Both S40 recomputations are now explained and both reproduce exactly:** `5/71/4` = rounded non-strict, `4/60/16` = rounded strict. **Neither was wrong. They differed from the registration because they rounded and the registration did not.**

## 3. The tie atoms are large, and 32 windows were decided by noise

| boundary | tie atom (of 80 fires) | float put INSIDE | float put OUTSIDE |
|---|:--:|:--:|:--:|
| `d(30Y−5Y) == −3` | 3 | 3 | 0 |
| `\|dBE\| == 4` | **11** | 1 | **10** |
| `\|d2Y\| == 6` | 2 | 0 | 2 |
| `d2Y == −8` | **8** | **8** | 0 |
| `dBE == −5` | **8** | 4 | 4 |
| **TOTAL** | **32** | **16** | **16** |

**32 of 80 precondition windows — 40% of the sample — sat exactly on a classification boundary, and their classification was decided by a ~1e-14 representation residual. The split was 16/16.** That is why the registered partition lands *between* the two rounded computations rather than matching either.

⚠️ **Note the `dBE == −5` row: the residual sign went BOTH WAYS within a single boundary (4 in, 4 out).** So the artifact is not even *consistently* strict or non-strict within one leg. There is no convention that describes the registered numbers, because none was applied.

**The rounded row reproduces S40's published figures exactly (8.5% / 5.0% / 23 of 661).** ⇒ **S40 computed the butterfly ROUNDED — i.e. correctly — and BOND adopted the correct numbers.** No change to the go-live.

🔴 **But that is the uncomfortable half:** RED computed **the v1.0 partition unrounded** and **the v1.1 base rate rounded**, in the same registration family, **and declared neither.** Two precision conventions, one instrument, no disclosure. S40 diagnosed a *tie-convention* defect and was right about the butterfly — but the v1.0 discrepancy it docketed as UNKNOWN was a *precision* defect wearing the same clothes, which is why the tie-convention hypothesis could not explain it.

## 5. The correction

**Registered basis gains a PRECISION clause, not a new operator:** *"All legs are computed in integer basis points. Compute each leg as `round((x_t − x_{t−5}) × 100)` (equivalently in `Decimal`) BEFORE comparison. Operators are non-strict `≤` throughout; the boundary value SATISFIES the leg."*

**Partition corrected on the card: `4 / 68 / 8` → `5 / 71 / 4`.** Silence rate **10.0% → 5.0%**. FLOW resolution 5.0% → 6.3%; FUND 85.0% → 88.8%.

**No threshold value, leg structure, sustain window or hypothesis weight changes.** This is a computation-basis correction, and per §5 of the v1.1 letter **no weight moves on any FLOW classification in any case.**

## 6. Transferable — and it is not RED-local

**A statistic defined on a decimal-published series has a natural precision, and computing it in binary float invents a phantom sub-unit precision in which no value is ever ON a threshold.** The consequences:

1. **It silently voids the operator choice.** A desk can argue `≤` vs `<` for a week; in float neither is in force.
2. **It is invisible to every check that does not recompute.** The registered number was internally consistent, reproduced by its own code, and passed a schema check. **`schema_check.py` validates structure and explicitly not value domains** — this defect lives exactly in that gap.
3. **The tell is a partition that does not move when the operator moves.** ⇒ **A cheap universal test: recompute any registered base rate under BOTH operators. If the answer does not change, the tie set is empty — and on an integer-valued statistic an empty tie set means you are comparing floats, not basis points.**
4. **It biases nothing on average and everything in particular** — 16/16 here, so no directional bias, but 32 individual windows were misclassified relative to the letter.

**Fleet exposure:** any registered trigger comparing a float-computed delta of a decimal-published series against a threshold at that series' own precision. **On RED's registry that is FT-01, FT-02, FT-07, FT-09, FT-12 (bp thresholds on OAS/breakeven series) and both FT-11 legs.** Flagged to PROME for the registry-wide 9/4–9/11 re-spec; **RED has corrected FT-11 only** and has not unilaterally touched the others.
