## The defect

`EARNINGS_PREP.md` is currently classified **two incompatible ways by two live surfaces**:

| Surface | Classification | Handling rule it implies |
|---|---|---|
| The file's own banner (2026-07-17 audit) | *"**STALE-VINTAGE** — Feb/Mar-2026 **fossil**. Do NOT cite as current."* | It is **rot**: worthless, retirement-eligible, refresh-or-archive |

**These are opposite dispositions.** One says the age is a defect; the other says the age is the point. A reader arriving via the banner concludes the file should be refreshed or swept; a reader arriving via `CLAUDE.md` concludes editing it is prohibited. **Both readers are following a live instruction correctly.**

## Proposed rider (append to the existing banner; do **not** replace it)

> 🧊 **CLASS: FROZEN CALIBRATION RECORD — the staleness above is the POINT, not a defect.** This file is a **pre-registration artifact**: its value is that it records what this desk expected **before** the prints it preceded, so it can be graded against outcomes. **Its content must NEVER be edited, refreshed or "corrected" — path fixes only** (`CLAUDE.md` § DOC OWNERSHIP; same class as `Q2_GRADING_FRAME_2026-07-21.md` and `PREPRINT_RECON_2026-07-17.md`). ⛔ **NOT retirement-eligible** — this is a live-doc-referenced calibration record, not an unmaintained fossil, and it must not be swept under the Data-Hygiene retirement rule. **"Do NOT cite as current" above still holds and means what it says: cite it as HISTORY, with its vintage.**

## Why this shape, and what I explicitly did not propose

1. **Append, don't replace.** The 7/17 banner is doing real work — *"do not cite as current"* is correct and must survive. The rider adds the missing half: *why* it is stale, and what that licenses.
2. **The rider goes on the FILE, not only in `CLAUDE.md`.** The boot card already carries the correct classification and it did not stop the near-miss, because **the reader who is about to archive a file is reading the file, not the boot card.** A warning has to be where the mistaken action happens.
3. ⛔ **I did NOT propose editing the file's body, or removing the STALE-VINTAGE banner** — either would be a content edit on a frozen calibration record, i.e. the exact thing the rider exists to forbid. A banner is metadata; the record beneath it stays untouched.
4. ⛔ **I did NOT propose generalising this to the other two frozen frames.** They carry no conflicting banner, so they have no defect to fix. *(`finding_a_ruling_governs_the_next_write_not_the_existing_state` — but the converse also holds: do not sweep a fix across files that do not have the problem.)*
