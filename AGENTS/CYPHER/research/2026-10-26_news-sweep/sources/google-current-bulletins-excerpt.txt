GCP-2026-073
Published:
2026-10-26
Description
Description
Severity
Notes
An incorrect authorization vulnerability was discovered in
        Compute Engine prior to August 31, 2026.
What should I do?
No action is required from you. This vulnerability was patched on
        August 31, 2026.
What vulnerabilities are being addressed?
An incorrect authorization vulnerability in Compute Engine
        versions prior to August 31, 2026 allows a user to exfiltrate
        disk data without the required IAM permissions.

GCP-2026-072
Published:
2026-10-24
Description
Description
Severity
Notes
Two vulnerabilities in PHP core, CVE-2026-109618 and CVE-2026-109619
        ("PHP2Shell"), allow an unauthenticated attacker to execute code
        remotely on a server running a vulnerable PHP version. They are fixed in
        PHP 8.2.35, 8.3.36, 8.4.27, and 8.5.12. No fixed release exists for PHP
        8.1 or earlier.
The impact on Apigee is limited to Drupal-based
        Apigee developer portals, which customers deploy and operate.
        Other Apigee products don't use PHP and aren't affected.
For instructions and more details, see the
Apigee security bulletin
.

GCP-2026-071
Published:
2026-10-23
Description
Description
Severity
Notes
On Saturday, October 17, 2026, Google received a report from a
        security researcher regarding the compromise of private keys associated
        with eight eMudhra subordinate Certification Authority (CA)
        certificates, including those cross-signed by AAA Certificate Services.
        Consequently, these CA certificates are no longer trusted and are being
        revoked.
Although Google Cloud infrastructure remains uncompromised, the
        following Google Cloud and Firebase products, base images, and client
        SDKs are impacted:
Google Cloud CLI
Cloud Shell
Container-Optimized OS
Compute Engine
Google Kubernetes Engine
Vertex AI
Colab Enterprise
App Engine
Cloud Run
Cloud Run functions
Cloud Functions for Firebase
Firebase AppHosting
Cloud SQL
AlloyDB
Cloud Firestore
Firebase App Distribution
Cloud Monitoring
Confidential Space
Google Distributed Cloud
What should I do?
Google Cloud is actively managing this issue across our
        infrastructure and platform services, and Google Cloud infrastructure
        has not been breached. Security telemetry shows no evidence of
        exploitation against Google Cloud workloads, and proactive mitigations
        are in place across Google-managed environments to block and distrust
        the affected certificate authority certificates.
For environments and dependencies that you manage directly, take the
        following actions:
Operating Systems & Self-Managed Environments:
If you manage operating systems or custom container images on
            Compute Engine, Google Kubernetes Engine (GKE), or Cloud Run, update
            the trust store via your operating system vendor to revoke trust in
            the compromised eMudhra (emSign) and AAA Certificate Services
            certificates:
Red Hat Enterprise Linux (RHEL): Follow
RHSB-2026-012
.
Debian: Update to the latest
ca-certificates
package (
Bug 1151446
).
Ubuntu: Follow
USN-8944-1
.
Windows: Install the latest Windows updates.
Container-Optimized OS (COS): Upgrade or restart nodes to pick
                up current COS milestone releases, or apply the
cos_ca_cert_mitigation
tool.
Google Cloud CLI:
Update to the latest gcloud CLI
            release to ensure bundled dependencies include updated certificate
            stores.
Service-Specific Guidance:
For managed Google Cloud
            and Firebase services, such as Google Kubernetes Engine, Serverless
            runtimes, Managed Databases, Cloud Firestore, Firebase App
            Distribution, and Confidential Space, Google Cloud is rolling out
            updates across managed fleets, and service-specific details, release
            notes, and customer communications will be published through the
            respective product documentation and official support channels as
            they become available. Please review individual service
            documentation for instructions tailored to your deployments.
            For GKE details and patch versions, see the
GKE security bulletin
.
If you have any questions or require assistance, please
        contact Google Cloud Support and reference issue
        #576444463.
What vulnerabilities are being addressed?
The private keys for eight eMudhra (emSign) subordinate Certification
        Authority (CA) certificates were generated using insufficient
        cryptographic randomness (weak entropy).
This weakness allows a remote attacker with network access to
        reconstruct private keys, forge trusted TLS certificates, and perform
        Man-in-the-Middle (MitM) interception against TLS clients, containers,
        or SDKs that have not yet removed trust in these subordinate CAs.

GCP-2026-070
Published:
2026-10-21
Description
Description
Severity
Notes
Two remote code execution vulnerabilities were found in the
open-source PHP language
.
        While Google Cloud itself is not vulnerable, users of this language
        running on Google Cloud may be vulnerable.
The following language versions are affected by this
        vulnerability:
All PHP versions between 5.4 and 8.5
The following framework versions include fixes for this
        vulnerability:
PHP 8.5.12, 8.4.27, 8.3.36 and 8.2.35
What should I do?
Customers should take immediate action to protect their workloads by
        redeploying their workloads with updated dependencies. Some workloads
        may be automatically patched and updated to the latest PHP if they are
        on Google App Engine Standard or one of Cloud Run,
        Cloud Run functions with automatic updates enabled. See the
blog post
for more information.
How can Google help?
Customers using Artifact Analysis receive notifications of
        these vulnerabilities on both new and existing artifacts to help them
        identify at-risk workloads.
