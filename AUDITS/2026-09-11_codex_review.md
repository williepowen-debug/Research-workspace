**What I would change about the workflow**

1. **Require one consumer-level check for a schema or state repair.** The question is whether the repaired file causes the expected downstream action. HENRY's pre-existing self-test passed because it supplied already-parsed tuples and never exercised the ledger reader. Today's new integration test would have caught the failure immediately.
2. **Separate an error correction, a new forecast, and proof of skill.** They answer different questions. A more accurate latest forecast can coexist with a poor original prediction. A technically justified void can still materially improve reported performance. Neither should be settled by the agent's narrative about its motives.
3. **Prefer fewer, stronger checks to another layer of reminders.** Today's useful checks include VIOLET's paired gap-detection/repair test and its immutable fixtures. Today's weak spots include text-token parsers and the ledger's abbreviated identity key. New reminders about these failures would not fix either implementation.
4. **Keep observation and interpretation distinct.** A mention is not consumption; a date label is not a settled price; an annualized statistic is not a matched-horizon comparison; a current confidence is not a registration confidence. Most of the consequential defects reviewed today cross one of these boundaries.
